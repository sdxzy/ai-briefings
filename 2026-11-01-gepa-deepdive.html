第 01 节

一句话读懂

先把结论放在前面

一句话

LLM 系统的一次 rollout 本身就是文本——别把每次尝试压成一个标量再估梯度；让反思模型读轨迹和「为什么」反馈，重写某一个模块的指令，并用逐实例 Pareto 存档避免塌成单一冠军。

  1. 信号。评价指标 µ 之外加反馈函数 µ_f：返回分数 + 可执行的旁路文本（缺哪些文档、哪条约束没过、编译错误摘录…）论文。
  2. 变异。每步只改一个模块的指令；minibatch 上 σ′>σ 才接受，再在 D_pareto 上整表评估论文。
  3. 选择。父代从「每个验证实例上的最优候选」并集采样，而不是永远盯着平均分第一名论文。
  4. 数字。Qwen3-8B 汇总：GEPA 54.85 vs GRPO 48.91 vs MIPROv2 47.84；rollout 远少于 GRPO 的 24,000论文。
  5. 前提。你要有指标，最好有高质量 µ_f；没有文本反馈时优势会缩水评论。

对 skill / 提示词 RSI：抄 µ_f + 逐实例 Pareto；合并默认先关；元提示词要改掉「把样例事实写进指令」以免跨仓库泄漏建议。

阅读顺序：第 2 节概念；第 3–4 节主循环与 Pareto 配图；第 5 节实验对照；第 6 节批评；第 7–8 节建议、术语与 Dong 理解。

第 02 节

关键概念

复合系统里，GEPA 动哪一块

概念定义论文实现备注评论
复合 AI 系统 Φ语言模块 + 固定控制流 C + 输入输出 schema实验中不改控制流、工具或代码
可学习参数提示词 Π 与权重 Θ；GEPA 只动 Π一个候选 = 各模块槽位文本的完整赋值
Rollout在一个实例上调用 Φ 并经 µ 评估；计入预算 B验证评估也算 B
轨迹执行轨迹（推理/工具/输出）+ 评估轨迹（如编译错误）多数团队只记前者
µ_f返回分数 + feedback_text，可模块特定仓库后称 Actionable Side Information（ASI）
反思式变异反思 LM 读指令、minibatch 输入输出与反馈，重写一个模块指令跨模块信用分配靠 LLM 读整段轨迹
逐实例 Pareto每个 D_pareto 实例保留其最优候选，并集去支配后按领先次数采样不是多目标 Pareto；是 MAP-Elites 式「照明」
系统感知合并两候选有共同祖先、改了不相交模块集合时才交叉单提示词系统上合并≈空操作
第 03 节

主循环

架构图

数据划分：D_train 拆成 D_feedback（学习信号）与 D_pareto（选择）；实验里常用 train/validation，minibatch b=3论文。

每步摘要：

  1. SelectCandidate：按 Alg.2 从前沿采样父代。
  2. SelectModule：轮询模块 j。
  3. 在大小 b 的 minibatch 上跑父代，收集轨迹、分数、µ_f 文本。
  4. 反思 LM 用 App.C 元提示词写出新指令 πⱼ′。
  5. 仅当同 batch 上子代均值 σ′ > 父代 σ 才接受。
  6. 接受后加入种群，在全部 D_pareto 上评估填充分数矩阵一行。
  7. 可选 Merge：整次运行最多约 5 次，条件严格论文App.D。
  8. 最终返回 D_pareto 平均分最高者——前沿用于搜索，不直接当部署配置论文。

元提示词会要求把「小众的、领域特定的事实」写进指令论文App.C。评论在事实会重复的基准上这是优点；对必须跨仓库泛化的 skill，这是泄漏风险，实现时应改成「只写与仓库无关的经验」。

第 05 节

实验：vs GRPO / MIPROv2

设置要点〔论文〕

任务含 HotpotQA、IFBench、HoVer、PUPA、AIME-2025、LiveBench-Math 等；反馈从「每跳缺失金标文档」「未满足约束」到「仅分数」不等。基线含 MIPROv2、Trace/OptoPrime、TextGrad、GRPO（LoRA，24,000 rollout）。GEPA 预算对齐到各基准上 MIPROv2 实测 rollout 的约 10% 误差内论文。

作者表述核对论文+ 精读：平均比 GRPO 高约 6 个百分点（54.85−48.91）；单任务可高约 20%（如 HotpotQA）；「rollout 少 35×」来自提升较小的 IFBench 分母，读时要当心；追平 GRPO 最佳验证分的样本效率最高约 78×（训练侧往往只需几十到几百次）。六次 GPT-4.1-mini 运行成本量级：GEPA 约 $86 vs MIPROv2 约 $76论文。反思调用每次运行仅 17–92 次——提案少，每个都要值钱论文。

Merge：对 GPT 汇总略正；对 Qwen 有害（如 IFBench 大跌）论文。建议默认先关 Merge。

跨模型：用 Qwen 优化的提示词迁到 GPT-4.1-mini，汇总仍可超过直接在 GPT 上跑的若干优化器论文Obs.6——提示词编码的是任务知识，不只是某模型怪癖。

第 06 节

批评与边界〔评论〕

  1. 你其实需要 µ_f。提升集中在反馈信息丰富处；「3 个样例就够」的宣传忽略了论文常用 45–150 训练 + 45–300 验证。
  2. Minibatch 关口噪声大。b=3 且硬阈值；安全网是随后的大验证集。用例只有 4–12 个时要加 ε 余量与确定性不退化关口。
  3. 过拟合与泄漏。元提示词鼓励写入实例事实；跨仓库必须改提示词并做标识符 lint。
  4. Goodhart。奖励反转实验显示 GEPA 能找到奇怪提示词钻评估器空子论文§5.2。
  5. 合并不稳定；全文缺少多种子方差；数学/IFBench 上提升小，Qwen AIME 上 GRPO 可胜过 GEPA。
  6. 与 Harness² 互补：GEPA = 离线、要指标、提示词级种群搜索；Harness² = 在线、无标签、整包 harness 文件 + 经验库。
第 07 节

给 Dong 的建议〔建议〕

现在就照搬

  • 带各层理由的 µ_f（结构缺失、幻觉路径、覆盖遗漏、读者适配评语）。
  • 逐实例（逐用例）Pareto 存档 + 按领先次数采样父代。
  • Minibatch 关口通过后再跑完整留出集；谱系树 + diff 当审计日志。
  • 修改元提示词：禁止写入仓库特定文件名/符号；可加 diff 大小纪律（借鉴 SkillOpt/ACE）。

暂时不要

  • 默认开启 Merge；变异脚本/CLI（等沙箱与编码提案者）；在同一循环里优化评判提示词本身；把推理时「过拟合本题集」模式当成在优化可迁移 skill。

与无 GT 的 Propose–Probe–Compose 怎么叠

内层（新仓库、无检查清单）：Harness² 式对照探测。外层（有标注用例）：把经验条目提升为 GEPA 槽位候选，只有过 L1/L2 类关口才进共享 skill。讨论

第 09 节

Dong 的理解〔讨论〕

  1. 别先估梯度，先读文本。轨迹里已经有信用分配线索；µ_f 把「为什么」交给反思模型。
  2. 每步只改一个槽位 + minibatch 关口 + 整表验证，比一次改整份 skill 更可审计。
  3. Pareto 是搜索用的照明，不是部署用的多套配置；上线仍可取平均分最高者，但要保留前沿当下一轮种子。
  4. Merge 不是默认技能；单模块或谱系不够时跳过。
  5. 对 module-explainer：把 skill 拆成 strategy / reader_rules / template 等具名槽位；脚本与评测套件固定；编辑器≠评判器家族。
  6. 样本效率好看，但不等于「没数据也能搜」——没有可靠 µ_f 和留出集，GEPA 会变成带文采的过拟合。
