NVIDIA：You don’t need long context——压缩与短峰上下文可逼近全历史

NVIDIA Research · arXiv 2026-11-03（HTML 全文） · 原文 约 25–40 分钟（论文）

问题。 论文长上下文被当成 Agent / 长程任务的默认解，但服务侧 decode 成本随窗口陡升：作者按 H100 on-demand 计价估算，同输出 token 下 256K vs 16K 约为 GLM 5.2 ~3.6×、Kimi K2.6 ~5.6×、Qwen 3 Coder Next ~7×。长历史也未必等于更好用——真正需要的往往是可解释的语义状态，而不是整段原对话。

**怎么做的 / 证据。

论文两条主路线：End-of-Conversation Compaction（EoCC）在会话边界压成摘要状态；Single-Action Compaction（SAC）更极端——每轮只保留一次 Bash 动作 + 语义状态交接。在 SWE-bench Verified、Multilingual、Terminal-Bench 2.1、FRAMES、τ²-bench、BFCLv3 等长程榜上，EoCC 相对全历史大致落在 Opus 4.5−3.7…+5.6ppt、GPT-5.6 Sol−3.3…+4.4ppt，作者估算优化后成本常可降2–8×。SAC 下 Opus 4.5 在 Terminal-Bench 约持平或+4.6ppt，GPT-5.6 Sol−2.0 / −3.3ppt，中位峰值上下文约7–9K。长输入任务若改成选择性读文件系统，常可匹配甚至超过「整段塞进窗口」基线。作者进一步提出Semantic State Space Models（SSSMs）**：后训练让模型在回合间更新可解释的自然语言状态。

评论与昨日 Message Threads「少传、同算」互补：Threads 砍传输与 TTFT，本文砍语义上不必保留的历史。对个人 Agent / coding Agent，设计重心从「堆窗口」转向「状态交接协议 + 可度量的压缩损失」。成本倍数是作者附录模型，宜论文自述读，非厂商牌价。

是否值得读原文 · 做 Agent harness / 记忆的必读；先 Abstract + EoCC/SAC 实验表，约 20 分钟。

You don’t need long context (arxiv.org) @omarsar0 (x.com)

第 02 节

RSI（自我迭代 / 人参与的迭代）

Meta²：离线学可复用 Meta-Skill，在线只做 run 内 harness 进化

arXiv 2026-11-03 · 原文 约 30–45 分钟（论文）

问题。 论文长程 Agent 常靠手工或跨任务乱改 harness；跨任务污染与「每次从零进化」都很贵。能否离线学会「怎么改 harness」，再在单次 run 内局部进化、跑完即弃？

怎么做的 / 证据。 论文离线用对比 rollouts（无 evolver / Meta-Skill evolver / 有 verifier 特权的 evolver）学出文本 Meta-Skill；在线冻结该技能，仅在检查点让 evolver 选择 KEEP 或 EVOLVE，改动不跨任务残留。以 GPT-5.6-Terra 为骨干：Terminal-Bench 2.1 81.00%（相对 NexAU seed 66.33，+14.67）；DeepSWE 1.1 44.44%（+9.77）。DeepSeek-V4-Flash 骨干 Terminal-Bench 77.67%。作者报告点估计优于 Meta-Harness / Continual Harness / ACE 等；对比式 Meta-Skill 优于自蒸馏。

评论这是偏「可上线的 RSI」路径：不改权重，改的是如何局部改编排。和「真·权重自改」叙事不同，但对 coding Agent 团队更可落地——预计算适应策略，再在检查点小步进化。

是否值得读原文 · 做 harness / RSI 的值得精读 Method + 主表，约 25 分钟。

Meta²: Precomputing Reusable Knowledge for Online Harness Evolution in Long-Horizon Agents (arxiv.org)

Continual AutoResearch：跨任务保留经验加快收敛，不保证最终更好

arXiv 2026-11-03 · 原文 约 25–35 分钟

发生了什么。 论文在 9 条任务族流上对比有状态 vs 重置的 CLI Agent（Opus 5、Sonnet 4.6、GPT-5.6-Sol、GPT-5.4、Kimi K3）。持久状态让五者时间收敛均改善（均值约 +3.0…+21.3 归一化奖励点），主要来自更早/更好的首解；但最终结果仅 Sonnet 明显更好（约 +7.6），其余接近零或略负。记忆卡消融：相关 insight 改变初始化与搜索，却未必抬最终分。

评论校准「always-on 记忆」预期：留住经验 ≠ 用好经验（选择后悔、过度锚定）。可与 Meta²「检查点进化、跑完即弃」对照读——持久与局部进化解决的是不同失败模式。

是否值得读原文 · 做多项目研究 Agent 则值得扫结果表，约 15 分钟。

第 06 节

高效使用 AI / Agent

从今日论文抽出的三条可执行提示

1. 压缩优先于堆窗口。 论文见第 1 节：EoCC 在会话边界做语义压缩；极端场景试 SAC（单动作 + 状态交接）。度量「压缩后 vs 全历史」的 ppt 差，而不是只看窗口长度。对自建 coding Agent：把「可解释状态卡」当成一等公民，原对话可归档。

2. 检查点进化，跑完即弃。 论文见第 2 节 Meta²：离线预计算「怎么改 harness」，在线只在检查点 KEEP/EVOLVE，避免跨任务污染。适合多仓库并行的 Agent 团队——共享的是 Meta-Skill，不是脏 harness。

3. 持久记忆要管「选用」，不是只管「存下」。 论文Continual AutoResearch：跨任务状态常加快首解，却不保证最终分；Salesforce Agentforce 记忆更新（官方ConvoMem 风格评测：1.8× 陈述事实召回、2.2× 随时间变化事实召回）强调把更新当更正而非并列追加——个人 Agent 可直接借「更正语义」。

附加信号。 第三方@ArtificialAnlys 推 Time per Task 头条指标（约千级 serverless 端点）：同一模型 medium vs max effort 分数与耗时差很大（例：Astra 约 52@medium/~5.8 min vs 57@max/~18 min）——选 effort 默认值本身就是产品决策。原帖

Allen Institute for AI · HF/Ai2 博客 2026-11-03 · 原文 约 10–15 分钟
