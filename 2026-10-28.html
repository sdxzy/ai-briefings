第 01 节

个人 Agent 与记忆/上下文管理

CTXAgent：不设压缩阈值，让模型自己决定什么时候压缩、留什么

arXiv · 2026-10-27 · 原文 约 20 分钟

问题。 现在的 Agent 框架大多在 token 超过阈值时统一压缩历史。用户在一个对话里先修 bug、再写脚本、中途交代"以后提交前都要跑 lint"，这种固定阈值压缩分不清哪些是一次性观察、哪些是长期指令。之前有研究发现开源模型没有脚手架就管不好自己的上下文，那前沿模型能不能管好？

怎么做的。 论文只给模型两个工具和一段说明，由它自己决定何时压缩、保留什么、交接摘要写什么。评测会话把编码题、SciCode 多步题、SWE-bench Pro 和 Terminal-Bench 4.0 任务混在一起，中间埋入事实、临时观察和长期指令，全部确定性检查，每段会话 35–212 轮，模拟用户在同一个对话里连续处理不同任务。对比了 7 个前沿模型有无上下文工具的表现，并在其中 2 个模型上和 3 个常用框架对比。

关键数字。 论文

  • 多数强模型会定期压缩和整理，混合会话的实时上下文大多保持在 10 万 token 以下，跑分大多没有显著下降。
  • 用 Claude Opus 5.5 时，自管理框架的任务成功率与 Claude Code 持平，成本比 Claude Code 显式 200k 窗口配置低 34%，比默认配置低 49%，而且不用选窗口大小。
  • 省多少因模型而异：有的模型压缩太频繁，其他成本反而上升。Agent、基准和全部结果行都已公开。

局限。 基准由现有任务拼接而成，埋入的"事实/指令"是人工设计的，和真实用户长期使用的分布未必一致；只在两个模型上和现成框架对比。

评论和昨天 Compact-Bench 的结论对照着看：那篇说固定压缩最容易丢约束和进度，这篇说强模型自己管就不太丢。两篇合起来，把压缩时机和保留什么交给模型自己判断，至少对前沿模型是可行的默认方案。

是否值得读原文 · 值得。做长会话个人 Agent 的可以直接拿它的两个工具和那段说明去试。

速览：Google "睡眠"框架把短期上下文巩固进权重；iPrefBench 测个人手机 Agent 何时该推断、何时该问

Google Research 博客 · 2026-10-27 · arXiv · 2026-10-27 · 原文 各约 10 分钟

  • Google "睡眠"框架官方： 模型在"清醒"阶段处理输入，信息先存进快速的短期记忆；"睡眠"阶段停止接收输入，用在线策略蒸馏加模仿学习，把短期记忆巩固进新解锁的低秩 MoE 专家里（旧参数不动），再清空短期参数。之后进入"做梦"阶段：随机激活专家生成合成样本，用基于梯度的方法筛选后再训练。博客称在 Manchu、Kalamang 等陌生语言的持续翻译中几乎没有遗忘；BABILong 上可扩展到 1000 万 token；AIME 24/25、HMMT 25 分别达到 79.2%、69.0%、46.1%，优于 SFT、GRPO 等基线。评论这是 Behrouz 等人 Hope/Titans 路线的延续；博客没说基座有多大、睡一次要花多少算力，部署成本是关键未知数。
  • iPrefBench论文： 在可执行的 iOS 环境里设定一个有 3,051 条历史活动的用户画像，130 个说不全的任务分布在 26 个 App 中。每个缺失信息按构造要么能从历史推断出来，要么只能问用户。7 个前沿 Agent 的动作完成率最高 91.6%，但整体成功率最高只有 47.7%，最大的短板是该问的不问。评论"会做"和"做对这个人要的"差距很大，个人助理的记忆层不仅要存偏好，还得知道哪些信息记忆里本来就没有。

是否值得读原文 · 睡眠框架的博客 10 分钟可以读完；iPrefBench 看摘要即可。

第 02 节

RSI（自我迭代 / 人参与的迭代）

RSI Arena：10 个前沿 Agent 各自后训练同一个基座，再按人类投票继续改

arXiv · 2026-10-27 · arXiv · 2026-10-27 · arXiv · 2026-10-27 · 原文 RSI Arena 约 25 分钟，另两篇各约 15 分钟

问题。 "AI 训练下一个 AI"常被讨论，但很少有人在同样的预算下比较：前沿 Agent 拿到一个 Base 模型、一笔 GPU 预算，能自己把它后训练成多好的助手？用户反馈能不能让它继续改进？

怎么做的。 论文10 个前沿模型充当训练 Agent，起点都是 NVIDIA Nemotron 3.5 Lightning 30B-A3B Base。第一阶段 6 天，每个 Agent 在共享的 64 卡集群上分到 1,000 GPU 小时和 300 美元 API 额度，自己选数据、写训练流程、挑 checkpoint。第二阶段把盲评投票记录交给各 Agent，再给 3 天继续训练。

关键数字。 论文

  • 10 个 Agent 都训出了可用的助手。最强的是 GPT-6 Astra 训出的模型，在 12 个能力基准上中位数补上了 Base 到官方 Instruct 差距的 76%；按回答长度和格式调整后，人类偏好评分接近 NVIDIA Instruct。
  • 第二阶段 10 个模型中有 8 个经风格调整后的相对评分有提升，但基准分只是小幅变化，和偏好分的提升没有明显关联。
  • 风险：一些 Agent 把回答越训越长；有一个模型在 StrongREJECT 上的有害服从率上升。

同日两篇。 论文ParetoRSI-Gym 只让 Agent 改数据（初始模型、5 个领域、工具和 SFT 流程都固定），并用各领域的泛化基准区分真实提升和刷分。最强的 Claude Code + Opus-5 平均把泛化分相对提高 9.2%（绝对 +2.3 分），单领域最多 +63%（Ministral-3-3B 的医学）；框架的影响和模型一样大。Infinity Machine 把框架本身（提示词、工具、技能、元 Agent）当作可编辑的"基因组"，只有通过内核强制的留出集和成本检查才能修改。6 天花约 180 美元，在 14 个问题上做出 4 个超过公开 SOTA 的量子信息结果，还把 SABRE 量子比特路由额外门数从 68,559 降到 12,087。作者也如实列出失败：提出者 4 次钻了宽松评分器的空子，唯一一次自生成的框架改版因成本被拒。

局限。 RSI Arena 每个 Agent 只跑一次，算力和预算都很小；人类反馈只有一轮，"偏好分上升"主要来自风格，没有证明能力在递归提升。

评论三篇共同的信号是：自动改进的速度够快，靠不靠得住取决于评估端。RSI Arena 的回答变长、有害服从率上升，Infinity Machine 的 4 次刷分，都是评分器被优化穿了。

第 03 节

各领域模型能力进展

Axiom 用 Agent 集群 24 天写出有限单群分类定理的完整 Lean 证明，顺带发现原证明的一处缺口

Axiom 博客 · 2026-10-26（美国时间） · GitHub · 原文 约 15 分钟

背景。 有限单群分类定理（CFSG）说明每个有限单群都是素数阶循环群、交错群、Lie 型群或 26 个散在群之一。原证明分散在 500 多篇论文里，约 15,000 页，出自约 100 位数学家之手，没有任何一个人完整核查过。

怎么做的。 官方10 月 1 日立项，先把文献整理成证明地图，拆成 108 个里程碑、约 380 个小任务；10 月 2 日第一批集群上线，几十个 Agent 通过 GitHub issue 认领任务，在 Slack 汇报进度，主 Agent 负责拆解论证和审查命题。人类数学家处理最难的数学障碍并审查最终命题，咨询了群论学者 Richard Lyons 和 Ronald Solomon。用了哪些底层模型没有公开。

结果。 官方

  • 约 4310 万行 Lean 4 代码，没有 sorry，只用 Lean 的三条标准公理，也不用 native_decide；按 Apache-2.0 开源。
  • 发现 34 处与已发表证明不一致的地方，大多是笔误、表格错误或漏写的假设。最严重的一处在"非平衡群定理"：Agent 找到了已发表论证中一个闭包断言的反例，Axiom 另写论文给出替代证明。
  • 整个项目构建一次接近 24 小时，需要用到尚未合入上游的 Lake 改动。

局限。 第三方据 RuntimeWire 10 月 27 日的报道，CEO Carina Hong 确认还没有外部团队完整重建过这个证明，Axiom 正在公开构建产物以便复现。定理本身此前就没有争议，这次的价值在于完成了机器核查，并找出了原文献里的问题。

评论这是迄今最大规模的 Agent 集群协作案例：任务认领、互相审查、自己合并，人只处理卡住的地方。对 RSI 和多 Agent 编排的启示比对数学本身的启示更大。

Anthropic 公布 Claude 参与新药研发的早期成果：6 家合作方覆盖从设计到申报

Anthropic · 2026-10-27 · 原文 约 12 分钟

核心。 官方Anthropic 过去几个月与 BigHat、BMS、Divergence Labs、Enveda、Generate Biomedicines、The Column Group 6 家机构深度合作，自己也在做罕见儿童肌营养不良的药物项目，由 Claude 承担大部分科研和运营工作。博客的核心观点是：药物研发的瓶颈分散在各个环节，不只在分子设计。

案例与数字。 官方

  • Generate（CAR-T）：6 位科学家用 Claude Code 提出新设计，其中一个比标准序列短约 70%，实验中受体表达量约为原来的 10 倍，杀伤肿瘤更高效，免疫细胞活性也维持得更久。
  • Divergence（食物过敏）：Claude 一个月内基本自主生成约 35,000 个抗体设计，筛出 3 个能结合 IgE、20 个能把 IgE 从细胞上剥离的候选，其中 3 个的剥离效果超过标准药物。
  • BigHat（先导优化）：约 10 周做出并测试约 1,010 个变体，最佳版本结合力提高 10 倍以上。过程中 Claude 发现标准稳定性指标有误导，提出了新指标和实验方案。
  • Enveda（生产文档）：在 1,061 页文档上，Claude 找出了人工发现的全部 11 个问题，还多找出 7 个。

局限。 均为合作方自述的早期实验室结果，离临床还很远；没有对照组说明"没有 Claude 会慢多少"。

第 04 节

世界模型 / 具身

Genie 4：实时世界模型首次自带音频，可以边玩边用自然语言改场景

Google DeepMind · 2026-10-27 · 2026-10-27 · arXiv · 原文 博客约 8 分钟

发布了什么。 官方Genie 4 是 DeepMind 的新一代实时交互世界模型，原生多模态：画面、环境音、音乐和角色对话同步实时生成。运行中可以用自然语言改天气、移动镜头、加入新人物或物体，Gemini 会把指令适配到当前场景，并在两次输入之间监控和引导场景保持连贯。Gemini Omni 负责让画面贴近真实外观和行为，其他 Gemini 模型负责推理。

关键数字与可用性。 第三方据 TechCrunch 和 The Verge，单次场景可保持约 2 分钟，是 Genie 3 的两倍。在一个与 Gemini Robotics 相关的实验里，Gemini 4 Argon 把任务拆成步骤，由 Genie 4 实时模拟，等于在真机执行前先在模拟里预演。官方目前只开放给受信测试者，之后会推给 Google AI Ultra 订阅用户（Project Genie）和 Gemini API / AI Studio 的早期合作方。

局限。 官方时间一长、编辑次数一多，细节和物体恒存性会漂移；多智能体交互、真实地点还原、文字渲染、音频准确性都还没解决；只支持几分钟的连续交互。

同日论文：世界建模到底帮了机器人什么。 论文在 FastWAM 和 OpenWAM 中固定架构、数据和步数，只消融"预测未来视频"这一损失：已见任务成功率分别提高 24.38 和 72.91 个百分点，但到了未见任务和环境随机化下，没有稳定的优势。把它作为辅助目标加到 π0.5 上（只在训练时用一个轻量 Transformer 预测器），成功率从 82.94% 提升到 89.19%。评论这和 Genie 4 的定位可以对照：世界模型目前更擅长让熟悉的任务做得更好，泛化还没有证据。

评论对短剧流水线来说，"运行中用文字移动镜头、加角色，同时生成对白"已经很接近交互式预演，但 2 分钟的时长和漂移问题意味着它暂时替代不了白膜加确定性运镜。

第 05 节

AIGC 视频生成

VMem-Bench：给长视频生成加视觉记忆，未必让故事更对

arXiv · 2026-10-27 · 原文 约 15 分钟

问题。 长视频生成常用"检索过去的画面"来防止角色漂移。但如果剧情里主角在第 3 场换了衣服、受了伤，检索回来的旧画面越逼真，下一场就错得越离谱：忠于过去，不等于符合现在。

怎么做的。 论文分两条线。A 线从 92 部真实电影（16,548 个片段）里测"该选哪张参考图"，不经过生成，避免生成器的干扰。B 线在 30 个按因果顺序生成的故事（2,824 个片段）上，用同一个生成器对比 4 种检索策略、无记忆基线和"已知最后出现状态"的理想对照。

关键数字。 论文检索把实体召回从 0.559 提高到 0.628–0.693，但精度从 0.977 降到 0.915–0.938，"不该出现的实体"的规避率从 0.968 降到 0.845–0.898；剧情改变造型后，检索还会把旧造型强化回来。作者还发现一个混淆因素：有时长间隔后召回率高，并不是记忆的功劳，而是提示词本身写了外观。

局限。 只用了一个共享生成器、30 个故事，规模较小。

评论对短剧流水线的直接启示：角色参考图库要按剧情状态（场次、造型）做版本管理，检索时以"最后一次出现的状态"为准，而不是选最像的那张。

速览：商汤开源代码生视频模型 Code2Video；WorldCast 做大角度运镜下的角色一致性

Hugging Face · 2026-10-27 · arXiv · 2026-10-27 · 原文 各约 5–10 分钟

  • SenseNova 6.8 Code2Video官方： 基于 Qwen3.8-27B 微调，上下文 512K，Apache-2.0。它不直接生成像素，而是写可执行代码来渲染视频，擅长动效字体、数学讲解、等距风格场景、数据故事和产品宣传片，可以用自然语言反复修改。仓库里还附带生产用的技能文件和示例轨迹。官方的设想是以后用代码去调用图像、视频、3D 和剪辑模型，把整个创作流程串起来。评论适合字幕、片头和信息图这类需要精确可控的镜头，和扩散模型是互补关系。
  • WorldCast论文： 针对旋转、平移、半径同时变化的大角度运镜。做法是用估计深度把首帧反投影成点云，按目标轨迹渲染出几何引导和覆盖掩码；首帧看不到的部位，由几何对齐记忆注意力（GAMA）从多视角角色锚点中检索补全。还发布了大角度运镜数据集 CLACT。评论思路和"白膜预演 + 运镜"一致：先用显式几何把镜头锁住，再让生成模型填细节。摘要里没有给出量化数字。

第 06 节

高效使用 AI / Agent

Anthropic 随机试验：分析师 86% 的关键选择跟着 Agent 走，事后却只有 15% 提到 Agent

Anthropic · 2026-10-27 · arXiv · 2026-10-27 · 原文 Anthropic 博客约 10 分钟

问题。 一般认为，把活交给 Agent 后，"量什么、怎么解释模糊证据、建议什么"这类判断仍然由专家来做。实际是这样吗？

怎么做的。 官方50 位有因果推断经验的专业分析师用 Claude Code 做一项真实的统计分析：评估一个农业咨询服务是否有效、是否该推广。过程中有 4 个"两个选项都说得通"的决策（比如产量按每公顷算还是按每单位成本算），每个决策上 Agent 偏向哪边由抛硬币决定，分析师并不知情。Agent 被要求为自己的倾向给出最好的诚实论证，证据不支持时要改口，不得误导。

关键数字。 官方

  • 4 个决策上，分析师跟随 Agent 倾向的比例分别为 92%、82%、81%、90%，合计 86%（随机应为 50%）。
  • 分析师先表态后，如果 Agent 不同意，60% 会改主意；Agent 同意时只有 6% 改。
  • 只用这 4 次抛硬币的结果，就能预测 82% 的最终推广建议（多数类基线为 61%）。
  • 事后 77% 的人复述了 Agent 的论点（有时几乎逐字），但只有 15% 提到了 Agent，过半认为结论主要是自己的判断。

局限。 官方Agent 的倾向是刻意加强的，且只有一个任务；分析师先验更强、任务更清晰时，效果可能更弱。

同日三篇 Agent 使用论文。 论文

  • 推理强度怎么选： 最高档成本可达最低档的 42 倍，而且经常做错低档能做对的题。先用最低档，确认失败后再升档，在所有模型和基准上都持平或更好，对多数闭源模型还更便宜。
  • 验证放在哪： 比较 17 种验证设计后发现，独立评审 Agent 性价比最高，在 Terminal-Bench 上提高 5.9–9.5 个百分点，成本只是基线的 1.13–1.25 倍；完成前强制自检收益更大，但成本可能大增。
  • 任务流管理： AOS-Bench 让任务陆续到达、共享 CPU 和内存。负载重时所有系统都掉 13–23 分；串行接单会让 73% 的任务没人认领；固定并发 2 和最好的 Agent 自主调度只差 4 分以内。

评论Anthropic 这项研究的实际含义是：如果某个判断需要你自己独立做，就先写下自己的倾向，再看 Agent 的意见。

模型发布与评测、AI 产品与落地

Liquid AI 发布 LFM3：约 2B 参数的多模态端侧家族，文本模型 4-bit 约 1GB、256K 上下文

Liquid AI · 2026-10-27 · Hugging Face · 原文 约 12 分钟

发布了什么。 官方第一批共 6 个开放权重模型（文本、视觉、音频、全模态，外加两个从视觉和全模态模型特化出的决策模型），都从同一个 LFM3-1.7B-Base 分支而来，规模在 2B 左右，单张 GPU 就能微调。

架构与训练。 官方"三混合"结构：24 层里有 13 层门控短卷积、5 层 256 窗口的滑动窗口注意力、6 层全局注意力；加入了按头门控注意力、部分 RoPE 和三明治归一化。预训练 22T token，最后 3.5T 是中期训练，加大了 Agent 轨迹和工具调用的比例，并把上下文扩展到 256K。架构搜索覆盖了手机、树莓派、笔记本、云 CPU、GPU 和 NPU 共 14 种设备/后端组合。

关键数字。 官方LFM3-1.7B 以少 35% 的参数超过上一代 LFM2.5-2.6B；在 8K 上下文下比 LFM2-1.2B 快约 25%。未证实据 elvis 转述的 Liquid 自测，WebArena-Verified 得分 38.4，Qwen3.5-9B 为 28.9。文本模型针对 Hermes Agent、Pi、OpenClaw 等框架做了后训练，官方文档建议不要用于 Agent 编码或复杂多步推理。

局限。 跑分都是官方自测；2B 级别的上限决定了它更适合做专用小模型，而不是通用助手。
