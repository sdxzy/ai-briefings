第 01 节

一句话读懂

先把结论放在前面

一句话

Super-agent 不是新模型，而是挂在 DeepSeek Harness 之上的调度/运行时：用 Router–Worker 把「对用户连续」和「对任务并发」拆开，再叠事件驱动、异步 ReAct、存算分离和 Watchdog。

  1. 定位。Harness（Cordis 插件内核）= 可替换单 Agent 运行时；Super-agent = 多 Session 之上的组织层官方。
  2. 四特征。连续、高效（可并行）、主动（听事件）、持久（可恢复）——经典单路 ReAct 撑不住官方。
  3. 核心。Router 只交互与分派；Worker 隔离执行、不直接对用户说话官方。
  4. 实验。合成负载下完成时间 p50/p95 约 12.4/15.7 分钟，优于单 Session+Subagent；用更多 token 换更稳的调度官方。
  5. 硬问题。安全与隐私：云端 Loop 被注入后的端侧全控、凭据进上下文官方。

和 Harness²/GEPA 互补：Super-agent 管怎么组织活着的多 Agent 系统；后两者管怎么把单个 harness/提示词变好评论。

阅读顺序：第 2 节与 Harness 关系；第 3 节问题与四特征；第 4–5 节架构与事件路径配图；第 6 节上下文/异步/部署/Watchdog；第 7 节实验；第 8 节原型与开放问题；第 9–10 节术语与 Dong 理解。

  • Super-agent = 在多个 Session 之上：谁对外说话、谁干活、事件怎么进、状态怎么活。

第 03 节

要解决的问题与四特征

瓶颈从「会不会干」转到「人跟得跟不上」

单任务 Agent 已能少人盯着干活；人通常只能跟进约 3–5 个活跃 Session官方。单 Session + MCP/连接器仍会撞：同步阻塞、多任务上下文搅在一起、本地离线就停。

目标形态四特征官方：

  1. 连续：IM / GitHub 等多入口像同一个 Agent，用户不必记「Session X 有没有 Y」。
  2. 高效：可并行多任务；不必等上一条命令结束才能接新指令。
  3. 主动：听环境事件自己推进；不该插嘴时安静。
  4. 持久：尽量始终在线，异常可恢复。

文章强调：单个经典 ReAct Loop 撑不住这四项，所以要改底层组织，而不是只堆提示词官方。

第 04 节

Router–Worker 双层架构

架构图

层职责官方模型/工具倾向
Router全局序点、协调、记忆；接所有人类入口；只交互与分派，不亲自执行可用更轻模型；甚至可不挂 Bash
Worker上下文隔离；干一件事；可再开 Subagent / 自己就是 Agent Team（对 Router 透明）通常最强模型 + 完整工具；不直接对用户说话，只向 Router 汇报

Router ≠ Team Lead

常见 Agent Team Lead 拆的是一个复杂任务并高频协调；Router 管的是任务之间的关联与分派，不介入单任务内部拆解官方。系统设计意图：Session 应是实现细节，不该是用户的认知负担官方。

能力视角上的新特性还包括：跨信道任务连续、投机执行（如群里报 bug 先静默复现）、信道适配输出（IM 单次约 ≤100 词；GitHub/邮件结构化交付）等官方。

第 05 节

事件路径：Fast / Slow 与 Thread 直通

流程图

  • Trigger：环境半结构化事件（群聊/邮件/日程/评审/CI…），不再主要靠人手敲提示词官方。
  • 两级过滤：来源/群组/白名单等确定性规则（Fast）先滤；剩下来再给 LLM 策略（Slow）官方。
  • Thread：同一 PR / 同一 IM 话题 / 同一邮件串上的连续 Trigger官方。
  • 订阅多对多：Worker 可订多个 Thread；多 Worker 订同一 Thread 时共享事件、自行发现冲突官方。
  • 直通意义：消融去掉直通后完成时间几乎不变，但 Router 决定数约 +30%，读缓存 token 约 +37%（23.23M → 31.77M）——直通主要省 Router 成本与延迟，不是提质加速本身官方。
第 06 节

上下文、异步、部署、Watchdog

Inline & Spill + Chain of Recall

把上下文窗口当 Cache官方：

  • Inline：近期高概率用到的信息直接进窗口（相邻消息、前 50 字、关联对象 ID…）；
  • Spill：超预算/低频内容只留指针，按需工具续读；
  • Chain of Recall：Trigger / Thread / Worker Session 带唯一 ID，注入时内联下一跳 ID，模型沿引用图多跳找回跨信道旧任务——缓解 Router 不能塞全历史的问题。

异步 ReAct

经典 run() 阻塞整步；异步改为 start() / stop()，立刻回 Started，结果当新事件回灌；前台可继续收消息官方。这是半双工 → 近似全双工的运行时改动，落在 Harness 层；Harness 已实现，默认未开官方。

存算分离 + BYOM

两步解耦官方：

  1. Agent Loop 计算 → 云端无状态容器；Session 等 → 数据库；
  2. 执行环境留在原地 → 端侧 daemon 只执行命令、不存会话；支持 BYOM（Bring Your Own Machine）以及云托管/按需环境。

对齐 Anthropic「脑手分离」叙事，但优先接用户本机（未提交改动、本地凭据、间歇在线），而不只是托管沙箱官方。

Watchdog

主系统外的独立 Session + 定时消息：盯基础设施故障 + Worker 是否空转/跑偏；维护者可用自然语言问因、改提示词/触发规则官方。

第 07 节

实验表（作者标注：合成负载，初步参考）

设定：约 300 条消息 / 约 20 条工作请求；编码用「只耗时」工具代替；间隔与工作时长按 1/4 缩放；模型调用耗时真实；每方案 5 次官方。

方案完成时间 p50 / p95（分钟）读缓存 token / 次
Super-agent12.4 / 15.723.23M
Super-agent（无直通）12.6 / 15.531.77M
单 Session + Subagent（中性提示）20.4 / 29.56.05M
单 Session + Subagent（优先委派）13.8 / 29.010.82M

解读官方+ 评论：

  • 中性提示下模型 5 次从未调用 Subagent，主会话被新消息打断 → 长尾很差；
  • 「优先委派」提示仍不如架构层强制「Router 不干活」稳定；
  • Super-agent 用更多 token 换更短、更稳的完成时间（调度收益，非单任务质量收益）。

Router 压力：Trigger 约 1 → 40 条/分钟时，平均 batch 1.0 → 2.8；单次请求 2.5 → 3.9 s；单个决定分摊推理 6.4 → 1.6 s（积压合并进 Prefill）官方。

第 08 节

开源原型与安全开放问题

原型大致落地了什么〔官方 README〕

仓库 deepseek-ai/dsh-superagent-prototype（MIT）：面向单个 GitHub 仓库的主动 Coding Agent，打成 Harness bundle；可选飞书。领域模型大致：Trigger → Eval/Decision → Ticket/Mandate → Assignment → Worker Session；Engine 单写者；SQLite；Effects 队列。Router preset 小工具集；Worker preset 完整工具（长命令转后台）。管理面板突出「需要人」的事项。

Worker 以操作者 OS 用户身份跑命令且无审批——文档明确要求隔离环境 + 专用 GitHub 账号官方。

文中未完全落进原型 / 标为未来方向：完整云端存算分离与 BYOM daemon、Watchdog 全套、部分路由/记忆设计官方。

官方承认的未解决问题

  1. Router 规模化：何时分片、Worker 何时需要直连；
  2. 跨月级长程记忆；
  3. Session 对用户隐藏之后，任务可视性与中途介入如何产品化；
  4. 多实例上下文边界与 A2A；
  5. 安全与隐私（最硬）：云端 Loop 被提示词注入/入侵 → 端侧全控风险；凭据进入模型上下文的泄露；需要「用不接触凭据的方式用凭据」官方。

第 10 节

Dong 的理解〔讨论〕

  1. 先分清三层：模型能力 ≠ Harness 插件运行时 ≠ Super-agent 调度组织层。
  2. Router 不干活是架构约束，不是提示词建议——实验里「请优先委派」仍抖长尾。
  3. 事件两级过滤 + Thread 直通省的是 Router 注意力与 token，不是魔法加速单任务。
  4. 上下文当 Cache（Inline/Spill）+ 引用链（Chain of Recall），比「把全历史塞进 Router」现实。
  5. 异步工具与 BYOM解决的是「人还在打字 / 电脑在自己桌上」的产品现实。
  6. 安全是一等公民：无审批的本机执行 + 云端 Loop，没有隔离就不要在真实凭据环境试原型。
  7. 和 RSI 工具链：Super-agent 解决「怎么同时活着跑多个任务」；Harness²/GEPA 解决「怎么把单个配置变好」——可一起用，不要互相替代。
