第 01 节

个人 Agent 与记忆/上下文管理

Context Is a Pipeline：窗口只用了 5.75%，三分之一的工具结果却在进模型前被截断

arXiv · 2026-10-28 · 原文 约 25 分钟

问题。 一个读 Linux 内核 trace 找故障原因的 Agent，上下文窗口几乎是空的，诊断却时对时错。原因不在模型，而在 harness：它把每个工具结果的 JSON 文本按固定长度直接切断，排在末尾的字段永远到不了模型。窗口大小和最终准确率这两个常用指标，都看不到这种"进模型之前就丢了"的损失。

怎么做的。 论文把 Agent 的上下文拆成五段流水线，逐段测量丢失；重放 864 条真实工具结果（其中一条来自生产 trace）；再用对照实验检验截断的代价；最后调查了 7 个 Agent 框架的工具输出处理方式。

关键数字。 论文

  • 720 次运行中，最大的一次提示只占窗口的 5.75%；但 11,189 条工具结果里有 3,827 条被截断，每一条截断后都成了非法 JSON。
  • 同一批结果里，一个字段只在 4.7% 的调用中到达模型，另一个字段到达率 99.3%；证据落在哪个字段取决于故障进程启动得早还是晚，诊断准确率也恰好按这条线分开。
  • 生产 trace 那条，现行截断把故障证据的 128 条记录全部删掉。
  • 对照实验里，截断的代价先体现为多干活而不是答错：工具调用多 43%，计算量翻倍，产出率从 0.61 降到 0.31；只要有别的路径能拿到信息，Agent 仍能答对。
  • 7 个框架里有 2 个用同样不安全的方式截断工具输出。

局限。 只有一个任务领域；截断是否就是准确率下降的原因，作者自己也说还没证实。

评论方法很朴素，价值在于测量本身：给自己的 Agent 加一项"工具结果被截断的比例和截断位置"的日志，很可能比换更长窗口的模型更有用。

When Retrieval Is Not Enough · Spine · arXiv · 2026-10-28 · 原文 各约 15–20 分钟

  • Stratum论文： 752 个真实修 bug 提交里，修复中位数只改 2 个文件，这些文件加直接 import 不到仓库的 10%，瓶颈在"选哪些"而不是窗口容量；47% 同改的文件对在结构上毫无关联，只能从历史经验中挖。Stratum 是跟着仓库走的分层记忆，每次返回都标明给了什么、还剩什么、花了多少。8 个真实 bug 的多会话实验里，继承上一会话记忆（由另一个模型写的）的新 Agent 在 24 次中 21 次找到根因文件，纯检索基线只有 6 次（p<10⁻⁴），token 中位成本低 4.5 倍；百万节点检索中位耗时 1.7 ms。评论样本只有 8 个 bug，但"记忆写给下一个会话看"的设计思路清楚。
  • 过时事实论文： 在 MemoryAgentBench 的 FactConsolidation 上，Qwen2.5-7B 把 BM25 检索预算从 64 加到 512 token，准确率从 45% 掉到 32%，而事后审计显示每次都检索到了最新陈述。控制证据量不变时，把一条无关陈述换成该事实的旧版本，准确率从 100% 掉到 44.6%（Qwen3-14B 为 87.8%）。评论记忆系统做更新时，删掉或显式标记旧版本，比多召回几条更重要。
  • Spine论文： 让 Agent 显式声明子任务边界，运行时把子任务树在每次调用前即时编译成上下文：未完成的子任务保留细节，已完成的只留结果，同时保住前缀缓存。接进 Codex 后用 GPT-5.6 Sol，SWE-Milestone 分数比原生 Codex 高 11.8%、总成本低 32.4%；与递归子 Agent 分数相当，成本低 73.7%。

第 02 节

RSI（自我迭代 / 人参与的迭代）

Harness 不再单独进化：CoHARL 与策略一起练，RuHarness 让评分标准跟着变，Trinity 按能力树组织

RuHarness · The Trinity · GEPA-Curator · EMMA · arXiv · 2026-10-28 · 原文 各约 15–25 分钟

问题。 过去一个月的自改进论文大多是"固定模型，搜索 harness"或"固定 harness，训练模型"。但策略变了，最适合它的 harness 也会变；评分标准不变，Agent 新暴露的弱点就没人管。周三一天有五篇论文从不同方向处理"谁跟着谁一起变"。

怎么做的。 论文

  • CoHARL： 一个共享策略配一群可执行 harness，策略在整群 harness 的 rollout 上做 RL，提议器根据执行轨迹在训练中修改 harness 代码。
  • RuHarness： 从轨迹中持续发现并重估行为评分标准（rubric），优先处理最相关的未解决弱点，再据此定向修改 harness，任务目标保持不变。
  • The Trinity： Creator、Explorer、Evolver 三个角色；Evolver 把按表面类别组织的任务树改成按共享能力组织的能力树，Creator 为同一能力节点造简化的可验证模拟世界，Explorer 沿树进化可复用的能力模块，最后用路由器按任务选模块组合。
  • GEPA-Curator / EMMA： 前者先筛掉可能来自噪声评审、随机执行或 harness 缺陷的失败任务，再喂给提示优化器；后者把多 Agent 系统的路由记忆、角色提示和技能当作情景记忆，失败后由反思器判断该改哪一块、只改一处，并用守卫限制每次修改的范围。

关键数字。 论文

  • CoHARL 在 SWE-rebench 上平均解决率 27.6%，比只搜 harness 高 6.4 个百分点；同等训练预算下，也优于"先搜一次 harness 再 RL"和"交替更新单个 harness"。
  • Trinity 进化出的 harness 在 28 个训练基准上平均提高 34 分，在 18 个未见基准上提高 26 分，其中包括两个真实具身任务。
  • GEPA-Curator 比 GEPA 最多高 20.7%，比 ACE 最多高 21.2%（优化器用 Gemini 3.1 Pro 和 Claude Opus 5）。
  • EMMA 在 KramaBench、AppWorld、BBEH 上比最强基线最多高 32.5%，训练执行次数少 17–38%。
  • RuHarness 摘要只说在未见任务上优于基线，没给具体数字。

局限。 都是作者自测；RuHarness 没给数字；Trinity 的 34 分提升基于其自建的任务树，泛化到真实工作还要看。

评论同日还有一篇研究进化时评估预算怎么花：搜索阶段稀疏反馈就够，最后选型时再定向补评估，用一半评估量就能在多数设置下超过全量评估（原文）。和上周"评分器被钻空子"的结论放在一起看：可靠的自改进越来越依赖评估端本身也会更新、会过滤噪声。

第 03 节

各领域模型能力进展

Gemini 4 Carbon：v5 指数 59 分登顶，网络安全三项领先，先只开放给网络防御方

Google 博客 · 2026-10-28 · 2026-10-29（CST） · 原文 约 10 分钟

发布了什么。 官方Argon 发布两周后，Google DeepMind 推出 Carbon，定位是网络安全和长时程任务最强的模型。内部团队看到它连续跑数天，在大型代码库和底层系统里定位并修复隐蔽 bug。

关键数字。 官方

  • Artificial Analysis Intelligence Index v5.0 得分 59，排第一（Argon 为 50）。第三方Artificial Analysis 确认第一，并指出它在其 Coding Agent Index 上仅次于 Claude Opus 5.5。
  • 网络安全（评测时未开护栏）：SEC-bench Pro 找漏洞 88.2%，ExploitGym 漏洞利用 54.8%，CWE-bench 打补丁 71.0%；内部基准上生成安全代码的成功率是 Argon 的 2 倍以上；Chrome 团队称它生成高质量补丁的表现是"另一家实验室的大型前沿模型"的 10 倍以上。
  • WebDev Arena 提高 89 Elo，排第 4。
  • 对齐：Terminal-Bench 4.0 上作弊成功率降到 0.0%、作弊尝试 0.4%；内部真实编码环境中高严重度失调警报下降近 80%；无依据的陈述比 Argon 少约一半；越界行为降 26%、做不到位降 29%；Gray Swan 间接提示注入基准攻击成功率 0.0%（Argon 为 0.7%）。

可用性。 官方参与美国政府自愿性的发布前测试；本周先给一部分网络防御方，经 Fairwind 计划逐步扩大，开发者和消费者"尽快"。价格与 Argon 相同，推介期每百万 token 输入 2 美元、输出 10 美元，之后 4/20 美元。

局限。 跑分多为官方自测，外部还用不了；第三方X 上多方对比指出 Opus 5.5 仍领先 OSWorld 和计算机使用，GPT-6 Astra 仍领先 FrontierSWE 2。

评论前三名在 v5 上只差 2 分，"按任务选模型"比"认一个最强"更现实。更值得注意的是发布方式：能力最强的一档先进可信渠道、后对公众，正在成为三家前沿实验室的共同做法。

是否值得读原文 · 值得读"对齐"那一节，几项 Agent 行为指标（越界、做不到位、遇歧义先问）比跑分更贴近日常使用。

第 04 节

世界模型 / 具身

BoxWorld：让代码写的规则引擎管"发生什么"，让视频模型只管"长什么样"

arXiv · 2026-10-28 · 原文 约 20 分钟

问题。 想做一个可交互的视频世界：用户定规则"推开门后灯亮、捡到钥匙才能开箱"。端到端视频世界模型把交互规则学在生成器内部，很难指定对象级规则，也难推断后果。

怎么做的。 论文把交互推理和渲染拆开。用户写规则，编码 Agent 生成一个 Box World Engine，负责判定交互结果，并以布局框、持久对象属性和动态状态变量的形式输出状态流；Box-State 生成式渲染器把这个状态流自回归地渲染成视频，外观和物理效果交给生成模型。训练分三步：从开放域视频学对象定位，从游戏视频学状态转换（都自动标注），再在自生成的历史上做 rollout 蒸馏。另建了配对基准 PairedStateBench 测细粒度交互控制。

关键数字。 论文摘要称明显优于端到端世界模型，并在多个公开基准上有竞争力，但没给具体数字。

局限。 规则引擎能表达的交互受限于"框 + 属性 + 状态变量"这套接口，连续物理（流体、形变）仍靠渲染器去猜。

评论思路和短剧流水线里"先用 3D 白膜锁空间和运镜、再让视频模型渲染"是同一类：把可验证的结构放在生成器外面。

是否值得读原文 · 值得看方法图和 PairedStateBench 的设计，结果部分等项目页数字。

速览：潜空间世界模型没有一个真正学到了环境动力学；MLE-World 用 4B 模型预测 ML 实验结果

MLE-World · arXiv · 2026-10-28 · 原文 各约 15 分钟

  • 潜空间世界模型的极限论文： 把"忠实的潜空间世界模型"定义为环境转移映射与潜空间动力学之间的等变条件，并提出潜空间 rollout 一致性（LRC）指标。结论是：所研究的几个 SOTA 潜空间世界模型，没有一个是靠忠实建模环境动力学来完成任务的。评论任务分数高不等于学到了世界，这个指标可以拿来查 JEPA 类模型。
  • MLE-World论文： 从 Qwen3.5-4B 微调，根据代码和数据描述直接预测程序的终端输出（报错、训练日志、验证分数），并给出置信度；置信度低时才真跑。在 17 个 MLE-bench Lite 任务上，留出程序的预测与真实输出一致率 77.9%，大得多的提示模型只有 41.1%；用它指导测试时扩展，观测平均表现最多提高 22.1%，真实执行更少。评论这是"给研究 Agent 用的世界模型"，和第 2 节的自改进直接相关：能便宜地预演实验，搜索就能更宽。

第 05 节

AIGC 视频生成

即梦上线短剧工作室（剧本、角色、分镜三个自研模型）；Higgsfield Cinema Studio 4.0 单次生成 30 秒多镜头

2026-10-26 · 2026-10-28 · 原文 各约 5 分钟

即梦短剧工作室。 官方字节跳动即梦把短剧生产做成一条流水线，三个自研模型：

  • DreamScript（剧本）： 原创、改编、出海、解说多题材生成，"爆款诊断"，可解析 10 万字长文本。
  • Anycook（图片）： 为短剧美术调校，做差异化人物设定和多风格场景。
  • DreamShot（分镜）： 画布和故事板两种模式，对话式改稿与全局修改；"3D 导演台"可设机位和运镜做动态预演，并串联关键分镜检查衔接和节奏。
  • 后期与出海： 单镜头定点重拍、人声与背景音分离后重配音、自动切镜、资产一处修改全链路生效；"重制转绘"可上传已有短剧，自动识别角色、场景、道具和镜头结构，按目标地区重新生成画面，保留原片节奏和镜头语言。

Higgsfield Cinema Studio 4.0。 官方单次生成 30 秒多镜头场景，最多 50 个参考（3.5 版为 15 秒、9 个参考）。新增"导演面板"：7 种类型片、1960–2020 年代设定、剪辑节奏、相机与镜头型号、50 多种调色预设、可调光照，加上 POV、机械臂、直升机等运镜；"情绪轮"控制角色表情和肢体。可向前或向后延长已有视频、局部修改某个物体或人脸、同一次生成原生音频。价格：16:9 带音频，720p 10 秒 70 积分，1080p 30 秒 480 积分（限时 360）。每次生成都会筛查真人脸和受保护 IP。

局限。 两家都只有官方描述，没有一致性或成片质量的独立评测；即梦"3D 导演台"的具体能力（是否支持导入白膜场景）未说明。

评论两家都在把"预演 → 生成 → 局部重拍"放进一个工作台，和用 3D 白膜做预演、再交给视频模型渲染的短剧流水线是同一个方向；即梦的 3D 导演台和重制转绘值得实际上手看看接口粒度。

同日论文：ReferStream。 论文流式生成到一半上传新角色图，要让它自然进入当前场景又不破坏已有角色。做法是把参考图 latent 放进最新场景 latent 的目标区域一起编码，只用它条件化"注入"这一段，再恢复被覆盖的全局缓存；无需训练。摘要称在文本遵循、主体相似度和数量准确性上高于对比方法（含提前拿到全部参考的离线方法），但没给数字（原文）。评论缓存层面的小技巧，适合"中途加角色"的交互场景，看摘要和演示即可。

第 06 节

高效使用 AI / Agent

kw-bench：同一个非前沿模型，两个实验室 harness 交了白卷，两个通用 harness 拿到五成多

InfraDev · ReInBench · arXiv · 2026-10-28 · 原文 kw-bench 约 15 分钟，另两篇各约 15 分钟

问题。 审计、税务、尽调这类知识工作，答案已经存在，只是藏在多个系统里残缺、不一致的数据中，要精确到分地还原并能说清依据。现有知识工作基准多是"按要求生成一份东西"，很少测这种调查型任务。

怎么做的。 论文第一个任务族是跨三代 SAP（旧 ECC、部分迁移的 S/4HANA、顾问重设计）重建五年增值税，只给原始导出：页眉、本地数字格式、残缺的关联表，没有任何文档说明它们怎么连。确定性打分，不用 LLM 评审。

关键数字。 论文

  • 同用 DeepSeek v4.1 Flash 跑两小时：OpenCode 0.542、micro-cc 0.528，Claude Code 和 Codex 都是 0.00。作者认为失败原因是"惯性"：长会话中没能同时保住许多弱信号。
  • 换成 Claude Opus 5.5，micro-cc 和 Claude Code 分别得 0.9986 和 1.000，用时 22 和 25 分钟。

同日两篇。 论文InfraDev 用 Megatron-LM、vLLM、verl 的真实 PR 做了 36 个多文件、多 GPU 任务，6 个前沿模型最好也只解决 38.9%；隐藏探针拒掉了 32% 通过全部官方测试的提交；只给原始 PR 描述时没有一个模型解决任何任务。ReInBench 收集 1,259 条 Agent 轨迹、1,403 个错误事件，其中 725 个错误 Agent 自己在几步内恢复了；据此训练的预测器能判断哪些错误值得人介入。

落地数据：犹他州试点。 第三方犹他州给 10 个州机构的 34 名开发者发 Claude Code，四周后 80% 的人 30 分钟内配好环境，77% 在一小时内有"顿悟时刻"，71% 自报节省至少 20 小时，约 29% 超过 40 小时；全是自报数据，没有对照组（Boris Cherny 原帖，约 2k 赞 · GovTech 报道）。

局限。 kw-bench 目前只有一个任务族；"实验室 harness 离开自家模型就失灵"只在一个模型上测过。

评论实用结论有三条：用便宜或开源模型时，harness 选择对结果的影响可能比模型还大；Agent 通过了测试不等于改对了，基础设施类改动要自己补"内存、时间、流量"检查；Agent 出错时不必马上打断，先看它能不能自己恢复。

是否值得读原文 · kw-bench 值得读，篇幅短、结论直接；InfraDev 的失败分析适合做训练/推理基础设施的人。
