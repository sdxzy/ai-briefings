第 01 节

个人 Agent 与记忆/上下文管理

记忆系统常按「是否忠实记下了对话」来打分；今天有一篇论文把标准改成：这段记忆有没有让下一次回答变得更好。

Leto：把 Agent 记忆看成对未来有用的预测，而不是对过去的忠实记录；PrefEval 准确率 60.5%，比最强对照高 16.3 个百分点

Shuguang Chen、Salman Paracha（DigitalOcean） · arXiv:2611.33005 · 11 月 25 日（Wed）批次 · 原文 摘要与设定约 8–12 分钟；方法与表格约 20 分钟

问题。 论文一个跨会话的 Agent 需要记住用户上周说的偏好，或一项没做完的任务。现有记忆系统多半从对话里抽事实、写摘要，再按与当前请求的相似度取回。评测也常看记忆是否覆盖了对话、取回的内容是否含有标准证据，也就是对过去的忠实程度（fidelity）。但用户往往不会在新请求里重申自己的偏好。论文用一个虚构订酒店的例子说明：只按请求匹配，可能订到用户去不了的酒店；若同时送上「用户使用轮椅」这一条未在当前请求里出现的记忆，结果才会可用。忠实记下对话，不等于下次回答会变好。

方法。 论文作者把记忆写成一个预测问题，并称其为效用（utility）：写入时要预测哪些信息以后用得上，取用时要预测这次回答需要哪一段，再用回答的结果回写选择。Leto 用索引保留对原始对话细节的访问，请求到来时做 memory replay，补上请求没有明说、但回答可能需要的上下文，再用结果更新效用。对照了六套记忆系统，评测分三条线：个性化（PrefEval、PERMA），长程任务（MemoryArena），长上下文问答（LoCoMo、LongMemEval S）。

关键数字。 论文PrefEval（十轮填充之后）上，Leto 的准确率为 60.5%，比最强对照 Hindsight 高 16.3 个百分点；RAG 与不用记忆的基线分别为 13.1% 与 3.3%。以词面重合为代理，偏好出现在 Leto 所送上下文里的比例为 84%，其他记忆系统为 12%–69%。摘要还写，PERMA 的任务完成比最强对照高 3.1 分。长上下文上，Leto 在 LoCoMo 为 71.82%（比直接检索原始历史的 RAG 低 2.79 个百分点），在 LongMemEval 为 73.20%（比 RAG 高 6.80 个百分点）；文中称 RAG 取回的 token 大约分别是 Leto 的 1.7 倍和 8 倍。MemoryArena 上，相对无记忆基线的增益随任务链加深而变大：购物链从第 1 次购买的 1.3 个百分点升到第 6 次的 7.3 个百分点。

局限。 这是 DigitalOcean 作者的一篇预印本，对照系统未必覆盖你正在用的产品记忆。PrefEval 的 16.3 个百分点是在特定协议（十轮填充）下对 Hindsight 的差值，不能当成所有个性化任务的通值。效用回写依赖「回答好不好」这一信号，线上若缺少可靠反馈，这一环会变弱。LoCoMo 上它仍低于直接检索全文的 RAG。

短评。 评论这和近日简报里「该记多少」「压缩历史还是各留一份可查记录」是同一类问题，只是判据从覆盖率改成了下游回答。例子很清楚，表格也够用来判断自己关心的场景；方法并不新奇，不必单独做深挖。

是否值得读原文 · 值得读摘要、订酒店的例子和 Table 1 / Table 3，约 10 分钟。不必从附录的分项误差开始。

第 02 节

RSI（自我迭代 / 人参与的迭代）

生成代码已经很快，难的是证明新代码和正在跑的旧系统行为一致。Anthropic 把这个问题写成了一篇工程实录。

Anthropic：用正在运行的 Messages API 当验证器，把服务从 Python 迁到 Rust；官方称每请求 CPU 约降 70%，中位首 token 时间约降 20%

Lance Martin 等 · Anthropic · 标注 November 25, 2026 · 原文 约 18–25 分钟

问题。 官方Messages API 是客户以及 Claude Code、Cowork 等自家应用访问 Claude 的主入口。文中称，从 2024 年初到 2026 年秋，API 流量大约增长了 1,800 倍。服务最初用 Python 写成，后来每条请求都要做校验、组提示、分词和安全分类，再把输出流拆成文本、思考和工具调用。完整重写通常令人却步：测试很难覆盖全部线上行为，而且旧服务还在继续加功能。

方法。 官方他们先只把解析模型输出的部分改成 Rust、再从 Python 调用，CPU 大约降了 8%–10%，但每个 token 要在两种语言之间往返三次，复杂度增加得不值。到 2026 年 5 月，文中称 Claude 已写出 Anthropic 合并代码的 80% 以上，生成不再是主瓶颈，验证才是。约 700 个集成测试也不够：测试和 Python 实现绑在一起，移植后审计发现 100 多处断言被削弱；2026 年 4 月 Rust 版测试通过率约 98%，但在对比的生产流量上，输入侧一致的比例大约只有四分之一。他们于是把仍在运行的 Python API 当成预言机，做流量镜像（shadowing）：模型只跑一次，把同一份输出重放到 Rust，再在计费和限额只计一次的前提下，逐步比较请求被接受与否、设置解析、提示拼装等检查点。因为不能阅读用户请求和回复，他们只记录差异出现的步骤、位置和长度，形成指纹，再按指纹归并后交给智能体修复。内环在沙箱里用自造请求快速试假设，外环用镜像的生产流量确认，规则以散文形式写入可被后续智能体阅读的记忆。

结果。 官方公开流量在 2026 年 9 月切到 Rust。官方写：在不停机、也不冻结功能开发的前提下，新服务每请求 CPU 约少 70%，中位首 token 时间约少 20%。文中配有 CPU、内存和首 token 时间的图，但正文没有单独给出内存下降的百分比，这里不另写一个内存数字。Claude 大约用一周写出了核心请求路径的第一版；人逐渐从亲手追差异，退到在循环之间做判断、写规则和审查修复。

局限。 这是一家公司对一条自己最熟悉的服务的迁移实录，不是可直接套用的通用框架。镜像依赖「旧系统仍可作为正确标准」，若旧系统本身有错，新系统会被拉去对齐错误行为。Claude 回复并不确定，所以他们必须比较模型调用前后的各步，而不是只看最终文本。测试通过率与生产一致率之间的缺口，也说明「测过了」不等于「和线上一样」。

短评。 评论值得读的不是「用 Claude 重写了 API」，而是他们把验证信号设计成智能体能行动的指纹，并把人放在循环外侧。若你也在用 Agent 改生产系统，可先问：有没有一个不依赖阅读用户数据、又能定位差异的验证器。

是否值得读原文 · 值得。重点看「测试约 98%、生产输入大约只对上四分之一」这一段，以及检查点 / 指纹 / 内外环，约 20 分钟。

第 03 节

各领域模型能力进展

通用模型要做实验室里的结构鉴定，仍然得把推理接到领域工具上；与此同时，OpenAI 的数学预印本给出了一个更强的主张——矩阵乘法的指数恰好是 9/4。

DeepMind：为 Antigravity 配备质谱技能；在 100 条已有库谱上，三种 Gemini 的精确匹配约 97%，轻量模型与旗舰持平

Robert Brunck 等 · Google DeepMind · 标注 November 25, 2026 · 原文 博文约 12–18 分钟

问题。 官方一滴血液、土壤或植物提取物里，质谱仪可以测到成千上万个分子信号；串联质谱（MS/MS）还会记下分子裂成的碎片。但谱峰并不直接等于结构。标准做法是把谱和已有参考库比对，文中称十年扩库之后，平均也只能注释约 5% 的实测谱，人体样本约 10%，其余常被称为质谱里的「暗物质」。许多未注释信号对应的分子其实已出现在公共化学数据库里，只是还没有参考谱，需要从碎片反推。每一步的工具是现成的，但一条研究可能有数千张谱，人工跑完全流程跟不上。

方法。 官方Mass Spec Skills 是一套给 Google Antigravity 用的领域技能：把 Gemini 的化学推理，与社区常用工具和公共数据库查询接在一起。智能体按用户的自然语言任务串起流程，并给出可供化学家复核的证据报告。文中的端到端例子：负离子前体 m/z 395.1387，先去掉 1,700 多个低强度噪声峰，剩下 19 个碎片峰；在参考库没有高置信匹配时，用 SIRIUS 得到公式 C20H21ClN6O（质量误差 −1.5 ppm），再对 PubChem 中 845 个同分异构体打分。按峰强度覆盖，有几个候选都解释了 14 / 19 个峰、合计 97.7% 的碎片强度；智能体再用中性丢失和键断裂是否说得通做区分，排除没有脲键、无法丢失 HNCO 的候选，最后得到 CID 137835447。

评测。 官方他们从 MoNA 中 Enamine REAL 的 MS/MS 集合抽样 100 个化合物（结构也在 PubChem 中），去掉几乎不碎裂的记录，比较三种设置：无网络无技能、仅允许上网、上网并启用技能；模型为 Gemini 3.8 Flash、Gemini 4 Argon 和 Gemini 4 Carbon，每条谱三次尝试，超过一小时记为失败。无网络时，三个模型的准确率都低于 4%。只给网络时，旗舰模型仍漏掉约四分之一到三分之一，轻量模型漏掉四分之三以上。加上技能后，三个模型都在约 97% 的尝试中识别并验证了确切分子，轻量模型与旗舰持平。技能还降低了生成 token：相对「有网络、无技能」，Flash 几乎降到约四分之一，Argon 约一半，Carbon 大约少五分之一。

局限。 约 97% 测的是参考库里已有的谱，不是「暗物质」或全新天然产物。官方写明：对数据库中不存在的分子，系统不能自行确认结构，只能给出公式、峰归属和注释表作为起点；对映体和某些近异构体也单靠一张 LC-MS/MS 谱分不开，还需要保留时间、离子淌度或核磁等其他测量。协作单位的「大多数评估中结构预测超过 90%」是引用评语，不是这篇博文里的主评测数字，不宜与 97% 混用。

短评。 评论这和昨天 GPT-6 蛋白质设计是同一类故事的另一面：通用模型单独看谱几乎做不成（低于 4%），但加上可审计的领域工具后，轻量模型也能接近旗舰。真正要看的是证据报告和「库外分子怎么办」，而不是把 97% 读成已解决结构解析。

是否值得读原文 · 值得。先看端到端例子和三种设置的对照，约 15 分钟。

OpenAI 预印本宣称：方阵乘法指数在任意域上恰好是 9/4；Lean 形式化覆盖的是无除法电路上的陈述

OpenAI Math Release 预印本 · 标注 November 24, 2026 edition · 原文 README 约 3 分钟；论文本身需数学背景，耗时视读者而定

它说什么。 官方这份 11 月 24 日修订的预印本主张：方阵乘法的指数在任意域上都是 9/4。README 还写：论文证明了形式算术电路上与之匹配的下界；对每个边长 n≥2，至少需要 ⌈n^(9/4)/2⌉ 个非标量乘法或除法门。方阵乘法张量的几何边界秩至少为 n^(9/4)，它在基域上的渐近秩等于 n^(9/4)。下界的几何框架放在同日的伴生论文里。仓库中的 Lean 开发证明的是：在任意域上，计算形式多项式恒等式的无除法电路，方阵指数为 9/4；形式化范围文档还写了对偶和矩形指数。同一目录下还有 10 月 2 日的上界预印本；此次文本把主张写成「恰好是 9/4」，并补上匹配下界。

公开讨论。 官方Brockman 在 11 月 25 日 10:31（Asia/Shanghai）发帖，并转述「This is really the kind of result that I never thought I would see in my lifetime」。他在随后一条里把此事放进「AI 正在帮助我们发现更好的计算方式，并理解计算的根本限度」。这些是介绍，不是额外的数学证明。

局限。 这是预印本，不是经过传统同行评审的定论。官方自己把 Lean 的范围写在「无除法电路 / 形式多项式恒等式」上，不要把机器检查过的这一段，自动升级成论文里每一句主张都已被形式化，更不要升级成「证明已被人读懂」。这和 11 月 24 日简报里 Lean FRO 对黎曼猜想 Lean 证明的态度是同一类谨慎：检查通过是一件事，理解是另一件事。对算法工程的实际加速，文本也没有给出可落地的实现数字。

短评。 评论若你关心「模型能否产出可核验的新数学」，先读 README 和形式化范围，再决定是否打开 PDF。不宜只凭标题或转述把 9/4 写成已关闭的问题。

是否值得读原文 · 先读 README 和 Lean 范围说明，约 5 分钟。除非你能核对证明，不必把 PDF 当作今日必读。

第 04 节

世界模型 / 具身

语言模型已经能在仿真里给人形机器人写控制代码。今天的新评测说明：走到目标已经不难，稳稳抓住一个盘子还很难。

Artificial Analysis 发布 AA-Robotics-Sim v0.1：GPT-6.2 Astra 以 71.0 分领先；洗碗和洗衣仍然接近做不成

Artificial Analysis · 标注 November 25, 2026 · 原文 约 10–15 分钟

设定。 第三方这是仿真研究预览，接在他们上个月的真机手臂评测 AA-Robotics v0.1 之后。模型通过同一套 Stirrup 编程智能体，直接控制仿真中的 Unitree G1（29 个关节、三指手、头部相机；物理引擎为 NVIDIA Isaac Sim）。共 10 项家务和轻工业任务。每个任务先在 5 个新场景里练习，只保留模型写下的笔记、代码和技能，再拿到 10 个房间、光线和布置都不同的新场景上评分。每个回合 0–100 分，允许部分分；总分是 10 项任务得分的平均。
