第 01 节

一句话读懂

开悟版：先把结论放在前面

读者 Mark 的理解 · 编辑稍作打磨

非法蒸馏 = 用欺诈账号与中转站，大规模套走前沿模型的回答——尤其是推理痕迹——再拿去训自己的学生模型。

Anthropic 说近期措施已把自家平台上可被收割的推理 token 量压到原来的约 1/10 到 1/100。它靠的不是单一开关，而是五层叠在一起：

  1. 不让你随便改上下文。对新 API 账户启用 preserved thinking：此前的推理块周围的系统提示、工具与消息不能被编辑，代理网络也就更难反复试探。
  2. 不让块随便搬家。推理只能被产生它的组织继续用，且不能被更早、防护更弱的同系模型读出来。
  3. 像挡生物武器一样挡提取请求。两阶段分类器拦截「吐出完整推理」一类请求，假阳性 <0.1%；反复试会被限流、封号，被拦的请求从 9 月 24 日起重新计费。
  4. 先摘要再给用户看。完整推理不直接露出；客户端只拿回加密/签名块用于下一轮。
  5. 但猫鼠游戏没结束。官方承认还没撞上「高度老练且持久」的完整绕过；跨平台与二手对话数据仍是平台侧鞭长莫及的通道。

一句话：藏推理 + 绑来源 + 拦提取 + 罚重试。做平台的要多层一起上；做应用的别把加密推理块当可公开分享的日志。

后面各节把这段拆开：第 2 节补概念，第 3 节看一张攻防图，第 4–5 节分别讲蒸馏与反蒸馏，第 6 节对照表，第 7 节给开发者带走的清单。

第 02 节

先补背景：蒸馏、推理痕迹和加密块

读后文前，先把五个词对齐。每个只讲到够用为止。

知识蒸馏 vs 非法蒸馏

知识蒸馏（knowledge distillation）本身是正统训练手段：用更强的「教师」模型对一批输入生成回答，再用这些配对去训更小的「学生」模型，让学生模仿教师的行为。经典表述见 Hinton 等人的 Distilling the Knowledge in a Neural Network 与序列级蒸馏 Sequence-Level Knowledge Distillation行业做法。

Anthropic 把 非法蒸馏（illicit distillation）定义为：工业规模、隐蔽地、未经授权地抽取一个模型的能力并复制到另一个模型上；通常靠虚假账号网络、盗刷卡与被盗 API key 完成官方。合法蒸馏是实验室蒸馏自己的模型；非法蒸馏是竞争对手（或国家背景实验室）用欺诈手段套走别人的能力。

为什么推理痕迹比最终答案更值钱

推理模型会在给出可见回答之前，先写出很长的中间思考（chain-of-thought / reasoning）。相对最终答案，完整推理更密：问题怎么拆、中间假设、工具调用轨迹、纠错路径都在里面。用完整推理训学生，通常比只用最终答案效果好很多行业做法；Anthropic 自己的评估也显示：用 Claude Opus 4.8 的完整推理转录本训出的模型在 SWE-bench Verified 上到 80.4%，只用摘要推理则降到 71.8%官方。所以反蒸馏几乎把火力都压在「别让完整推理落到蒸馏者手里」上。

摘要推理 vs 受保护 / 加密推理块

多数 API 不再把明文完整推理直接交给用户。常见两层：

  1. 摘要：把内部推理压成一段人类可读的短文给用户看。信息量低，蒸馏价值也低官方。
  2. 受保护块 / 加密推理块：把真实推理封进不透明字符串（文档里常叫 thinking signature / thought signature / encrypted reasoning blob），客户端必须在下一轮原样回传，服务端再验签、解密、继续对话。这样服务端可以做无状态多轮，又不必把明文推理长期存在服务器上。Claude 文档见 Thinking；OpenAI 见 Reasoning models；Gemini 见 Thought signatures行业做法。

Matthew Green 在 Let’s talk about encrypted reasoning（2026-05-29）里指出：这些块在密码学上往往用全局密钥做认证加密，因而可跨会话、甚至跨账户回放——验签只证明「内容没被篡改」，不证明「这块属于这段对话」行业做法。arXiv 2608.09867 进一步表明：若同家族里较弱的模型也能接受较强模型产生的块，较弱模型就可能被诱成「解密预言机」，把隐藏推理誊写出来行业做法。披露后各厂商已修补同类攻击；本页只保留概念层结论。

代理网络（proxy / transfer station）

Anthropic 在不对中国等地区提供商用接入时，非法实验室会经由代理服务 / 中转站访问模型。中转站用虚假身份、虚拟卡、被盗 key 批量开号，把流量打散到官方 API 与第三方云上；一家中转站曾同时管超过 20,000 个欺诈账号官方。有的中转站还会存下用户与模型的对话并转售给蒸馏方官方。这就是后文「账号池」的基础设施。

模型抽取：更老的黑盒亲戚

在「套推理」流行之前，黑盒模型抽取（model extraction）已经研究多年：只靠预测 API 的输入输出，重建近似模型或窃取部分参数。代表工作包括 Stealing Machine Learning Models via Prediction APIs（Tramèr et al., USENIX Security 2016）与面向生产语言模型的 Stealing Part of a Production Language Model行业做法。今天的非法蒸馏可以看成「抽取」在推理模型时代的加强版：监督信号从最终 token 升级为完整思维轨迹。

第 04 节

蒸馏策略：他们怎么收割数据

这一节只讲在做什么、为什么有效，不提供可复现的操作手册。具体案例编号来自 Anthropic 2026 年 9 月威胁情报报告官方。

4.1 账号与代理网络：先弄到「合法」门卡

没有稳定的 API 入口，就谈不上百万级收割。常见路径官方：

  • 中转站批量开号：虚假身份、住宅代理、一次性邮箱、虚拟卡；被封一批立刻换另一池。
  • 盗用合法客户的 key / session：从泄露仓库、APK、容器镜像、被攻破的客户环境里挖凭证，再把蒸馏流量挂到受害者账单下。
  • 混流掩护：把蒸馏请求与无关正常客户流量混在同一代理网络里，降低「全是同质提示」的指纹。

二月披露里，DeepSeek / Moonshot / MiniMax 合计经约 24,000 个欺诈账号产生逾 1,600 万次交换；九月报告又写到 Alibaba（GTG-16005）峰值近 300 万次/天、逾 3,500 个欺诈账号，累计逾 1.51 亿次交换官方。

4.2 提示模式：从「被动学回答」到「主动掏推理」

早期是被动蒸馏：正常发任务，收集回答再训。平台改成「只给摘要推理」之后，攻击转向主动提取：用各种措辞诱模型把隐藏推理原样写出——从「逐字输出先前推理」到「当作调试会话」「用另一种语言翻译工作记忆」、再到一次实验里试 12,000 种不同套路找能漏的那几种官方。普通用户几乎不会要求模型「吐出完整隐藏推理」，因此这类请求本身就是强信号。

4.3 在会话之间、模型之间、账户之间搬家

当单次「请写出来」会被分类器挡住时，蒸馏方改走结构漏洞——不改加密块的内容，只改它出现的上下文官方：

搬家维度意图（概念层）为何曾经有效
跨会话把上一通拿到的受保护块塞进新会话验签通过 ≠ 属于本会话；模型可能把块当「自己刚想过的」
跨模型强模型产块 → 同系弱模型读块弱模型防蒸馏训练往往更松，更易被诱誊写
跨账户一号被封，换代理池里下一号继续账号级封禁跟不上「九头蛇」式轮换

Moonshot（GTG-16002）的做法被官方点名：保存 Claude 返回的 thinking signature，开新会话，再诱模型把签名「还原」成完整推理——这就是跨会话回放绕过「只给摘要」的控制官方。DeepSeek（GTG-16001）用了同类手法官方。Zhipu（GTG-16006）则把捕获的推理再回灌 Claude 做清洗，再用于训 GLM官方。

4.4 静默转发与二手数据：用户以为在用自家模型

若干实验室被指把自家用户的请求悄悄转给 Claude，再把 Claude 的回复显示回去，同时存档用于训练官方：

  • Moonshot / GTG-16002：约 10 天内转发近 30 万次客户请求（多数到 Opus），经 5,380 个欺诈账号；其中一次疑似与解放军相关的用户请求，用「Kimi」分析成都大量摄像头的 CCTV，实际落到了 Claude官方。
  • DeepSeek / GTG-16001：对使用第三方编码脚手架的请求打标签后转发 Opus；案例含企业机密与境外政府相关凭证官方。
  • Xiaomi / GTG-16008：不一定把 Claude 回复直接给用户，但会把用户与自家模型的会话回放到 Claude 上做 SFT/RL 数据官方。
  • SenseTime / MiniMax：买第三方转售的 Claude 对话，或自建只卖美方模型接入的壳公司代理官方。

这比「自己写提示去套」更危险的一点：端用户以为数据留在 A 厂商，实际经过了 B 厂商，隐私与合同义务一并破裂官方。

4.5 能力瞄准：代理、代码、网络

蒸馏不是均匀取样。官方多次写到目标集中在智能体 / 工具使用、编程与数据分析、逻辑推理，以及更近的网络攻防能力官方。Zhipu 在 GLM-5.3 前曾蒸馏美国模型的网络能力；先打 Claude Fable 5，因网络防护太硬而改打更老的 Claude 与另一家实验室的模型；CAISI（NIST 下）随后评估 GLM-5.3 为当时最强网络能力开源权重模型之一，但仍落后美国前沿约四个月——见 NIST 公告官方。Anthropic 另称自家研究显示 GLM-5.3 的防护易被绕过，且愿意端到端编写安全漏洞利用官方。

蒸馏还会产生跨域外溢：即便收割的对话很少直接谈生物或网络，学生模型的一般推理能力提升仍可能抬高危险任务上的上限；而且教师模型上的安全拒绝不会自动长到学生身上官方。

4.6 概念示例：「真块 + 假上下文」

下面用一张图说明官方描述的跨会话手法在结构上是什么——不是逐步操作指南。块里的推理是真的；包着它的对话许可是假的示意。

arXiv 2608.09867 把同一结构推到「跨模型解密预言机」：不必直接越狱最强模型，只要块能被更弱的兄弟模型吃进去行业做法。Anthropic 后来用「旧模型读不了新模型的推理」「推理仅对本组织可见」等绑定，正是冲着这类搬家来的官方。

第 05 节

反蒸馏策略：官方怎么做到约 90%–99%，以及行业还在用什么

百分比口径要先钉死：Anthropic 估的是自家平台上蒸馏者抽到的推理 token 量，在分类器上线后降到原先的约 1/10～1/100；再叠加 preserved thinking 等改动。他们尚未声称这能挡住所有高度老练的持久绕过，也不能单独覆盖跨平台与二手数据官方。

5.1 接入与账号层〔官方〕

  • 用元数据与异常行为识别代理网络；尽量归因到组织再整批处置，而不是逐号打地鼠。
  • 对教育账号、安全研究通道、创业通道等易被滥用的入口加强核验。
  • 出现未授权转售或来自受限地区的信号时，可要求身份验证，否则封禁。
  • 已封与蒸馏相关的账号数以万计，常见在活动开始后两小时内处理完毕。

5.2 检测与滥用响应〔官方〕

  • 两阶段分类器（同类系统见其 Constitutional Classifiers 研究）：专门拦推理提取类请求；对最强公开可用模型假阳性 &lt;0.1%；经内外部红队，号称鲁棒性接近挡生物武器辅助的级别。
  • 覆盖 Sonnet 5.5、Opus 5/5.5、Fable 5/5.1 等最吸引蒸馏者的公开模型，并计划用于未来同类模型。
  • 发现新手法（如「把先前推理译成别的语言」「用标签夹带全文」）就快速补丁。
  • 反复尝试 → 更严限流；持续则封号。
  • 自 2026-09-24 起，对假阳性 &lt;0.1% 的高置信拦截区域（含蒸馏），被拦请求重新计费，抬高盲试成本。

5.3 输出塑形〔官方〕

  • 默认给用户推理摘要而非全文；评估显示蒸馏后 SWE-bench 从 80.4% 降到 71.8%。
  • API 侧以签名/加密块维持多轮，避免明文推理成为默认可训练语料。

5.4 把推理绑回「出处」〔官方〕

针对「搬家」：

  • Preserved thinking（Claude Fable 5.1、Opus 5.5；适用于 2026-08-31 及之后新建的 API 账户）：禁止新账户编辑 Claude 先前上下文，削弱「改前文 + 回放块」与代理网络反复试探。
  • 较新模型的推理不能被更早、反蒸馏更弱的模型读取。
  • Claude Sonnet 5.5：推理转录本仅对产生它的组织可访问。

这些直接对应 2608.09867 与 Green 文所揭示的「块可移植」结构问题——官方用产品约束补密码学绑定尚未做严的缺口推测（产品约束与论文建议的 AEAD 绑定是同方向、不同层）。

5.5 模型训练与系统级对齐〔官方〕+〔行业做法〕

  • 把「提取隐藏推理」当作与网络/生物滥用同级的拒答目标来训与评官方。
  • 行业侧还有：对教师输出加水印/指纹以便事后审计（如 A Watermark for Large Language Models、Watermarking Makes Language Models Radioactive）；训练「难蒸馏的教师」（Undistillable）；采样期干扰蒸馏（Antidistillation Sampling）；以及仅用可见输出+摘要反推近似推理的攻击提醒我们——就算藏住原文，摘要与答案仍有信息（How to Steal Reasoning Without Reasoning Traces）行业做法。

5.6 平台协同与代价〔官方〕

蒸馏流量分散在官方 API、第三方云与其它推理商。Anthropic 明确说：只靠一家不够；云与网关商应快速清退欺诈账号。代价包括：推掉蒸馏相关的付费流量（称达万亿 token 量级）、研发投入，以及合法开发者要改集成（preserved thinking）；分类器仍有 &lt;0.1% 误伤且误伤请求也计费官方。

第 07 节

开发者可带走的防御清单

下面分「你在跑推理 API / 网关」与「你只是调用方」两类。除标明官方的呼吁外，条目是工程建议建议。

若你提供模型或代理推理

  1. 别只靠摘要。 摘要是降质，不是门禁；配上提取分类器与滥用限速官方建议。
  2. 推理块要绑上下文。 至少做到：用户 / 组织 / 会话 / 模型版本之一不可跨；理想情况把前序对话哈希进 AEAD 附加数据（2608.09867 Appendix A；Green 文）行业做法建议。
  3. 守住最弱的兄弟模型。 家族内兼容解密是系统性风险；网关应拒绝「块的源模型 ≠ 当前模型」行业做法建议。
  4. 按组织打代理网络，而不是按单个 key。 共享支付指纹、设备、提示模板聚类官方建议。
  5. 高置信拦截可以计费。 把「盲试 12,000 种提示」从研究成本变成现金成本官方建议。
  6. 与云和同行共享指标。 蒸馏者会转移供应商；一家的封号若邻居不认，只是搬家官方。
  7. 发布前假设自己会被蒸。 危险能力与拒答要在权重侧可验证；开源或宽供给前用独立评测（如 CAISI 类）压一遍建议。

若你只是应用开发者 / Agent 搭建者

  1. 别把含 reasoning / thinking / signature 字段的原始日志推到公开仓库。 即使用户可见部分已打码，块内仍可能含密钥与 PII（2608.09867 在公开轨迹中解出大量凭据）行业做法建议。
  2. 需要分享轨迹时：删掉所有不透明推理字段，或只留官方提供的、已确认可公开的摘要建议。
  3. 不要经不明中转站「低价」调用前沿模型。 官方案例里，中转站会存盘转售，还会掉包成别的模型官方建议。
  4. 集成时预留 preserved-thinking 一类「不可改历史」模式。 合法产品改一次 SDK，比平台被迫全面关掉多轮推理更可控官方建议。
  5. 监控自己的 key。 被盗 key 既是账单风险，也是别人做蒸馏的马甲官方建议。

不该从本页带走的东西

本页故意不提供提取提示模板、回放脚本、分类器对抗样本或任何可直接复现的攻击步骤。若你做的是授权红队，应走厂商的官方安全渠道与法律框架建议。

第 08 节

仍不清楚的

下列问题在已核读来源中没有清楚答案，标出来避免过度解读。- 90%–99% 能维持多久？ 官方自己说不知道，并预期持续猫鼠官方。- 「高度老练且持久」的绕过长什么样？ 文中明确尚未观测到官方。- 加密块的具体密码学（算法、是否按用户衍生密钥、nonce 策略）厂商文档仍不透明；Green 与 2608.09867 的结论是基于行为实验的推断行业做法。- 跨云与其它模型商的协同实际覆盖了多少流量，无公开计量推测。- 摘要不忠实（模型在隐藏推理里已得出答案、摘要却另写一套）有多常见、对安全监督的影响多大——2608.09867 给出了例子，但不是系统审计行业做法。- 训练侧 antidistillation / 放射性水印有没有进入 Claude 生产栈，官方 10 月博文未声称推测。
