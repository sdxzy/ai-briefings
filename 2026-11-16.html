第 01 节

个人 Agent 与记忆/上下文管理

一条很反直觉的轨迹编辑实验：正确内容写进历史，并不自动等于更好的下一步。

把历史改得像已经做对，而世界里错误还在，接收者往往更糟

Salesforce AI Research · arXiv · 2026-11-13 · 原文 论文约 25 分钟（摘要、引言与两组实验设计最有用）

问题。 论文工具 Agent 会留下自己的错误记录，而压缩、修复或交接历史的系统必须决定：这些错误在文本里怎么说。先前工作多半在世界状态固定时改写历史，于是「让记录看起来已完成」和「把正确值写进去」是绑在一起的，分不清到底是哪一项在起作用。

方法。 论文作者把一条轨迹冻在任务中途，精确恢复当时的世界状态，再单独改历史或单独改世界，交给接收模型继续做。在 AgentCE-Bench 上，Agent 已经写入错误值且该值仍在世界里：一种编辑是在保留原错误的同时，旁边加一条如实说明正确值的笔记；另一种是把该步改写成 Agent 自己已经完成的动作。在 AppWorld 上，一次数据库写入的回执写成成功或失败，再分别搭配「写入效果已存在 / 不存在」。

证据。 论文在固定的错误世界上，如实笔记把剩余目标的恢复率从配对中性笔记的 51% 提到 66%；改成「已完成的动作」则把恢复率从未经编辑历史的 50% 降到 44%。正确值本身并不能预测效果。在 AppWorld 上，成功回执在效果尚未出现时，把整题成功率从 45% 降到 28%；效果一旦存在，又从 38% 升到 49%。两种效应合计相差 27 个百分点（两名接收者合并；八名接收者里六个在 97.5% 水平、七个在 95% 水平上方向为正）。

局限。 干预发生在冻结的中途交接，不是在线压缩器自己持续改写；基准是 AgentCE-Bench 与 AppWorld，未必覆盖所有工具环境。

短评。 评论这和本周 CoReMem「按下一题代价估值」是同一问题的另一面：记忆或历史编辑如果只追求看起来干净，而不核对世界里是否还留着错误，会把接收者带偏。可用的区分很具体——旁注说明对，伪装成已完成的动作有害。

是否值得读原文 · 值得。先读两组实验设计和上述数字，约 10 分钟。

第 02 节

RSI（自我迭代 / 人参与的迭代）

一篇把「政策知识」和「执行可靠性」拆开、并且不用更强教师的共进化实验，正好接上本周 Continual-ARC 的讨论。

知识放进 harness，可靠性写进权重；12B 模型可以只靠自己的部署日志同时改这两层

Brightendata · arXiv · 2026-11-13 · 原文 论文约 30 分钟（方法、门控规则与 2×2 消融最有用）

问题。 论文适合私有部署的小开源模型，在客服这类要严格遵守书面政策的长对话里，通常同时有两个缺口：该用哪条政策时想不起来，以及已经知道的规则执行得不稳定。许多系统会请更强的模型来改 harness，或只训练权重；作者问的是：一个 12B 模型能否只靠自己的部署日志和参考结果，同时改这两层，并且增益能迁移到从未进入训练环的官方题。

方法。 论文起点是 Gemma 4 12B，政策不写进系统提示，而放在按需加载的 skills 里。每一轮先在一批新任务上部署；基座模型诊断失败对话并写成规则，一条规则必须通过代码检查、反例自审、成对复测，以及按噪声校准的验证门，才能留下。随后用 GRPO 在完整的多轮、带工具对话上训练 LoRA。官方题只用于汇报，不参与训练或筛选。

证据。 论文在 τ²-bench 的零售和航空域上，两轮之后相对起点：pass@1 分别提高 12.5 和 19.5 分，pass@4 分别提高 18.4 和 22.0 分。它还超过了「同一模型、把全部政策放进系统提示」的基准 Agent：pass@1 高 11.8 和 8.0 分，pass@4 高 22.8 和 16.0 分，并在同一协议下缩小了与三个前沿模型的大部分差距。2×2 消融显示：规则能救回模型从未解出的题，而且这些政策知识不会被「规则在上下文里、再做 RL」内化进权重；训练过的权重则让已经能解的题变得更稳。

局限。 领域是两个客服基准，不是通用编码或开放网页；教师自由环仍然依赖带参考结果的日志，不是完全无监督。规则与权重的分工是否在其他政策密集型任务上同样清楚，还有待验证。

短评。 评论和 Continual-ARC「现成 harness 几乎不从经验里学、训练权重才有泛化」可以对上：这里给出一种可操作的拆分——新政策先作为可检查的规则留下，执行的稳定性再交给权重。同日 MultiLoop（Google Research，arXiv:2611.15754）则提醒：用编码 Agent 自动改多 Agent harness，在 DeepSearchQA 上用 10 条训练样本把准确率提高 4.6 个百分点，但编排类失败大多还在。

是否值得读原文 · 关心 harness 与权重如何分工的，读方法与消融即可，约 15 分钟。

Knowledge in the Harness, Reliability in the Weights: Teacher-Free Co-Evolution of an LLM Agent (arxiv.org) 代码与记录 (github.com)

第 03 节

各领域模型能力进展

Google 把一批「人出题、多 Agent 探索、独立证伪器把关」的科学与工程结果写出来，并宣布把这些工具向外开放。

/teamwork：并行探索加独立证伪，用来做长证明、形式化和实验室级结构解析

Vahab Mirrokni / Google Research · 2026-11-13 · 原文 博客约 15 分钟

做法。 官方作者把 /teamwork 的设计归结为两点：单次生成不稳定，所以并行探索，并配上 Lean 4、未改动的测试套件、模拟器、检索或硬件计数器等独立证伪器；多日任务里上下文会发散，所以按步骤切分上下文，协调者把任务交给新的后继 Agent，评审在干净上下文里质疑。工作流写成「声明式、可自我改进的自然语言模式」，并按提示路由到不同 harness。官方写明：这些工作都与人类专家合作，相关工具正在 Antigravity 的 /teamwork（以及 /boost 等）向外开放，后续几周还会补齐更多能力。

数学与形式化。 官方Google、港中文、南加州大学和卡内基梅隆的研究者用 Long Proof 模式证明并 Lean 形式化了 2013 年的 Courtade–Kumar 猜想：先由模型找到对一篇旧推广的反例，再由港中文团队提出新的候选函数，把问题化成 14 变量优化并给出关键下界；Gemini 4 Argon 与更早的 Gemini 划分参数空间、写出大部分新的分析界和区间算术证书，并在无人工介入的情况下把证明从平衡函数扩到非平衡函数。完整形式化「producing 50 million lines of code」。/teamwork-LEAP 还「fully autonomously」写出 Weil 猜想的端到端机器可检查形式化，约 180 万行 Lean、经 28,800 次子 Agent 调用；并写出超过 91.9 万行 Lean，形式化一般整数环上 Hilbert 第十问题的一份近期证明。文中还提到对带光滑外力的三维 Navier–Stokes 有限时间爆破、Birkhoff 猜想，以及三维 Bochner–Riesz 猜想的首次形式化，后者还修了近期非正式证明中的缺口。

评阅与化学。 官方STOC 2027 有 578 篇投稿（超过三分之一）选择接受 Deep Review；正在进行的作者调查 N=70，90% 认为反馈大多或几乎全部属实，90% 愿意再用；超过 30% 说它抓住了实质性证明错误或数学上重要的笔误，14% 说发现了需要一小时以上才能修好的技术缺口。分子结构方面，30 个专用 Agent 与物理约束的光谱模拟器组成自校正环，在复杂基准分子上达到 95% 的 top-1 精确匹配和 100% 的 top-3 准确率，「nearly doubling single-agent performance」。

局限。 这是官方结果汇总，不是独立复现；「50 million lines」是形式化体量，不自动等于证明更短或更可读；Weil、Hilbert 第十问题和 Navier–Stokes 条目写的是对已有证明的形式化或再现，不要读成今天新解决了这些公开问题。Deep Review 的 90% / 30% 来自仍在进行、样本为 70 的自愿调查。

短评。 评论方法上真正可迁移的，是「独立证伪器 + 按步切分上下文 + 人类确认定理陈述」这一套，而不是把某一条形式化行数单独当成能力分数。

是否值得读原文 · 值得浏览数学与化学两节，约 10 分钟；具体证明仍应回到各领域论文。

第 04 节

世界模型 / 具身

驾驶世界模型常被拿来比较候选计划，但现有指标往往只检查相机有没有跟上命令。同周末，World Labs 把下一代世界模型 Atlas 对所有人开放。

驾驶世界模型带动了相机，却几乎没有带动场景；计划应以几何而不是 token 进入模型

重庆大学 · arXiv · 2026-11-13 · 原文 论文约 25 分钟（问题设定、场景响应 α 与 ReTime-Compose 最有用）

问题。 论文计划条件下的驾驶世界模型，本应用来回答「如果在这里减速，前方会怎样」。可是常用控制指标只从生成视频里还原自车轨迹，再和命令比较，并不检查场景是否也按该计划变化。作者指出：未被实际驶过的计划，其真实结果其实已经记录在数据里——把日志按时间重采样，可以得到其他速度下同一位姿的图像和 LiDAR；立体相机则在同一时刻记下横向偏移后的视图。

方法与证据。 论文他们用场景响应 α 衡量：预测里静态场景点的距离变化，占真实变化的多少。已发布模型在速度计划下最多只达到真实视频约三分之一的响应；在 0.54 米横向偏移下，最多只达到真实图像运动的约四分之一。以半速计划为例，Epona 生成的相机轨迹长度是计划路径的 1.18 倍，但前方场景距离的变化只有真实视频的约四分之一，像是场景跟着相机一起走。现有尺度对齐 ADE 甚至会更偏好「忽略速度命令」的真实视频，因为它把速度差缩放到消失。干预实验把失败定位到计划通道：预测几何主要由上下文帧决定，一旦帧里已经带上计划几何，计划 token 几乎加不了什么。据此提出无需训练的 ReTime-Compose：把一次已记录速度的生成结果搬到计划相机位姿，再让冻结生成器只补没有被任何帧覆盖的区域。冻结模型随后在 KITTI、nuScenes 和 Argoverse 2 上，对 0.54 米横向偏移的跟随接近真实场景，并在三个生成器的减速计划和两个生成器的加速计划上，响应强于重新采样。

局限。 参照来自重定时日志和立体基线，不是任意新路径的真实重驶；ReTime-Compose 依赖已有一次滚动生成，对完全新颖的几何仍要靠生成器补全。

短评。 评论如果世界模型只是让画面里的相机按计划移动、场景却像黏在镜头上，它就不该被用来比较计划。同日同济大学的 AFTER-WM（arXiv:2611.15215）处理的是另一类失配：机器人动力学突然且持续改变时，预测误差要同时做到快响应、不被瞬时扰动带跑、并在开环滚动中把适应留下来；其多步误差比最强对照低 16%–34%。

是否值得读原文 · 做世界模型或规划对照的值得读 α 的定义和 ReTime-Compose，约 12 分钟。

Driving World Models Move the Camera, Not the Scene (arxiv.org)

Atlas 对所有人开放：一张图或最多 64 张输入生成空间一致的世界，并可导出关键帧、视频或 Gaussian splats

World Labs · 页面未单独标注日期 · 2026-11-13 02:09（Asia/Shanghai） · 原文 产品页约 8 分钟；官方线程约 5 分钟

产品。 官方World Labs 宣布「opening up access to Atlas to everyone」。产品页提供两组 Web 应用和面向开发者、Agent 的 API。Viewfinder 用 Atlas 的空间智能从图像创建世界：可以从单张图生成整个世界，也可以用最多 64 张输入重建真实环境，并导出空间一致的图像、视频或 3D Gaussian splats。Chisel 面向「创建显式 3D 几何」的 agentic 工作流：可用文本或参考图建世界，再渲染图像和视频，或导出 splats，并尝试不同视觉风格。页面还列出 Splats to Mesh、Relight，以及 API 与 Blender 接口。官方同时开放支撑这些应用的全部 API 端点，「Build your own tools incorporating Atlas, or even directly use your agent to interact with our models」。

短评。 评论它把「先得到可编辑的三维世界，再导出一致的关键帧或视频」做成可直接上手的产品，和同周末 WorldDraft、Driving World Models 追问的问题是同一条线：几何要先进入工作流，而不是只靠生成器自己补。

第 05 节

AIGC 视频生成

与周五 BWM-Forge 同一波 arXiv、当时未写入的一篇基准：如果代码已经建好 4D 世界，视频模型能不能只负责渲染。

WorldDraft：草稿越细，结构更稳，外观却更容易崩；冲突线索会造成严重的源泄漏

南方科技大学 / 香港科技大学等 · arXiv（与 11 月 12 日 BWM-Forge 编号相邻，周末补记） · 原文 论文约 30 分钟（基准设计、三项发现与表 2 最有用）

问题。 论文多模态编码 Agent 已经能把场景布局、物体轨迹和物理交互写成可执行仿真草稿，再交给视频模型做外观。这时视频模型的角色从「生成世界」变成「生成渲染」。可靠的生成渲染要同时做到两件事：保住草稿规定的几何、运动、事件和相机路径（world preservation）；以及把文本指定的外观属性在运动、遮挡和视角变化中持续绑在对应实体上（visual realization）。现有视频到视频基准只覆盖了其中一部分。

方法。 论文WorldDraft 提供 432 组严格配对的测试，覆盖 48 个可执行 4D 世界家族、六类动态挑战。实验是 3×3 因子设计：在同一套动力学下，正交交叉草稿细度（从抽象代理到预演）和外观对齐（从中性到冲突）。作者在 12 个有代表性的视频模型上评测，并给出即插即用的视觉提示方法 WorldDraft-Primer。

证据。 论文三项主要观察：（I）世界保真与外观实现仍处于明显的操作张力中；（II）更细的草稿能锚定结构，却反而损害外观保真；（III）冲突的源线索会引发严重的源泄漏（最高达 64%；文中举 Wan2.1-VACE 为 64.17%），说明跨模态解耦仍然脆弱。WorldDraft-Primer 在冻结的视频渲染器上同时改善了这两个目标：论文表 2OmniWeaving 的 Overall 从 57.62 升到 60.13（+2.51），其中 Preservation +2.99、Realization +4.56，泄漏从 50.97 降到 47.55（−3.42）；MiniMax-H3 的 Overall 从 63.63 升到 65.56（+1.93），Realization 从 76.38 升到 80.21（+3.83）。

局限。 这是生成渲染基准，不是端到端拍片管线评测；冲突外观是受控实验条件；Primer 的升幅在不同模型上并不一样大。论文与周五已报的 BWM-Forge 属于同一波提交，本条是补记，不是新的一周起点。

短评。 评论它把「先用代码规定空间，再让视频模型渲染」写成可打分的问题，并且明确警告：草稿加得越满，并不自动等于外观更好。

终止滞后：成功轨迹里，38%–82% 在第一次改源代码时就已经做对，但之后仍会消耗大量步骤

宾夕法尼亚州立大学 · arXiv · 2026-11-13 · 原文 论文约 20 分钟（定义与主要统计最有用）

问题。 论文SWE-bench 一类评测只看最终提交的补丁，这会把「何时首次做对」和「是否知道该停」混在一起。两个 Agent 可以在第 10 步写出同一份正确补丁，一个立刻提交，另一个再跑 40 步去复测、检查调用点和审 diff，得分却相同；有的轨迹还会在已经正确之后把补丁改坏。

方法。 论文作者记录每一步后的仓库补丁，并在离线状态下用 Agent 从未见过的官方测试来判定对错，从而定义首次正确补丁时间（TTFCP）和之后的终止滞后（termination lag）。核心评测覆盖 Qwen3-Coder 与 Laguna-XS.2，以及 SWE-bench Verified 与 Multilingual，并在五个模型、两套 Agent 框架、三个数据集上做推广。

证据。 论文成功轨迹中，38%–82% 在第一次改源代码时就得到正确解。但 Agent 仍继续工作：在 Verified 与 Multilingual 的成功轨迹里，解出之后的步骤中位数，Qwen3-Coder 为 35%–37%，Laguna-XS.2 为 54%–60%。这些步骤主要用于验证和探索仓库。有 1%–8% 的情况，后续修改会撤销先前的正确补丁，使最终提交变为错误。

局限。 离线用官方测试来标记「首次正确」，Agent 自己并不能看到这些测试；「该不该停」因此仍取决于它能收集到的证据。结果依赖所测模型与框架，不能直接外推到所有产品 Agent。

短评。 评论对日常编码 Agent 的启示很具体：把「验证」预算显式关掉或设上限，可能比一味加长轨迹更省；同时也要防备验证不足导致的过早提交，以及验证过度导致的回退。

一直在线不是一直醒着：用收件箱、定时器、记忆、权限和发件箱把多次 run 串起来

William Hu / Anthropic · 官方未标注日期，第三方报道为 2026-11-13 · 原文 指南约 12 分钟

做法。 官方「一直在线」是用户体验，实现上 Agent 大部分时间在睡：被事件叫醒后跑一次 run，写入状态再睡。周围架构由五个原语组成。事件收件箱是耐用事件表，由快速确认的 handler 写入、由 worker 取出；建议每个收件箱同一时刻只有一个在职工人，并把连续多条消息批成一次 run，避免并发 run 互相覆盖。定时器分 follow-up 和 schedule，单独存放，由调度器到期后写入收件箱，而不是自己直接开跑。记忆要有独立存储，用来在多次不相连的 run 之间保持连续性。权限把凭证放在环境之外；发件箱则在需要控制节奏或做错误恢复时，再从普通 send 工具升级成正式队列。新 session 只带系统提示、工具定义、记忆和触发事件；过长则压缩或新开 session，必须留下的先写入记忆。

证据。 官方作为「智能变便宜、长程任务受益最大」的例子，文中写：在一个长程编码基准上，Opus 5.5 每个解出任务的成本比 Opus 5 低 78%，而在典型工作负载上低 40%。文中未给出该基准名称和设置。

局限。 这是架构指南，不是对照实验；官方页面无日期；78% / 40% 缺少可核对的评测说明。文中提到的 dreaming 指向既有记忆文章，不是本次新结果。
