第 01 节

个人 Agent 与记忆/上下文管理

今天两条线：个人 Agent 的"手脚"在哪儿跑（沙箱），以及它的"记忆"怎么读（检索）。

Perplexity 开源 SPACE：给每个 Agent 任务一台一次性小电脑

Perplexity · 2026-10-15（美西） · 原文 README 与架构文档约 15–20 分钟

发生了什么。 个人 Agent 一旦能跑代码、开浏览器、装依赖，就需要一个"弄坏了也无所谓"的地方。Perplexity 把支撑 Perplexity Computer 全部任务的沙箱平台 SPACE（Sandboxed Platform for Agentic Code Execution）以 Apache 2.0 开源。

怎么做的。 官方每个任务一台 Firecracker microVM（轻量虚拟机，有自己的内核和可写文件系统），外层控制平面负责创建、暂停、挂起/恢复、故障恢复和会话分支；应用只通过 HTTP + SSE 调用：从模板建沙箱 → 执行命令 → 流式取输出。关键设计是凭证和出网流量在 VM 外面管——Agent 拿不到平台持有的密钥。实现用 Rust，本地可用 Kind（在 Docker 里跑的 Kubernetes）部署，需要 x86_64 Linux + KVM 和 btrfs。

证据。 官方据 Perplexity 博客，7 月起它替换了原商用沙箱供应商，承载全部 Computer 会话、每天数百万次沙箱创建，同流量下创建速度快 3–5 倍。CEO Aravind Srinivas 在 X 上说：沙箱本身是大路货，难的是在生产流量下同时服务数百万个。

局限。 不能直接在 macOS 上跑；挂起/分支能力绑定其存储栈；安全性目前只有自述，没有第三方审计。

与 Dong 的关系。 和 10-12 期 Muse 的 Secure VM 思路一致（隔离执行 + 凭证外置），但这次有源码可读，是自己搭个人 Agent 执行层的现成参考。

是否值得读原文 · 做 Agent 执行环境的值得读架构文档里凭证与网络的部分；只当用户的话，看本段即可。（Perplexity 博客原文对抓取返回 403，故只链 GitHub。）

MemPursuit：记忆检索别只挑"最像的"，要挑"还缺的"

arXiv:2610.15642 · 香港中文大学（深圳） · 2026-10-11 · 原文 正文约 25 分钟；本摘要约 2 分钟

问题。 问 Agent "奶奶比我大多少岁"，需要两条记忆：奶奶的年龄、我的年龄（32 岁）。标准 Top-K 按相似度独立打分，名额被几条讲"奶奶"的近义记忆占满，"我 32 岁"排第 11 被挤掉，答案算不出来。

方法。 一句话：把查询向量当作要"拼出来"的目标，每选一条记忆就用已选记忆的凸组合重构查询，剩下的残差就是"还没覆盖的信息"，下一条选和残差最对齐的（正交匹配追踪 OMP / Frank-Wolfe 的思路搬到记忆读取），残差不再下降就自动停。不训练、不调 LLM，只用检索阶段已有的嵌入。

数据与评测。 没有新数据构造：在 LoCoMo、LongMemEval-S、BEAM 上评测，记忆写入用 Mem0-v3，候选池 200 条，嵌入 text-embedding-3-small。

关键数字。 官方LoCoMo 固定预算下 Top-10 准确率 +7.2 个点（多跳题 63.1→75.9）、Top-20 +5.5；只用 20 条记忆就达 85.1%，超过混合检索用 50 条；接到其他记忆框架上 Top-10 提升 +2.47 到 +9.29；选择延迟中位数 8.67ms，约为 BGE-v2-m3 重排的 1/33，拿到后者约 73% 的增益。

局限。 完全依赖嵌入空间几何，无法推理记忆之间的逻辑关系；作答和打分都靠 LLM。

短评。 方法很朴素，本质是更讲道理的去冗余（类似 MMR），数学工具很老。真正的提醒是：记忆系统的瓶颈常在"读"而不在"存"，Top-K 独立打分天然浪费名额。同期 Cortex（10-14）走另一极端：把上下文带来的收益合并进低秩/FFN 权重更新，14B 模型连续 50 次编辑后保留 88.9% 收益、99.8% 原有能力。

是否值得读原文 · 不必精读；自己做记忆检索的，直接试代码替换 Top-K，看主结果表即可。

Sakana「The Agentic Scientist」：把 Codex / Claude Code 编排成带评分标准的研究流水线

Sakana AI · 2026-10-15 · 原文 博文约 12 分钟；论文较长

问题。 直接把研究题丢给编码 Agent，常常得到一个"超参数优化器"：分数涨了，但想法很窄，也没人解释为什么涨。

方法。 一句话：第三代 AI Scientist 不再自己写代码，而是把现成编码 Agent（Codex、Claude Code、OpenCode、Pi 等）包进流水线：起草任务 → 并行验证假设 → 选最优程序 → 自动跑基线与消融 → 事后分析 → 写 LaTeX 论文并审计。任务怎么定义（最值得学的部分）。 每个任务是一份可执行的任务说明 + 脚本化评估器；提假设的 Agent 要在实验之前写下评分 rubric（实验必须证明什么），执行 Agent 才去改程序跑分。并行 worker 通过共享记忆交换成败，定期重置上下文并交接，避免对话无限变长；写作阶段生成"证据地图"，把每条论断链到日志和代码，再由独立审计查过度宣称。

证据。 官方人机合作的 Error Diffusion 论文被 ALIFE 2026 接收为口头报告（人定方向和 rubric，并核对全部结果与引用）；全自动运行把 Doc-to-LoRA 多针检索精确匹配从 52% 提到 98%（只在合成任务上）。5 个任务 × 14 个"模型 + harness"组合共 70 次运行显示：底座模型的影响大于 harness。

局限。 作者坦承早期出现过分数高但违反学习规则的"奖励投机"方案，是人发现后才收紧 rubric；文献检索只在写作阶段做；除 ALIFE 那篇外，论文质量只用 AI 审稿人打分（与实际效果相关性 r=0.44）；任务全是计算型 ML。

与 Dong 的关系。 这是"人参与的迭代"的样板：人定问题与证据标准，Agent 放大实验量。可以直接借鉴"先写 rubric 再跑实验"和"证据地图"两个做法。

是否值得读原文 · 值得读博文的经验总结和工作流图；论文按需。

Anthropic 让 METR 六人团队以"员工级"权限驻场评估

Anthropic · 2026-10-15 · 原文 约 6 分钟

发生了什么。 官方Anthropic 给非营利评估机构 METR 的 6 名员工配公司电脑、办公位，以及大致和自家风险评估团队同等的内部工具与系统权限。METR 将独立发布对 Anthropic 风险、事故与做法的评估，Anthropic 不能否决发布，只能在事先划定的少数类别（客户数据、律师-客户特权信息、模型架构）里要求删改，而且 METR 可以公开评价这些删改。

TheoPhysEval：GPT-6 Astra 在 50 道未发表的理论物理研究题上答对 49 道

arXiv:2610.16733 · ICTS、TIFR、Duke、Kavli IPMU 等 · 2026-10-09 提交，10-14/15 讨论升温 · 原文 正文约 30 分钟，附录 50 道题可挑着看；本摘要约 2 分钟

问题。 现有物理基准多是竞赛/课程题，答案可能早已在网上。作者想测的是：一道"本领域专家约一天能做完"的真实研究计算，Agent 能否在无人提示下独立做对？数据怎么造（本文最值得学的部分）。 向各方向专家征题，三条硬标准：和当前研究相关；答案容易验证但很难猜；文献里查不到。最常见的造法是"改参数"——拿出题人自己近期论文里的一段计算，换维度或参数，得到答案全新、但必须先找到原论文、读懂并重做整套推导才能解的题。属于"摇曲柄"式的常规研究计算，不是突破。为避免用 LLM 当裁判，所有符号答案都代入给定数值（同时给出相关和无关的物理量）变成难猜的数字再判分；题目也不做对抗筛选，不因 AI 能解就删题。

评测。 Harbor 框架（Terminal-Bench 同款），两条赛道：可上网的"现实赛道"和断网的"隔离赛道"；每题限时 8 小时，每个 Agent 只跑一遍。

关键数字。 官方现实赛道 GPT-6 Astra + Codex 49/50（98%），平均每题成本不到 3 美元；Opus 5.5 + Claude Code 46；Gemini 3.8 Flash + Antigravity 34；DeepSeek-V4.1-Flash 27；GLM 5.3 21。隔离赛道 Astra 和 Opus 都是 46——断网几乎不掉分，作者认为前沿模型已经"记住"了大量理论物理文献。

局限。 只判最终答案、不看推导；单次运行有采样波动；部分出题人自己用过 AI，不能排除泄漏；两道题约定写得不清。

短评。 这测的是"把已知技术准确推广一步"，不是"提出新物理"；作者也指出 Agent 还不会在题太难时主动换个同样有意义的方向。作者的结论很直白：这类题已不适合当新研究生的入门课题。真正可复用的是造题法——从自己论文里改参数 + 数值化判分，任何领域都能低成本搭防泄漏的私有基准。

是否值得读原文 · 值得读造题与判分两节，并在附录挑 2–3 道题感受难度；结果看本摘要足够。

第 04 节

世界模型 / 具身

Matrix-Game 4.0：规则交给游戏引擎，画面交给视频模型，单张 RTX 5090 实时运行

昆仑万维 Skywork AI · 2026-10-15 · 权重 Hugging Face · 原文 项目页约 10 分钟（有可拖动的生成/低模对比视频）

问题。 纯视频世界模型靠逐帧外推像素来"记住"世界：东西离开视野就没了，规则要从每一帧重新推断，玩久了会漂移。

方法。 一句话：给视频模型套一层 harness 持有世界状态。官方游戏引擎按规则演化状态并画出廉价的低多边形代理画面；Coding Agent 把玩家的新要求写成规则注册进引擎，并读引擎状态写出动态提示词；少步因果视频模型只负责把每一块（4 帧）"渲染"成成品画面，靠参考帧锁外观、按相机位姿检索空间记忆。

训练简述。 据综述底座是 Wan2.2 5B Fun Control 改成的视频到视频模型（30 层因果 DiT）；训练数据是在 Unreal Engine 5 里成对渲染的"结构帧 ↔ 精细画面"，覆盖城市、沙漠、城堡、空战等场景；再蒸馏到 1–2 步去噪，并用 FP8 与滚动 KV 缓存提速。

关键数字。 据综述480p、60 FPS，按键到画面约 112ms，单卡峰值显存约 18.5 GiB；开源代码、权重和资产，附中世纪城堡、古埃及、城市赛车等可玩 demo。综述拿它和英伟达 StreamRender-H3（8×GB200、约 545ms）对比，但分辨率与测量口径不同，不宜直接排名。

局限。 480p；物理与规则仍靠手写引擎，换新游戏类型要新代码和新数据。

短评。 这是对"世界模型"一词的务实降级：把最难的一致性问题还给确定性程序，神经网络只做渲染。同期港大与腾讯 ARC 的 Multics（10-12）思路相近：多人共享世界里用"玩家→组→全局"分层通信替代全连接，10 人时自注意力算力 9.6 vs 69.1 TFLOPs。

是否值得读原文 · 做互动生成或游戏 AI 的值得跑 demo；关心"真正学物理的世界模型"的，看本段即可。

Google Deep Review 公开：把长技术文档拆段并行"审稿"

Google Research · 2026-10-14 · 原文 约 8 分钟

发生了什么。 官方Google 把内部审稿 Agent（原名 Paper Assistant Tool）公开为 Deep Review。它此前在 STOC 2026、ICML 2026、NeurIPS 2026、ICLR 2027 为 1.6 万多份自愿参与的投稿做过投稿前反馈。

怎么做的。 四步：分段 Agent 把文档切成逻辑段 → 按信息密度分配算力（证明多的段给更多推理预算）→ 各段并行核查（每个 Agent 能看全文，但只负责一段）→ 汇总 Agent 做跨段一致性检查和外部事实核验。

怎么用。 每人每周免费 2 次，填 Gemini API key 可提额度并调用 API；目前支持 PDF 和纯文本，多文件即将支持；上传文档不用于训练、保存一年。Antigravity 里也有同样思路的 /teamwork-preview 多 Agent 审阅模式。

与 Dong 的关系。 建议可以当作写完设计文档或长文后的"第二双眼睛"，专查数字和前后矛盾；它的结构本身也是自己写审阅 Agent 的好模板：分段 + 按密度分预算 + 全文可见但职责单一 + 最后统一核对。

Meta 发布 Muse Spark Open：816B 开放权重，两台 Mac Studio 能跑

Meta Superintelligence Labs · 2026-10-15（美西，北京时间 16 日凌晨） · 原文 博文约 4 分钟，模型卡约 10 分钟

发生了什么。 官方Meta 放出 Muse Spark 的开放权重版：MoE，总参 816B、每 token 激活 42B（256 个专家选 8），1M 上下文，输入文本/图像/视频/音频，输出文本。BF16 约 1.65TB（8×B300），NVFP4 约 537GB（4×B300），也能用 MLX 跑在两台 M5 Ultra Mac Studio 上；Baseten、Fireworks、Groq、Together、OpenRouter 等首日上线。

分数。 官方模型卡，xhigh 档MCP-Atlas 89.2（同表最高）、OSWorld Verified 80.4、Terminal-Bench 2.1 76.4、DeepSWE 1.1 60、GPQA 89.0、HLE（带工具）61.0。同一张表里，编码/终端类明显落后于 GLM 5.3 和 Kimi K3（Terminal-Bench 83.9 / 85.0）。第三方Artificial Analysis 给出智能指数 39：美国开放权重第一（第二是 NVIDIA Nemotron 3.5 Super VL 的 26），离 Meta 自家闭源的 Muse Spark 1.2（40）只差 1 分；每任务输出约 4 万 token，是前九名开放模型里最省的；但四项 agentic 评测在前九名开放模型中垫底。

许可。 Muse Model License：须标注 "Built with Muse Spark Open"；年收入超 2,000 万美元的"模型即服务"业务需另签协议。

与 Dong 的关系。 推测想在本地跑隐私敏感的个人 Agent，这是第一个能放在桌面设备（两台高配 Mac Studio，成本不低）上的 Meta 前沿级模型；但长程编码 Agent 目前还是 GLM / Kimi 更强。
