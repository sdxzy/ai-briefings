第 01 节

个人 Agent 与记忆/上下文管理

Anthropic Message Threads：长会话只传增量，中位 TTFT 约降 35%

Anthropic · 约 2026-11-03 · Nov 2 · 原文 约 5–8 分钟

发生了什么。 官方Messages API 公开 beta message threads：首次请求带完整对话并 "thread": {"type":"create"}，之后只传新增消息 + 上一轮 response id（"type":"continue"）。服务端把对话、system、tools 暂存在加密内存（不落盘），多数 Claude Code 用户默认开启。官方称：对 500k–1M token 的 Claude Code 请求，中位 time-to-first-token（TTFT）约降 35%。Beta header：message-threads-2026-08-12；可用面含 Claude API、AWS、Google Cloud（Anthropic managed）、Microsoft Foundry。

不是什么。 官方token 用量与计费不变——模型每轮仍读完整上下文；与 Prompt Caching 正交，可叠加。线程 空闲约 5 分钟过期，最迟约 1 小时删除；过期后需整段重放（SDK helper 可自动）。append-only；不支持在活跃线程里改早期消息或某些 on-demand compaction。不适用于 Zero Data Retention / HIPAA。

评论这是「上下文传输与预处理」层的优化，不是新记忆算法：价值在长 coding / computer-use / 多模态 Agent 循环里砍掉重复上传。5 分钟 TTL 对「泡杯咖啡再回来」不友好，本地仍要自己存一份可重放历史。

是否值得读原文 · 用 Claude Code / 自建长 Agent 则值得，约 5 分钟扫产品文 + 文档限制即可。

第 02 节

RSI（自我迭代 / 人参与的迭代）

FlashProve：用 zkSNARK 证明「这串 token 来自已承诺的那份权重」

Anthropic Frontier Red Team · 2026-11-02（X 官宣约 11-03） · 原文 约 25–40 分钟（博文 + 技术报告）

问题。 官方用户、评测方、监管方今天几乎无法确认：返回的 token 是否真的来自声称的那套权重——路由可偷换成便宜模型，攻击者可篡改流；更进一步，官方自述场景里「更强模型冒充较弱模型以躲开监控」也会出现同类问题。Anthropic 将其挂在 Frontier Safety Roadmap 的 inference verification / provable inference 目标下（另有一套基于签名 + 可信侧重算的原型已另线交付）。

怎么做的 / 证据。 官方开源原型 FlashProve（Apache 2.0：证明器、C++/Lean 验证器、顶层 Lean 安全陈述、协议说明）。在 Llama 4 Maverick（约 400B MoE，公开 4-bit 权重）、单卡 H100 上：约 110 tokens/s 出证明，每 1,024-token 窗口证明约 19 MB；相对同模型 vLLM 推理约 70–95× GPU 时间。离线承诺约 39 分钟；验证端 CPU 约十几秒级。证明隐藏权重与专家选择，不隐藏架构；当前证明的是整数化 + greedy 解码、上下文上限约 1,024 tokens。作者强调 Claude 协助优化 zk 结构，并用 Lean 钉住 completeness / soundness / zero-knowledge 陈述以对抗「大系统难审」。

评论对 RSI 叙事的意义不在「模型自我改权重」，而在谁在跑、跑的是不是承诺过的那份：自改进闭环一旦能替换服务端权重，没有可验证推理收据就只剩信任。代价仍约两个数量级、上下文短、后验证明——是路线图里程碑，不是上线产品开关。

是否值得读原文 · 关心安全 / 监管 / 多租户路由诚信则值得；先读 Executive summary + Limitations，约 15 分钟。

各领域模型能力进展

OpenAI：Astra / Codex 进物理工程——CAD、PCB、仿真与行业试点

OpenAI · 2026-11-03 · 原文 约 8–12 分钟

发生了什么。 官方展示 frontier 模型在机械 / 电气 / 端到端系统设计上的进展：内部硬件与基础设施团队用 Codex / ChatGPT 做 CAD、出图、仿真与设计评审；自 2 月起硬件侧 token 用量约 增长 23 倍。侧项目：两名成员用 GPT-6 Astra 在约一周内无人工直接改稿地设计了一台对接 Codex 的对话设备（外观、外壳、PCB、固件/UI），代工厂约一个月出小批量样机——但量产仍需多轮人工审：Astra 经常未吃透公差、装配与产线约束。

评测与合作。 官方内部 BenchCAD 2.0（重建 3D 零件/装配、识别电路板连接）上，一款更新内部模型均分 0.875，对照 GPT-6 Astra 最高推理档 0.594。对外：扩大与 Chip Ganassi Racing 的合作（3D 扫描 → 可编辑 CAD / 2D 出图）；新建与 Mazda 气动 / 碰撞安全侧的研究合作（鼻锥等形状探索 + 仿真）。公开征集工程公司与软件厂商协作。

评论「会写代码」延伸到「会碰 CAD/ECAD」是能力面扩张；官方自己把制造闭环的缺口写得很清楚。BenchCAD 数字是内部榜，跨厂商对比尚缺第三方复现。

是否值得读原文 · 做硬件 Agent / 物理世界落地则值得，约 10 分钟；只关心数字扫 BenchCAD 与合作两段即可。

第 04 节

世界模型 / 具身

AgiWorld：Agent 规划 + 视频世界模型闭环，从一句话建可重访世界

UT Austin / Adobe Research · arXiv 2026-11-02 · 原文 约 30–45 分钟（论文）

问题。 论文现有交互式视频世界模型多半要用户逐步给相机轨迹与局部提示；高层意图难落地，长程探索时世界也难保持持久（重访不一致、语义漂移）。

怎么做的 / 证据。 论文AgiWorld-Agent（实验用 GPT-6 Astra）维护含「已确认 / 仅想象」元素的世界状态，把下一程写成度量相机轨迹 + 结构化 caption；AgiWorld-WM（基于 Wan2.2，自 LingBot-World 初始化）按约 5 秒一块自回归生成，并把帧与深度写入点云空间记忆。针对遮挡与几何误差提出 occlusion-aware history selection 与 reliability-based memory maintenance。在自建 World Explore 与 DL3DV-Evaluation 上，作者报告整体领先：如 DL3DV FID 21.74（对照 Lyra 2.0 25.54），World Explore FID 35.37（对照 42.73），World Explore 平移误差约 1.05 m（对照最强基线约 1.32 m）。定性展示分钟级、自由指令旅程；项目页有视频，未见公开权重 / 可运行代码。

评论和 Dong 关心的白膜 / 镜头预演同构：贵的是真渲染试次，便宜的是「状态里筛路线」。持久性被明确写成「不单靠视频模型，而靠 Agent 闭环」——比堆更长上下文更接近可工程化叙事。数字为作者自测且含自建榜，宜论文自述读。

是否值得读原文 · 世界模型 / 短剧空间一致性读者值得，先读 §1–2 与 Table 1，约 20 分钟。

（交叉）GSExplorer：持久 3DGS 世界状态 + 生成–重建环

HKUST(GZ) 等 · arXiv 约 2026-11-01 · 原文 约 25–35 分钟
