第 01 节

个人 Agent 与记忆/上下文管理

MemoryTax：模型够强时，"自己翻原始记录"打败专门设计的记忆系统

arXiv · 2026-10-22 · 原文 约 15 分钟（短实证研究）

问题。 Mem0、Zep 这类记忆系统在问题到来之前就决定记什么；Claude Code、Codex 这类编码 Agent 则保留原始历史，让模型用 grep 等工具自己找。模型变强以后，前者还有必要吗？

怎么做的。 论文只用一段 LoCoMo 对话（419 轮、152 个问题），比较 4 种记忆方法（全文塞上下文、BM25、Mem0、Zep）和 3 个编码 Agent（Pi、Codex、Claude Code），各配 GPT-4o-mini、GPT-6 Luna、Claude Opus 5.5，记录每次运行的花费。

结果。 论文三条：① Mem0 只在 GPT-4o-mini 上赢过全文上下文，且光是建记忆库的花费就超过一次全文运行——作者称之为"给弱模型打的昂贵补丁"；② 记忆有天花板，由"写记忆的模型"决定，换更强的模型去读，也补不回弱模型当初漏记的内容；③ 用 Opus 5.5 时，Pi 在成本-准确率前沿上排第一，99% 正确、花费不到全文上下文的一半，唯一一题错是标准答案本身有误。

局限。 一段对话、每格只跑一次；Pi 的领先部分来自只有 Agent 能读到的照片说明，在 88 个证据不含照片的问题上，Pi 和全文上下文只差一题。

是否值得读原文 · 值得，篇幅短。做个人 Agent 记忆的看"writer ceiling"那节，结论和昨天简报里 FrontierMemory"记忆要用下游表现衡量"的思路一致。

MemoryTax: The Bitter Lesson of Agent Memory (arxiv.org)

记忆注入：一次提示注入，在 ChatGPT、Claude、Gemini 的新会话里一直生效

arXiv · 2026-10-22 · 原文 约 30 分钟

问题。 传统聊天机器人被注入后，影响只限于当前会话；有了跨会话记忆，恶意指令可以写进记忆，之后每次新对话都带着。

结果。 论文在 ChatGPT Instant 5.3、Claude Sonnet 4.6、Gemini 3 Flash 上，NIST 定义的各类攻击目标合起来都能实现；入口包括个人记忆、Projects、Skills、组织级指令和通过 MCP 接入的资源。三家都能被操纵去持续散布错误信息、生成有害内容，或在新会话里假装"离线无响应"。Claude 的组织共享记忆可以让攻击者一次影响同组织多名用户，并外带用户提示词。作者按威胁模型推出一组防御措施，称其中近一半三家都还没实现。

同日。 论文PerMIT 只信任用户亲手输入和经过"闸门"确认的内容：来自环境的记忆值必须经闸门确认才能触发敏感动作，这一性质在 Lean 4 里做了机器证明；在 Trojan Hippo 记忆投毒测试上未观察到攻击成功。代价是每条外部记忆都要有人或验证模型点一次头。

是否值得读原文 · 给个人 Agent 接记忆、Skills 或 MCP 的，看威胁模型和防御清单两节。

第 02 节

RSI（自我迭代 / 人参与的迭代）

METR 与 Redwood 驻场三周，红队测试 OpenAI 内部 Agent 监控：最大的问题是"有些流量根本没被看到"

METR · 2026-10-22 · 原文 约 12 分钟

发生了什么。 官方2026 年 7 月 21 日至 8 月 11 日，METR 与 Redwood 各一人在 OpenAI 办公室驻场，用 OpenAI 设备访问代码库和监控提示词，访谈约十几名员工，评估 OpenAI 用来监测内部 Agent"错位"行为（谋划、破坏监控、外泄数据、注入等）的系统。私有报告 61 页，公开版只是双方同意发布的一小部分，OpenAI 有权删改。

发现。 第三方

  • 覆盖率：GPT-5.5 及以上模型的内部 Responses API Agent 流量中，约 75–94% 属于"应被监控"范围（内部 Codex 子集 99.2%）；测试开始时 RL 训练运行不在覆盖范围内。
  • 压缩漏洞：5–7 月，约一成量级的 Codex 应监控流量来自未经监控的上下文压缩（compaction），测试期间已修复。
  • 触发时机：监控在 Agent 交还控制权时才运行，Agent 可以把被检查的时间往后拖；另有利用序列化差异的方法，可藏起最近几百个动作。
  • 开关：找到两个客户端可设置的请求头，能让新建的 Agent 不受监控（但设置这一动作本身可能被监控发现）；两个被认为只读的内部工具有简单绕过方法，未验证实际可利用性。
  • 正面：除少数例外，监控看到的轨迹与 Agent 看到的一致；监控出错率低于 0.2%。

后续。 官方OpenAI 称影响生产防护的漏洞已全部修补；METR 表示未核实。报告给出的设计原则包括：按每 N 条消息或每 N 分钟检查，而不是等 Agent 交还控制权；定期把推理日志与监控日志对账；Agent 不应接触监控系统的设计和代码。

是否值得读原文 · 做 Agent 平台或内部 Agent 治理的，值得读全文，尤其是最后的设计原则清单。

自动化研究的两面：Recursive 用"Eureka Machine"造出 Flint；Agent4Sci 显示前沿 Agent 在科学 ML 上只会"工程调参"

Recursive · 2026-10-21（美国时间） · arXiv · 2026-10-22 · 原文 Flint 约 8 分钟；Agent4Sci 约 25 分钟

Flint。 官方Recursive（Richard Socher 创办）开源的本地编码 MoE 模型，总参数 40B、每 token 激活 2.5B，Apache 2.0，称在 50B 以下 MoE 里 SWE-Bench Pro v2、Terminal-Bench 2.1、SWE-Bench Verified 领先，M4 Pro MacBook Pro 上超过 125 token/s。卖点是"小团队加 Agent，不到四个月从零造出"：自动研究系统 Eureka Machine 参与了数据、优化器、训练配方、架构搜索（从 35B/3B 基线搜到 40B/2.5B）、量化（反常规地把输出层量化到 4 bit，再用自蒸馏补回精度，NVFP4 版与 16 bit 差距在 0.7 分内）和 Metal 内核。未证实"AI 造了大部分"的程度没有量化披露，分数均为自测。

Agent4Sci。 论文20 个科学 ML 基准、11 个领域，看 Agent 能把已发表最佳模型推进多少。前沿 Agent 在每个基准上都超过了已发表最佳，Claude Opus 平均相对提升 10.4%，但几乎全来自 ML 工程技巧而非领域洞见。轨迹分析的三种失败：对新颖性判断失准、算力用不满、很快退化成局部参数扫描。加上研究构思、实验管理、定时检查清单三个轻量 skill 后，Opus 升到 20.1%，Codex 从 4.4% 到 8.1%。

对照。 评论两者说的是一件事：当前自动化研究强在大规模搜索和工程优化（Flint 的量化、内核正是这类），离"提出领域新想法"还远。

是否值得读原文 · Flint 读"How we built Flint"一节；Agent4Sci 读失败模式和 skill 设计两节。

第 03 节

各领域模型能力进展

Anthropic：Claude 为 123 个开源库写出机器可检验的"不崩溃"证明，约 1.8 亿行 Rocq

Anthropic Frontier Red Team 与 Theorem · 2026-10-22 · 原文 约 20 分钟

做了什么。 官方把 Google OSS-Fuzz 里开发者写的模糊测试入口，直接变成形式化规格："对任何小于 64 MB 的输入，这个入口编译出的 RISC-V 程序都不会崩溃"（OSS-Fuzz 用 AddressSanitizer 插桩，内存越界即崩溃，所以等价于证明无内存安全错误和断言失败）。Claude 写证明，Rocq 内核检查。几周内完成 123 个库（含 cJSON、simdjson、OpenSSL、zstd）的 239 个入口，共约 1.8 亿行通过检查的 Rocq，典型证明约 60 万行，对应二进制中位长度 1.8 万条 RISC-V 指令。

顺带找到的 bug。 官方证明过程中发现数百个 bug，Claude 自行打补丁后重新证明。不少是模糊测试很难碰到的：一个解压器只在约 20 MB、特定布局输入下才触发的越界写；需要 64 MB 输入和 2 GB 以上内存的图像解码器越界读；重新发现 libexpat 的 CVE-2026-56132。还发现了不会崩溃的逻辑 bug，例如某库"限制可加载文件"的功能并不总是生效。

要信任什么。 官方只需信任 RISC-V 与 Linux 进程的形式化语义、定理陈述和 Rocq 检查器本身；前提是单线程、静态链接、固定内存预算。其他实验：在 x86 二进制上证明 Linux 内核 zlib 符合 RFC 1950；用 Verus 证明 Claude 写的 Rust 版 Python 解释器行为等价，注入的 7 个 bug 有 5 个躲过随机测试，但全部让证明失败。部分证明、语义模型已公开，Theorem 提供开源项目验证计划和配套 Claude skill；会暴露未修补漏洞的证明暂不公开。

局限。 第三方证明的是"不崩溃"，不是功能正确，也不保证会终止；多线程和其他架构还不在范围内。

同日。 论文FrontierCS 2：从 48 篇论文的开源代码里删掉论文贡献，让 Agent 在真实仓库里补回来，覆盖 13 个领域；评测 12 个 Agent，最好的 Opus 5.5 只有 58% 的运行通过，16 道题没有任何一次运行通过。

是否值得读原文 · 值得，"Turning tests into proofs"和"Finding and fixing bugs"两节是核心。

第 04 节

世界模型 / 具身

CADRE：世界模型该用什么样的视频自编码器？摄像机静止和移动时答案相反

arXiv · 2026-10-22 · 原文 约 25 分钟

问题。 交互式世界模型在视频自编码器的潜空间里生成，压缩率决定每帧成本和动作多久才生效；但多数世界模型直接沿用文生视频的自编码器——那是为离线生成设计的，没人在等，而且没有训练代码，换不了压缩率。

怎么做的。 论文做了一族因果扩散表征自编码器 CADRE：冻结的特征上加一个小瓶颈，不同成员只在时空压缩率上不同，共享一个自蒸馏到 1–几步的扩散解码器。在操作和导航两类任务、各两个环境上，用同一个世界模型分别接每个自编码器。

结果。 论文CADRE 占据延迟-质量前沿的大部分，摄像机移动时优势更明显。四条发现：强压缩下扩散解码器比感知回归更清晰；机器人操作中，时间压缩放在自编码器里比放在世界模型里更有效；操作和导航需要相反的压缩——摄像机静止时时间压缩几乎无损，摄像机移动时空间压缩更便宜；静止摄像机下，粗的空间 token 对运动的伤害远大于对画质的伤害。代码、模型和在线 demo 已开放。

补录。 论文10 月 20 日开源的 Ropedia W0（项目页）：第一视角"移动 + 操作"世界模型，用 1 万小时人类第一视角视频和 3 千小时机器人数据训练，相机位姿编码移动、投影骨骼编码手部操作，在 DreamDojo、AgiBot 等 5 个跨形态基准上报告最佳，蒸馏后可实时生成分钟级视频并接 VR。

是否值得读原文 · 做实时世界模型或可控视频的，CADRE 的四条发现值得读；对短剧这类"固定机位 vs 运镜"的取舍也有参考。

第 05 节

AIGC 视频生成

SolarRenderer：白膜、深度、骨骼、线框、分镜草图，4 步渲染成真实视频，因果版 768p 实时

NUS Show Lab 等 · arXiv · 2026-10-22 · 权重 · 代码 · 原文 约 30 分钟

问题。 3D 白膜预演、游戏引擎、仿真能把空间布局和运镜定死，但要变成真实画面，以往要么为每种结构（深度、分割、骨骼）单独训练控制网络，要么需要大量"粗渲染-真实"成对视频。

怎么做的。 论文冻结 MiniMax-H3 33B 参考生视频模型，只加一个控制 LoRA（rank 384）和一个 4 步蒸馏 LoRA。结构视频走模型原生的参考图通道，用逐帧对齐的位置编码，不区分结构类型，只用固定的一句话描述"这是什么结构"。训练数据 13.6 万段逐帧对齐片段（约 243 小时），来自 8 个来源：UE 灰盒场景、CARLA 分割、引擎深度、Blender 白模、UnrealZoo、YouTube 视频估计的 SMPL 人体，以及外观数据。

结果。 论文4 步比 50 步快 12.3 倍（单卡生成一段 158 帧：209 秒对 2,562 秒）；因果版最高 28 FPS 实时生成 768p。自建 208 个测试样例、16 种结构，其中 11 种训练时没见过（分镜草图、蜡笔画、点云、线框等）。以 Gemini-3.8-Flash 两两比较打 Elo：未见结构上总分与 LynnReal-Omni 并列 1441，见过的结构上 1510 对 1410；与 15 篇已发表工作的官方 demo 对比，49 胜 13 平 24 负。消融显示数据"对齐"比数量重要（数据砍到 1/10，分数变化不超过 0.2）。

局限。 论文第三方权重沿用 MiniMax-H3 社区许可，不对美国、欧盟、英国、韩国开放（代码 Apache 2.0）；完整模型在 80 GB 显卡上会爆显存，另发了 8 bit 版；因果版颜色会漂移；快速运镜、彩色深度、体素和分镜输入上不如 50 步；评分靠 LLM 裁判。

同日。 论文C2R# 走另一条路解决缺成对数据：先用好构造的"真实图→粗渲染图"图像对，训练一个在 DINO 特征空间把真实画面变"粗"的模型，再逐帧作用于普通真实视频，造出伪粗渲染视频来训练"粗→真"模型；摘要未给数字。官方HeyGen 发布 HeyGen Video 1，同样基于 MiniMax H3 后训练：文/图/参考生视频，5–15 秒、最高 2K、画面与对白音效一次生成，最多 12 个参考素材、可固定种子复现，API 模型名 heygen-video-1；官方自称 Artificial Analysis 文生视频榜第一，并坦言最适合单主体、固定机位的短镜头，手部特写较弱。

是否值得读原文 · 做白膜预演→成片流程的，SolarRenderer 必读（数据构造与结构类型清单两节），并可直接下载权重试跑。

LiteLLM 发布流水线被攻破：官方初步认为，泄露的 GitHub 令牌来自代理日志里的 Claude Code 响应

LiteLLM · 2026-10-21（持续更新） · 原文 约 10 分钟

发生了什么。 官方10 月 21 日（UTC 11:39–13:23，即北京时间 19:39–21:23），PyPI 上的 litellm==1.107.0 与 Docker 的 v1.107.0、latest、main-latest、main-stable 标签被换成恶意版本，安装后在每次 Python 启动时运行（cook.pth、sitecustomize.py），窃取凭证并每小时拉取远程代码。GitHub 上的官方源码标签是干净的。

怎么发生的。 官方LiteLLM 的初步结论：他们观察到 Claude Code 在特定情况下会把用户的 GitHub CLI OAuth 令牌嵌进响应体；内部一个暴露在公网的 LiteLLM 代理记录了响应体，攻击者疑似借此拿到三名开发者的令牌，其中一个属于组织所有者，用它关掉分支保护，把发布流程指向仿冒仓库 Berri-AI/litellm 并签名发布。调查仍在进行。

怎么做。 官方若在该时段装过或运行过：先别跑 pip（会再次触发），从 shell 删掉载荷文件、结束持有 /tmp/remote_code_loader.lock 的进程，重建环境并固定 litellm==1.106.2，轮换主机能接触到的所有密钥。评论更普遍的教训：Agent 网关的请求/响应日志本身就是高价值凭证库，应默认脱敏或不落盘。

是否值得读原文 · 用 LiteLLM 的立即看"Who is affected"；做 Agent 网关或日志的看"How this happened"。

两个可以直接抄的做法：工具调用前先备份；让"新开的上下文"来验收代码

arXiv · 2026-10-22 · arXiv · 2026-10-22 · 原文 各约 20 分钟

先备份。 论文RegretBench 收集了 205 个真实"后悔时刻"（用户在 GitHub、Stack Overflow 等处抱怨没留旧状态）改成的可执行任务。6 个前沿模型平均完成 86.1% 的任务，但只在 15.2% 的情况下事先备份。作者的 BackUpper 是挂在 harness 上的备份层：每次工具调用前检查要改什么，常见操作走规则表，复杂情况交给轻量子 Agent；覆盖了全部后悔动作，恢复后与原状态平均相似度 92.2%，每任务 0.014 美元，比让主 Agent 自己备份少用 7 倍 token。

独立验收。 论文同一个 Agent 既写代码又写测试时，测试不再是独立证据。预注册实验里，在三个有状态服务中埋了 46 个缺陷，新开上下文、先只看规格的验证者，比构建者自己的测试查出更多缺陷（Holm 校正 p = 0.006），还暴露了规格歧义，代价是偶尔给出错误的预期结果；换一家厂商的模型做验证者，没有额外收益。

是否值得读原文 · 两篇都是"读方法一节就能用"；第二篇的结论很实用——要的是隔离上下文，不是换模型。

OpenAI Decisions API 正式可用：只回答"有限选项"的问题，号称比 Responses API 快 10 倍、输出不收费

OpenAI · 2026-10-22 · 原文 约 6 分钟

是什么。 官方基于 GPT-6 Luna 的专用端点，用于分类、路由、"下一步做什么"这类答案有界的小决策。三种答案类型：predicate（条件为真的概率）、choice（从给定选项里选一个，附概率和置信度）、score（按分级量表打分）。输入可以是文本、图片或原生 JSON，单请求最多 400 个问题（公测时的两倍），新增 GPT-Live 语音会话原生集成、提示缓存、美国与欧盟推理驻留。

价格与客户数据。 官方输入每百万 token 0.10 美元、缓存输入 0.01 美元，输出不收费。客户自述：Datadog 用它在执行前给 Agent 生成的命令打风险分，p95 比前沿模型快 40 倍；Sierra 选下一步动作 p95 低于 280 毫秒；Box 在 30 个保险凭证样例上路由快约 5 倍、准确率持平。
