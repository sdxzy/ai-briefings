第 01 节

个人 Agent 与记忆/上下文管理

一条编码 agent 的跨任务记忆论文：先测「下一道还没见到的题能省多少」，再决定记什么、怎么用。

CoReMem：记忆要按「下一道未知题能省多少步」来估值；真正值钱的是仓库位置和可执行检查，不是叙事

Yale / 清华 / Goodvision AI · arXiv · 2026-11-12 · 原文 论文约 35 分钟（§3 方法与表 1 最有用）

问题。 论文真实的编码 agent 会在同一个、不断被改过的仓库上连续修多道题：上一题留下的工作树会传给下一题，但下一题是什么事先并不知道。现有记忆方法多半在「当前题内部压缩上下文」，或把通用经验搬到互不相关的仓库，或在评测时把仓库状态重置后再回放本题。作者在 ChainSWE 上对照后发现：把全文历史、Mem0 的事实、MemOp 的指南或 ReasoningBank 的策略交给下一题，往往能提高一点解出率，但加上写记忆本身的 token 之后，步数和总 token 并不能同时降下来。

方法。 论文先给一条记忆下定义：在继承下来的仓库状态上，用「带着它跑下一题」和「不带它跑下一题」的差值，衡量它值不值得留下。再把当前轨迹切成推理文本、命令、读到的仓库内容、测试输出、diff、结局、临时文件七段，逐段拿掉，看下一题的步数和 token 会怎么变。付得起的部分被收成两类锚点：位置（文件路径、行号、符号名）和检查（测试命令、测试标识）。记忆模板保留命令和仓库内容作主字段，测试、diff 文件列表和结局用压缩形式，推理文本和临时文件丢掉。第二步再训练执行模型本身：同一组 rollout 里混合「带本仓库记忆」「不带记忆」「带错仓库的记忆」，奖励在解出的前提下扣步数；只有实际用到记忆里锚点的步骤，才获得记忆的额外分，避免模型学会见记忆就跟。

证据。 论文在 ChainSWE 测试集上，对 Qwen3.8-27B-FP8：解出率从 21.0% 升到 25.7%，步数少 17%，含写记忆在内的总 token 少 11%；三个开源执行模型上，单位总 token 的解出率平均提高 41%。只换记忆、不训练执行模型时，六个模型（含 Claude Opus 5.5、GPT-5.6 Luna、DeepSeek-V4-Flash）的步数都下降，解出率不降。对照里，Mem0 / MemOp / ReasoningBank 在多数模型上总 token 更高。消融显示：去掉「按记忆价值给步骤记功」后，27B 模型遇到错仓库记忆会多花 2.1 步；加上之后，额外代价降到 +0.3 步。

局限。 主实验是 Python 仓库和 mini-swe-agent；训练只覆盖三个开源执行模型；更长的仓库历史里记忆该如何累积和刷新，作者列为未来工作。

短评。 评论和本周 Continual-ARC 的结论可以对上：记忆若在任务识别之前就选好，或只存叙事性经验，下一题用不上。这里给出的可操作答案很具体——先按下一题的代价来估值，再只留下能直接执行的位置和检查。

是否值得读原文 · 值得。读 §3 和图 5（各段对下一题步数的贡献）以及表 1，约 15 分钟。

第 02 节

RSI（自我迭代 / 人参与的迭代）

一篇把「生成候选」和「持久写入」分开的统计框架，正好接上本周 FGSE 与 Continual-ARC 的讨论。

EGE：能写出一套自我更新，还不等于它该成为系统的持久状态

Subodh Lonkar（独立研究者） · arXiv · 2026-11-12 · 原文 约 40 分钟（§4–§7 的门控规则和部署协议最有用）

问题。 论文Agent 越来越多地根据交互记录改提示词、记忆、工具配置、工作流和路由策略。可是「看起来更好」并不等于「应该写进持久状态」：候选是根据已有成败自适应提出的，打分器可能偏袒某种文风，窄目标上的提升还可能损害事先声明要保住的能力。作者把「持久采纳」单独写成一个决策问题，而不是生成方法的附属步骤。

方法。 论文Evidence-Governed Evolution（EGE）把生成和确认分开。候选先冻结，再用没参与过构造的新样本做确认；至少一项预先规定的主目标要达到有实际意义的提升，所有受保护能力相对一个版本化的参照配置做非劣效检验，再通过不能用平均分抵消的治理约束（权限、资源上限、必要的人工批准等），最后只在限定范围的金丝雀环境里运行，通过预定标准才提交。统计部分用候选各自的校准样本，估计业务打分器相对参照评审程序的偏差，并给可数的候选序列分配总误差预算。参照配置若要更换，必须先和上一版做桥接检验，累计允许的退化被明确写出来。

证据。 论文作者做的是合成蒙特卡洛压力测试，不是真实 agent 评测：每组条件 3,000 场、每场 10 个候选。在业务打分器对有害候选偏高 0.25 时，不做校准的规则在 3,000 场里有 2,997 场至少接受了一个有害候选；加上候选级校准后，九组设定里都没有观察到有害接受。样本量只有 5,000 时，校准门的功效是 52.6%–76.2%，到 20,000 才到 100%。若校准样本和确认样本来自不同的偏差分布（故意违反假设），校准门会在全部 3,000 场里接受有害候选。规划公式也显示，候选序号越大、校准样本需求越高。

局限。 作者写明：本文没有在真实自主 agent 上做实证，保证取决于有界成对分数、新鲜抽样和有效的参照评审；回滚只能恢复配置，不能撤销已经对外发生的不可逆操作。文中也披露使用了 ChatGPT 辅助组织与起草，作者对论证和实验负责。

短评。 评论和本周 FGSE（先证伪再写入）、上周 TRUST（统计接受门）是同一条线上的不同层：FGSE 管一条经验能不能留下，EGE 管整份配置改动要过怎样的证据门槛。共同前提都是——生成候选的那套机制，不能同时当最终裁判。

是否值得读原文 · 关心 agent 自我更新治理的读 §4 的接受规则和 §7 的两阶段提交即可，约 15 分钟。定理证明和蒙特卡洛细节可略过。

第 03 节

世界模型 / 具身

BWM-Forge：先用编码 agent 写出可编辑的 Blender 场景程序，再拿代理视频去生成外观；同一套程序可换机位、换外观、换机器人

同济大学 / Koala Uran · arXiv · 2026-11-12 · 原文 论文约 30 分钟（§3 流程与 §4.3 可控性例子最有用）

问题。 论文端到端生成机器人视频时，场景几何、机器人动作和相机轨迹都埋在像素里，改一个物体、换一个机位或换一种机器人，往往只能整段重抽，也很难在任务之间复用。

方法。 论文BWM-Forge 把「世界编程」定义成：用可执行的场景程序写出物体、空间关系、机器人运动和相机状态。输入可以是首帧图、首帧图加运动数据，或人类演示视频，再配上机器人资产和任务描述。一个由四类角色组成的 harness 分工：预处理核对资产与运动、解析视觉证据；搭建 agent 在 Blender 里分阶段建环境、导入机器人和合成动画；评审 agent 根据画面和数值证据做局部修正；渲染 agent 用代理视频和参考图，经 Seedance 2.5 生成外观，并用客观指标和视觉模型评分。阶段摘要会写入经验库，后续任务按范围检索可复用的建模与渲染规则。同一套场景程序可以输出同步多机位，或在不重建场景的前提下更换环境外观。

证据。 论文在覆盖单臂、双臂、灵巧手、四足和人形共 15 个任务上，与 LingBot-World Base Cam 相比，BWM-Forge 在美学、主体一致性、背景一致性、运动平滑度，以及 RoboJudge-9B 的物理符合度、指令对齐上都更高；基线只在动态幅度上领先。指令对齐为 3.33 对 2.73（16 FPS 版本为 3.40）。定性例子包括：同一工厂任务的三个机位、同一段搬运动作换成市集 / 仓库 / 垂直农场外观，以及把经验规则从车间复用到实验室和厨房。

局限。 评测规模只有 15 个任务，没有验证这些生成视频能否提高下游机器人策略；部分修正仍依赖人工反馈；动态幅度低于对照，细接触（如缝合）从抽样帧上也难以判断。

短评。 评论这是又一个把「可编辑的 3D 代理场景 + 相机 + 生成渲染」写成完整管线的例子，和近期 Intangible 2.0、白膜约束空间一致性的思路一致，只是服务对象从短剧预演换成了机器人数据。

是否值得读原文 · 做具身数据或空间一致性视频的值得看 §4.3 的多机位与外观迁移例子，约 10 分钟。

第 05 节

高效使用 AI / Agent

两条可执行的用法：同一条任务里按阶段换模型；把分类、定位从生成模型里拆出来。

Antigravity Orchestrator：别在整条轨迹上从头到尾用同一个前沿模型；默认的 high 往往比 xhigh 更划算

Google Antigravity · 2026-11-12 · 原文 Antigravity 博客约 4 分钟；AA 帖 2 分钟

问题。 官方静态路由器往往只根据第一条提示判断难度，然后把整道题交给同一个模型。但长程 agent 任务里，规划、改代码、跑测试、遇到卡点后再规划，所需的推理深度并不一样。

做法。 官方Orchestrator 在同一条轨迹里动态切换 Carbon 和 Hydrogen：例如 Carbon 先只读探索、写出带重新规划触发条件的计划，Hydrogen 再改代码、更新依赖、跑测试；若 Hydrogen 受阻，再交回 Carbon 检查状态、修正计划后续跑。官方举例，Carbon 也可作协调者，Hydrogen 作并行的执行和校验 agent，在隔离工作区里同时改和测。Antigravity 博客称，在 Terminal-Bench 4.1 上 Orchestrator 接近 Carbon 的成功率，同时平均少用 24% 配额、快 19%。评论Google 主博客同一数字写的是 Terminal-Bench 4.0，两处基准版本不一致，引用时需注明来源。

选档。 第三方Artificial Analysis 测得 Hydrogen 在 xhigh 档智能指数为 54，单任务成本 3.16 美元；官方与 AA 都指出，默认 high 档为 51，已超过 Argon 的 50。AA 补充：xhigh 相对 high 多出约一倍输出 token，才换来 3 分；high 档单任务成本降到 1.87 美元。「对多数工作负载，high 就能达到 Argon 级智能，成本只是零头。」Hydrogen 在 AA 上也很「话多」：智能指数评测产生 3.04 亿输出 token，同价位中位数约 7,280 万。

可用范围。 官方Hydrogen 向 Google AI Pro / Ultra 付费用户在 Antigravity 放量；Orchestrator（Carbon）面向 Ultra，Orchestrator（Argon）面向 Ultra 与付费 Pro。

Perplexity Decider v1.3：开源决策模型新增加 locate，一次前向可同时做判断和抽原文

Perplexity Research · 2026-11-12 · 原文 博客约 20 分钟（用法与评测表可先看后半）

是什么。 官方Decider v1.3 与更小的 Flash v1.3 是决策模型的新版本，在 Hugging Face 以 Apache 许可开源，并进入 Decisions API 与 OpenRouter。CEO 称 OpenRouter 上免费一周。模型从生成式 LLM 改造成分类器：一份共享上下文加多道题，一次前向返回各选项概率。题型仍是是 / 否、多选和有序评分。v1.3 的骨干是 Qwen3.8-27B，Flash 蒸馏到 Qwen3.5-4B；注意力改为「问题彼此隔离、但都可以看到共享状态」，避免上一版「所有问题互相看见」时答案随一道题怎么问而变。

新能力。 官方locate 不再从预置选项里选，而是按标签或指令从原文里抽出匹配片段，并给出起止字符位置；没有匹配则返回空列表。同一请求里可以混合定位、分类和评分。官方在 17 个域外抽取任务上，v1.3 平均 69.0、Flash 63.6，高于对照的通用抽取模型。在 72 个检索重排任务上，v1.3 的平均 nDCG@10 为 83.99；对决策 API 上线前 18 天、经用户许可的 100 万条真实请求，v1.3 与裁判模型的一致率为 93.98%。标签顺序扰动时，v1.3 的答案翻转率只有 0.27%。

内部用法。 官方Perplexity 用它离线抽查 agent 会话日志，检查现有监控规则是否漏报或误报，再由安全团队批准规则修改。官方称，一天内 Decider 读了 7,000 个会话共 10 亿 token，据此提出 14 条规则修改，其中 6 条在两天内获准上线；在一周日志上回放后，最繁忙那条规则的触发量下降 52%。它也被用来观察 RL rollout 中工具或沙箱故障、以及爬取时的页面质量过滤。监控只观察和诊断，不改奖励、不停下运行。

局限。 真实请求没有人工金标准，一致率依赖前沿模型当裁判；成本对比未对齐延迟与硬件口径。

Gemini 4 Hydrogen：默认档智能指数 51，超过更贵的 Argon；面向日常编码与 agent 执行，全价 1M 上下文 1.50 / 7.50 美元

Google DeepMind · 2026-11-12 · 原文 官方博客约 8 分钟；模型卡评测表约 3 分钟

是什么。 官方Gemini 4 Hydrogen 从 Gemini 4 Carbon 改编而来，定位是日常编码和多样 agent 工作流里的快速执行，而把长程、高难度推理留给 Carbon 和 Argon。统一 100 万 token 上下文（输入、思考、输出共用），默认同步输出 64K，后台长解码可达 100 万。四个思考档：low、medium、默认 high，以及新的 xhigh。价格在整段 1M 上下文上按统一费率：每百万 token 输入 1.50 美元、输出 7.50 美元。面向 AI Studio 与 Gemini API 的所有档位、Gemini for business、Gemini 应用、Google 搜索，以及 Antigravity 里的付费 Pro / Ultra 用户；免费应用用户在自动选模型时也可能用到它。官方称它也成为 Antigravity 托管 agent 的默认模型。

数字。 官方默认 high 档在 Artificial Analysis 智能指数上为 51，超过 Argon 的 50；xhigh 为 54。相对 Gemini 3.8 Flash，默认档完成任务快 2.5 倍，Terminal-Bench 4.1 从 18.2% 升到 57%，虚构陈述减少 5 倍以上。模型卡对比 Claude Sonnet 5.5 与 GPT-6.1 Terra：SWE-sweep 13.5% 对 3.1% / 5.8%；Agents' Last Exam v1.1 为 71.6% 对 60.4% / 69.8%；MKA 为 53.4% 对 52.0% / 43.8%；HLE-Diamond 为 58.8% 对 53.3% / 47.3%。Terminal-Bench 4.1 上 Sonnet 仍更高（63.9%）。官方还称，工具失败或搜索为空时更能适应，并行批量读文件和搜索；早期合作伙伴在复杂图、SQL 和企业数据工作流上看到比 3.8 Flash 快 2 到 2.8 倍、token 少 12% 到 23%。第三方AA 称，Hydrogen 智能略低于 Claude Sonnet 5.5 和 GPT-6.1 Sol，成本约为 Sonnet 的三分之一、Sol 的 2.5 倍；xhigh 档单任务 13.7 分钟、首个答案 token 延迟 40.55 秒，偏慢也偏长。AA 另测 AA-Robotics v0.1：Hydrogen 是 Google 模型里最高的，总榜第四，前三为 Claude Fable 5.2（75）、GPT-6 Astra（69）、GPT-6.1 Sol（65）。

局限。 官方知识截止日期为 2026 年 3 月；可能出现幻觉，高思考档有时更慢或超时、token 更多；完整 Safety & Security Report 将在数日内发布。第三方Simon Willison 指出，Hydrogen 相对 Carbon / Argon 只便宜约 25%，中档并不等于「便宜档」。官方自报基准需以 AA 等独立评测为准。

Claude Meetings 进入 beta；Managed Agents 可在自有环境里跑控制面

Anthropic · 原文 两篇官方说明合计约 10 分钟

Claude Meetings。 官方Team 与 Enterprise 计划开始滚动预览：Claude 可以作为可见参与者加入 Google Meet，跟着讨论写文档、白板和其他产物，并整理笔记和待办；同事可在会议中同时编辑。默认在聊天里书面回答，使用已连接的工具前会征求当事人同意。会后，笔记、逐字稿和产物留在 claude.ai 的会议页上，可供事后再问。目前只支持 Google Meet，其他会议平台「即将到来」。默认在有组织外宾客时不加入，若中途进来会离开；管理员可允许外宾场景，但 Claude 不在通话聊天里回复。它保存逐字稿、摘要和屏幕描述，不保存音频。预览期笔记和逐字稿免费；通话中的产物免费至 2027 年 2 月 10 日。使用已连接工具的回答计入套餐用量。开启零保留、HIPAA 就绪或客户托管密钥的组织暂不可用。

自托管 Managed Agents。 官方私有预览允许把 Managed Agents 的控制面放到自有云或机房：harness、沙箱、凭证和会话历史都在组织自己的环境里运行，模型请求则发往 Anthropic、Bedrock、Google、Microsoft Foundry 或自建网关。开发者仍使用与托管版相同的核心 API。官方强调这不是「自托管模型」：会话历史可放在自有数据库，但对 Claude 的调用仍会离开本机。设计原则包括：harness 与沙箱分离、凭证不进沙箱、网络可按允许的主机限制、每一步工具调用可经 OpenTelemetry 导出。私有预览需通过 Anthropic 客户团队申请。第三方ClaudeDevs 原帖获得 1.1 万次以上点赞。

OpenAI Daybreak：把授权安全测试和补丁准备做成两款 agent 产品，补丁需工程师审查后才能合并

OpenAI · 2026-11-12 · 原文 产品页约 5 分钟

是什么。 官方OpenAI 在 11 月 12 日的 Cyber at the Frontier 活动上，为 Daybreak 平台增加两款产品。Red Team 进入早期访问：在隔离环境和边界审查之下，对组织授权的自有 Web 应用做持续安全测试，并帮助复核扫描器、漏洞赏金和披露报告里的已有发现。Defense Factory 进入预览：把上述发现或 Wiz、Snyk、Endor Labs 等工具的结果导入后，由基于其网络安全模型的 agent 在代码库中定位问题并准备补丁，工程师审查、测试后才合并，不会自动上线；也可结合 Codex 补充上下文、调整补丁。支持扫描已连接的 GitHub 仓库、关注新提交，以及按计划复查。
