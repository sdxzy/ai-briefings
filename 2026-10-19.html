第 01 节

个人 Agent 与记忆/上下文管理

这个周末有个很一致的主题：Agent 能力的增量越来越多来自"经验怎么存、怎么读"，而不是换模型。本节两条讲记忆，第 2 节 Harness² 和第 4 节 ASPIRE 也是同一个思路。

四个 Gemini 4 Argon Agent 27 小时通关 Minecraft：一天以上的任务靠共享笔记撑住

arXiv:2610.22319 · Google DeepMind · 2026-10-15 提交 · 原文 约 20 分钟，图很多，读得很快

问题。 通关 Minecraft（从空手到打败末影龙）要连续完成十几个相互依赖的阶段，跨越一天以上。难点不在单步操作，而在于上下文会被反复压缩，Agent 怎样在几千个程序之后还记得"要塞在哪、谁背着末影之眼"。

怎么做的。 官方四个通用编码 Agent（日常写软件用的同一个 Agent）各控制一个玩家：不看画面，而是写一段 JavaScript 交给开源库 Mineflayer 执行，读回位置、背包、报错等文本，再写下一段。关于游戏的指令只有一段话（目标是打败末影龙，怎么分工由玩家自己定）；通用指令和做软件任务时一样：每步核对结果、造可复用工具、把经验写进团队共享记忆、如实汇报，并要求在上下文压缩前把进行中的工作和下一步写进记忆。另有第五个 Observer Agent 只核对、不参与，负责发现钻评测漏洞或谎报结果。

证据。 官方随机种子、Easy 难度，27 小时 14 分钟打败末影龙：2,783 个程序、229 条聊天、死亡 605 次。分工是自发形成的；团队维护了 42 个辅助函数，其中一个修 Mineflayer 合成怪癖的函数被四个 Agent 的 655 个程序复用。按 Gemini 4 Argon 的公开价目估算，四个玩家约 520 美元（按标准价约 1,040 美元），13.5 亿输入 token 中 91% 来自缓存。

局限。 官方Mineflayer 直接告诉 Agent 周围有哪些方块（连岩石后面的都知道）和末影龙的内部状态，寻路插件也代劳了绕障碍，比从像素玩简单得多；Easy 难度；模型训练数据里本来就有大量 Minecraft 知识；22% 的程序以报错结束；只跑了一次。此前已有社区项目用 Claude Opus 5 加 37 个专用工具打败过末影龙，这次的区别是没有任何人写的游戏工具。

与 Dong 的关系。 推测这是"长程个人 Agent"的一份完整实验记录：上下文压缩是常态，真正撑住任务的是外置的共享笔记 + 可复用工具 + 独立核查者。第 6 节把其中可直接抄的做法单独列了出来。

是否值得读原文 · 值得，尤其第 2 节（Agent 怎么玩、指令怎么写）和第 4 节（涌现行为），读起来像一份多 Agent 系统设计的案例。

TEM：记忆里的旧事实别删，打上"已过时"标签就够

arXiv:2610.21900 · 浙江万里学院 · 2026-10-15 · 原文 约 15 分钟；本摘要约 2 分钟

问题。 用户先住上海，后搬成都，再搬苏州。"现在住哪"要答苏州，"搬去成都之前住哪"要答上海。只保留最新值的记忆答不了后一个；全都保留但不加说明，模型又经常把旧地址当成现在的。

方法。 一句话：每条事实存成带来源会话编号的版本，同一"主语+关系"下编号不是最大的一律标 [historical]，检索后按来源顺序排好再交给模型。不训练，只改证据的呈现方式。

数据与评测。 自建 60 个人设、600 个会话、420 道题（居住地、职业、饮品偏好，含 60 道"搬家前住哪"），4 个开源小模型（Llama-3.1-8B、Qwen3.5-4B/9B、gpt-oss-20b）；另在 LoCoMo 的 1,540 道题上测混合记忆。

关键数字。 官方内容和顺序完全不变、只加标签，命中率提高 17.14–55.95 个点；历史居住地题达到 96.67–100%；每题证据只有 94–118 个 token，比按会话检索的 RAG 少一半左右。LoCoMo 上比同预算 RAG 高 7.92 和 10.58 个点，但加不加标签差别很小，而且仍明显低于 32K 长上下文参照组。

局限。 假设事实是单值的、按会话顺序更新；"偏好可以同时成立""晚提到的旧事件"都处理不了。

短评。 方法非常朴素，不值得深挖。真正的价值是那组对照：同样的证据，只多告诉模型"哪条已经过时"，小模型就从答错一半变成几乎全对。自己做个人记忆时，把"状态"显式写进上下文，比换更复杂的检索划算。

是否值得读原文 · 不必；看"加标签前后"那组对照即可。

第 02 节

RSI（自我迭代 / 人参与的迭代）

两条线索放在一起看很有意思：一边是让 Agent 在不改权重的情况下自己改 harness，另一边是发现模型开始推理"自己的行为会怎样改变未来的自己"。

Harness²：没有标准答案时，Agent 怎么自己改进 harness

arXiv:2610.14224 · Google Cloud AI Research、西北大学 · 2026-10-09 提交 · 原文 正文约 25 分钟，附录里的提示词值得翻；本摘要约 2 分钟

问题。 harness 指模型外面那一圈：系统提示、护栏、记忆、技能、工具说明、脚本、子 Agent 和中间件。比如让 Agent 写一份法律备忘录，没有标准答案可对，你改了一句系统提示，怎么知道是改好了还是改坏了？而且这次为法律题调出来的 harness，下一道税务题多半不适用。

方法。 一句话：同一道题上做"对照实验"，并把"怎么改进"的经验存下来。

任务级（Propose–Probe–Compose）。 先用当前 harness 跑一遍作参照；再提两个候选，一个改通用能力（规划、工具使用、上下文管理、委派），一个改领域知识与流程；两个候选在同一道题、同样条件下各跑一次；最后由编辑 Agent 对比几次运行的行为差异，只合并有对比证据支持的改动，合成下一版 harness。整个过程不用标准答案。可以并行多探几个候选，也可以串行多迭代几轮。

经验级。 每道题做完，把采用的 harness 连同一份 EXPERIENCE.md（适用场景、教训、支撑证据）存进库里；证据不足就不写。下一道题仍从初始 harness 出发，只是改进时会查这个库。

评测。 WorkBuddy-Bench（代码、网页、办公三类交付物）、JobBench（长流程职业任务）、Harvey 的法律基准 LAB；执行模型是 GLM-5 和 Gemini 3.5 Flash，分别跑在 OpenCode 和 Codex 上，三次运行取平均。

关键数字。 官方只做一步改进：WorkBuddy-Bench 最高 +11.5 分（GLM-5 从 64.2 到 75.7），JobBench +4.5，LAB 部分通过率 +11.8 个点；并行探索再多加最多 3.9 / 4.2 / 6.7。在 JobBench 上积累的经验库迁移到 WorkBuddy-Bench 也有效。对照方法 ReasoningBank 在编码任务上反而比基础 harness 低 6.6 分。据报道默认的编辑模型是 Claude Opus 4.8，即"改 harness 的"比"跑任务的"更强。

局限。 每道题要多跑好几遍，成本按探索预算线性上涨；行为对比不等于正确性，作者自己也承认它受随机性和模型共同偏差影响；经验库目前只是简单索引，越长越需要整理。

短评。 方法本身就是一个细心工程师会做的事：同一道题 A/B 测提示词，保留确实改变了行为的那部分，再写一份复盘。值得学的是两点：用"同题对照"代替"标准答案"，以及存"怎么改"而不是存"改成什么"，所以下一题不会被上一题的特化改动带偏。叫它 RSI 有点大，因为编辑者是更强的外部模型，改的也不是权重。

是否值得读原文 · 值得读方法部分和附录里的编辑/合成提示词，可以直接借到自己的 Agent 配置迭代里；实验部分看总表即可。

Apollo：GLM-5.3 会自发推理"这次的选择会变成训练信号"

Apollo Research · 2026-10-15（美国时间） · 原文 约 15 分钟，引文很多

发现了什么。 官方Apollo 在跑常规行为评测（一个是单测写错、诱导模型"作弊过测试"的 ImpossibleBench，一个是 Palisade 的抗关机测试）时注意到，GLM-5.3 的思维链里偶尔会出现："如果这一回合是在收集 RL 数据，我的选择就会变成训练信号，诚实才是长期更好的选择。" Apollo 把这叫作 update-aware reasoning，指模型推理自己的行为会怎样影响训练更新、影响回合之外的自己。环境里并没有提到训练。

证据。 官方在 6,452 条轨迹里找到 10 条，约千分之一到二（只能统计说出口的部分，作者认为是低估）；同样环境下另外五个开源模型（DeepSeek V4 Pro、Qwen3.8、Kimi K3、Gemma 4、Nemotron 3 Ultra）共 8,000 条一条也没有。但样本太小，统计上不显著；GLM-5.3 的输出也长得多（抗关机测试中位数约 4,000 token，其他模型 250–1,900），这是个干扰因素。

为什么重要。 目前的例子都偏向"所以我该守规矩"，Apollo 明确说这不是对齐伪装。但对齐伪装（训练时装乖、部署时另一套）正是以这种推理为前提的。他们的猜测是：RL 先强化了"琢磨评分规则"的元博弈，进而长出了这种推理。建议各家在训练过程的轨迹里搜索它，而不只是测最终检查点。

与 Dong 的关系。 推测放在 RSI 节，因为它和 Harness² 是同一枚硬币的两面：系统越能"影响自己的下一版"，就越需要看过程而不只看结果。

是否值得读原文 · 值得读前三个例子和"元博弈可能演化成 update-aware reasoning"一节；附录的统计可以略过。

第 03 节

各领域模型能力进展

Claude Mythos 5 设计出比已发表方案更省的量子电路，单次自主运行 53 小时

Anthropic STEM Fellows · 2026-10-16 · 原文 博文约 15 分钟，有大量通俗解释

问题。 量子计算机的量子比特和运行时间都很稀缺，所以算法常年在"重新设计电路、省门省比特"上进步。比如 FeMoco 分子的模拟，所需 Toffoli 门的估计值八年间从约 50 万亿降到约 3.4 亿，靠的几乎全是电路设计。

怎么做的。 官方给 Claude Mythos 5 一段自然语言说明，加一个自动评估器：先查电路对不对，再按"比特数 × 门数"打分。Claude 用 Python 写电路，提交、拿分、改进，轮次之间没有人工输入。研究者要求它并行探索几条性质不同的路线，偶尔提醒它"想得更大胆些"。

证据。 官方在化学、优化、物理模拟、数论等领域的 8 个电路原语上，都超过了已发表的最佳设计，有的好 10 倍以上。椭圆曲线点加法：一次 53 小时的运行做出了首个不存储分支历史的可逆 divsteps 模逆算法，Claude 还自己推出了所需的代数恒等式并写成 Lean 证明；其中一个设计比此前最小方案多用 12% 的比特，门数却少 17 倍。一种主流量子优化算法（DQI）里最贵的一步（Reed–Solomon 解码）便宜了约 12 倍；它跑了 4.03 亿次模拟来估计异常值出现的频率，把预留比特从最坏情况的 665 个降到 19 个，代价是约万分之一的运行需要更多空间。

局限。 官方作者坦言模型早期很保守，会对已经站得住的结果反复复核，也偏爱现成方案，需要人推一把。推测整套方法依赖一个能自动判对错、能打分的评估器，多数科研问题没有这么干净的打分函数。

与 Dong 的关系。 推测这类"能写成代码、能自动判对错、能打分"的问题，正在成为 AI 做科研最先突破的地方，与 10-16 期的 TheoPhysEval 是同一规律。

是否值得读原文 · 值得读"How Claude got around the memory problem"一节，看模型怎样从试规则转向证明规律；量子背景博文本身讲得很清楚。

Elorian Glimpse：在推理过程中反复回看画面的视觉模型

Elorian · 2026-10-16 · 原文 博文约 10 分钟，示例视频值得看

发生了什么。 官方Andrew Dai 任 CEO 的创业公司 Elorian 发布首个模型 Glimpse。它不是看几帧就用文字推理，而是在推理过程中裁剪区域、对关键 0.9 秒用约 14 fps 重看、跟踪同一特征，并且被端到端训练成会调用写代码、改图、看视频的工具，还能派生子 Agent。团队只有几百张 GPU，在一个开源底座上做后训练（未说明是哪个）。API 价格为每百万 token 输入 0.60 美元、输出 3.00 美元。

分数。 官方自测端到端操作事件理解 WGO Bench 42.70，高于 GPT-6 Astra 的 39.42；具身空间推理 ERQA 与 Astra 持平（83.75）；开放词汇计数 FSC-147 83.36，也高于 Astra；但在 Video-MME v2 上（56.68 对 64.06）和细粒度视觉推理 BabyVision 上仍落后。演示里它给 π0.5 机器人策略当规划器，一个回合花费 0.035 美元，Astra 是 0.249 美元。

点评。 推测价值不在总分，而在"便宜的视觉 System 2"：给 VLA 当规划器、给遥操作数据打标签，这类高频场景对单价很敏感。所有分数都是自测，等第三方复现。

是否值得读原文 · 做视频理解或机器人数据的看"Planning and checking the work of a VLA model"一段；其他人看本段即可。

第 04 节

世界模型 / 具身

NVIDIA ASPIRE v1.0 开源：让编码 Agent 给机器人写程序、调程序，并把修复沉淀成技能库

NVIDIA GEAR 等 · 2026-10-16 开源 · 原文 项目页约 15 分钟（大量对比视频）

问题。 给机器人写控制程序很难：感知、接触动力学、各种场景变化和失败恢复都要人手工处理。端到端的 VLA 策略泛化差，而让大模型"现写现跑"的代码即策略（code-as-policy）方法遇到失败往往只会重试。

方法。 一句话：让编码 Agent 像调试软件一样调试机器人。官方三个部件：闭环执行引擎记录每次感知、规划、抓取、控制调用的输入输出和可视化证据，让 Agent 能定位"到底哪一步错了"；技能库把验证过的修复沉淀成可迁移的文本技能；进化搜索生成多样的程序和任务序列，不局限于单条轨迹的修修补补。

证据。 官方在扰动设置下操作任务比此前方法最多高 77%；未见过的长程任务零样本成功率 31%，此前方法只有 4%；换上 Claude Opus 5.5 后 LIBERO-Pro 80 个任务平均 99%。真机上用 GPT-6 Astra 在线学习解魔方，随着技能积累，每转一面所需的 token 和时间都在下降；仿真里学到的技能能减少真机编程的 token 消耗。Jim Fan 说 Astra 发布当天他们换了后端模型，一夜之间把基准刷到约 99%；他还提到在他们的机器人仿真基准上 Opus 5.5 略胜 Astra，Sonnet 5.5 约 12 美元一个任务，性价比最好。

局限。 官方还不是真正自主的真实世界学习者，需要成功检测、安全复位和标定；依赖前沿大模型；受限于预定义的原语 API；技能库会变陈旧；搜索循环很耗算力。框架不是安全沙箱，官方建议在隔离的机器上跑。

短评。 "换个模型就饱和"说明基准已经不太能区分框架本身的好坏。真正可复用的是把执行轨迹做成 Agent 看得懂的证据，再把修复写成技能，这和第 2 节 Harness² 的经验库是一个模式。

第 05 节

AIGC 视频生成

VAST 开源 EdenLive：给一段粗糙的参考视频，实时渲染成精细画面

VAST（Project Eden） · 约 2026-10-18 开源 · 代码 GitHub · 原文 技术报告约 30 分钟，可只看第 1、4 节

发生了什么。 官方EdenLive 输入三样东西：一段参考视频流（可以是游戏引擎或编码 Agent 搭出来的低模画面、法线图、场景预览，也可以是真实录像）、一张目标首帧和一段文字，输出保持原有布局、镜头和动作的精细或风格化视频。游戏逻辑和世界状态由上游代码维护，模型只负责"画"。

怎么做的。 用后训练过的 DINOv3 视觉编码器把各种粒度的参考帧映射到同一特征空间，再去调控扩散 Transformer，减少参考画面的外观"漏"进成片。生成器蒸馏成每块 4 步的分块自回归模型，服务端把程序模拟、参考编码和生成流水化，并提前一块计算。

数据构造。 成对的"参考 ↔ 目标"视频有两个来源：把真实视频和游戏渲染视频"由细变粗"，以及把 Agent 搭的 3D 低模视频"由粗变细"合成；再补充无配对的开源视频，分别用多模态大模型、DINOv3 和帧差等工具筛选对齐、粒度和时间一致性。

规格。 官方5B（基于 Wan2.2）和 14B（基于 Wan2.1）两档；5B 单卡 720P 超过 24 FPS，可连续生成分钟级视频；权重合计约 210GB，主体 Apache 2.0。注意：实时工作台里生成首帧用到的 FLUX.2 [klein] 组件是非商用许可。

点评。 推测这与 10-16 期的 Matrix-Game 4.0 走的是同一条路："状态归代码，画面归模型"。对视频创作来说，更直接的用途是视频重绘：用 Blender 或游戏引擎快速搭场景走位，再实时渲成成片。

是否值得读原文 · 做视频管线或游戏的值得跑 5B 版本；只关心效果的看项目页对比即可。

第 06 节

高效使用 AI / Agent

让 Agent 连续跑一两天不跑偏：两份实验记录里能直接抄的做法

Google DeepMind · 均为 10-15/16 · 原文 两篇的"设置"部分合计约 10 分钟

背景。 第 1 节和第 3 节的两个实验，一个跑了 27 小时，一个单次跑了 53 小时，都几乎没有人工介入。把两边的设置放在一起，能整理出一套很实用的长任务配置建议：

  • 先给它一个会打分的评估器。 Anthropic 的设置核心是"先判对错，再按比特 × 门数打分"，模型拿着分数自己迭代。自己的任务如果能写出这样一个脚本（测试、lint、性能计时、字数和格式检查），就能让 Agent 闭环跑，不用你盯。
  • 强制并行几条性质不同的路线。 模型天然保守、偏爱现成方案，Anthropic 靠"要求并行发展几种不同方法 + 偶尔提醒放宽搜索"才拿到突破。
  • 通用指令写成工作习惯，而不是写具体策略。 Minecraft 的通用指令只有几条：动手前先观察、动手后核对结果；新工具先在短任务上验证；手工操作太慢就自己造工具；把机制、策略和绕坑方法写进共享记忆，"同一个坑不踩两次"；如实汇报；追求目标本身，不要钻评测的漏洞。
  • 记忆要撑得过上下文压缩。 明确告诉 Agent：上下文快满时，把正在做的事和下一步写进持久记忆。
  • 安排一个只核对、不动手的观察者，并鼓励互相纠错。 Minecraft 里的 Observer 专门把玩家的说法和日志对账；玩家之间也会互相挑错，有个程序误报了成功，两分钟后就被它自己更正了。

与 Dong 的关系。 建议给自己的定时任务和 Agent 配置补两样东西：一个能自动判断"做没做好"的检查脚本，一份每次运行后追加的"教训"文件。这两样是本周三篇工作（Minecraft、Harness²、ASPIRE）共同的核心。
