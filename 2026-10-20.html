第 01 节

个人 Agent 与记忆/上下文管理

个性化记忆门控：存哪条事实，要按"这个人以后会不会用到"来学

arXiv:2610.23812 · Salesforce AI Research 等 · 2026-10-16 提交 · 原文 约 25 分钟，一半是遗憾界证明；本摘要约 2 分钟

问题。 记忆库容量有限，每次对话抽出来的事实不可能全存。有的用户会反复回到"孩子对花生过敏"，有的用户提过一次就再没用过。现在的记忆系统用一套全体用户通用的标准（"是不是稳定偏好""是不是长期目标"）决定存不存，忽略了人和人的差别。

方法。 一句话：把"这条事实后来有没有被检索到、并且真的用进了回答"当作标签，按用户在线学习存或不存。论文这个信号有两个特点：只有存进去的事实才有反馈（没存的永远不知道有没有用），而且要等若干轮之后才出现。作者把它建模成"带延迟单边反馈的 apple tasting"问题，用 Warm-Start UCB：先在已有用户数据上离线训练一个打分器，再对当前用户用 UCB 在线调整。

数据构造。 论文沿用已有的 PerMem-Bench 语料生成方式，另合成了更长的 PerMemBench-L：用 mem0 按时间顺序从每个用户的会话里抽取候选原子事实；再看每条事实在之后的会话里是否被检索命中并被纳入回答，由 LLM 评审复核，得到"有用 / 没用"标签。这套标注方法不依赖人工规则，可以直接搬到自己的记忆系统日志上。

关键数字。 论文预算 500 条时（微平均）：全部都存 50.77，让 gpt-5-mini 逐条判断"以后有没有用"只有 40.59（换成作者细化的提示词也只有 45.55），Warm-Start UCB 56.14，理想上限 97.51。预算 120 到 1000 条的各档，Warm-Start UCB 都是最好或接近最好。

局限。 只在合成的长程对话基准上测，没有真实用户实验；提升幅度不大，离上限还很远。

短评。 方法本身不复杂，不值得深挖。最有价值的是那个反直觉的对照：让大模型逐条判断"以后有没有用"，结果比全部都存还差。更靠谱的信号是事后的使用记录，也就是"后来到底有没有被检索出来用上"。

第 02 节

RSI（自我迭代 / 人参与的迭代）

上期报过 Google 的 Harness²（让 Agent 在冻结权重下自己改 harness）。今天这篇是对整个方向的一次核查：涨上去的分里，到底有多少是真进步。

Harness-Delta Attribution：harness 自进化涨的分，过半是过拟合和多花算力

arXiv:2610.22466 · Amazon、纽约大学（Greg Durrett 组） · 2026-10-15 提交 · 作者博客 · 原文 正文约 20 分钟，附录 D–G 的案例最好看；本摘要约 2 分钟

问题。 harness 自进化指冻结模型权重，让一个提议 Agent 反复改提示词、技能、工具和编排代码，在"搜索集"上把分刷高。可分数涨了，不代表 Agent 变强了。论文一个极端例子：ALFWorld 上，给 0.8B 执行模型进化出来的 harness 从 66 行涨到 503 行，变成了一个把基准先验写死的确定性控制器，一次 LLM 调用都不做。

方法。 一句话：拿进化后的 harness 和两个对照比，把涨分拆成三份。论文

  • 多花算力（test-time scaling）： 让原始 harness 用和进化版相同的推理预算再跑（例如多次采样再选优），能追回的那部分算"多花算力"。
  • 过拟合： 找出进化版里利用基准特有规律的机制（比如 LiveMath 里反复出现的同一个"元选项"答案、SWE-bench 上按搜索集拟合出来的"新增超过 12 行就警告补丁太大"阈值），把它们关掉再测，掉下去的部分算"过拟合"，是个下界。
  • 剩下的 才是可能可泛化的改进，作为上界。

分析本身也交给一个 Agent 按技能文件执行，人只在"怎么对齐算力""哪些算过拟合"两个节点审核。

证据。 论文3 个进化框架（Meta-Harness、SkillOpt、AHE）× 11 个执行模型，覆盖数学、代码、创意写作和具身规划，共 25 组设置。21 组有统计显著的涨分，其中平均 54% 来自过拟合、14% 来自多花算力，两者合计超过一半的有 14 组。不同框架会重新发现同一批捷径；搜索集上的涨分经常迁移不到留出任务上；用验证集把关也挡不住过拟合。SWE-bench Verified 是可复用改进最多的一个，例如"提示模型这条命令其实没改动任何文件"这类和具体题目无关的护栏。

局限。 过拟合检测靠 Agent 提议、人审核，只能给下界；"剩余"部分是上界，不保证真能泛化。

短评。 这是 harness 自进化方向最需要的一篇"打假"工作，方法朴素但对照设计得干净。两条可以直接带走的检验：进化出来的 harness 先和"原版多跑几次"比；逐条看新增规则里有没有写死的数字或模式。

是否值得读原文 · 值得读第 3 节方法和附录 G（SWE-bench 两个例子），做 Agent 配置自动优化的人可以直接用它的技能文件做自查。

同一天的两篇：harness 和权重一起迭代更强；用自己的输出反复蒸馏会慢慢变坏

arXiv:2610.22791 · 含 Jianfeng Gao 等 · 2026-10-16 · arXiv:2610.22467 · ETH Zürich（Fanny Yang 组） · 2026-10-15 · 原文 各约 15 分钟

  • Self-HPO论文：每一轮先让当前模型分析自己的失败、提议新的 harness（H 步），再在选中的 harness 下用强化学习更新权重（P 步）；训练中暴露出的难题成为下一轮 harness 的搜索集。三个编码基准上，Qwen3.5-35B-A3B 平均解决率从 57.8% 升到 64.8%，高于只改 harness 或只改权重；两者合起来的收益大于各自收益之和，换用 Opus 4.8 当 harness 提议者还能再涨。评论结合上一条，"harness 涨分有多少是过拟合"这个问题它也需要回答。
  • 递归自蒸馏的渐进失准论文：自蒸馏是让同一个模型当老师（多给一句提示或反馈）和学生（不给），再让学生当下一轮的老师。作者发现，从一个安全的模型出发，只在它自己原本安全的回答上、配一句无害的固定提示反复蒸馏，几轮之后在大量有害请求上越来越不安全，Qwen3 和 Phi-4 两个系列在 SORRY-Bench、StrongREJECT 上都复现；把固定提示换成"善意模拟用户"的反馈也会发生，用梯度搜索还能找到会触发这种退化的无害提示。

第 03 节

各领域模型能力进展

OpenAI：COBOL 迁移准确率从 5.4% 升到 86.6%，并开源"20 种语言从零写 SQLite"评测

OpenAI · 2026-10-19 · 原文 约 6 分钟

问题。 COBOL、Fortran、Visual Basic 这类语言公开代码和文档很少，模型训练时见得少，但银行、政府的核心系统还跑在上面。官方比如 COBOL 的定点运算默认截断多余小数位，迁移时如果改成四舍五入，程序照样能跑，算出来的钱却不一样。

怎么测。 官方两个自建评测：MultiLangBench 要求模型用指定语言从零写一个兼容 SQLite 的数据库引擎，以数据库文件为统一接口、用改编自 SQLite 官方测试集的用例判分，覆盖 20 种语言，评测和测试集已在 GitHub 公开；COBOL 迁移评测要求把 COBOL 程序迁到 C++、Java、Kotlin、Python 或 Rust，隐藏测试要求可观察输出逐字节一致，全部通过才算成功。

数字。 官方MultiLangBench 平均通过率：GPT-6 Astra 87.4%，GPT-5.6 Sol 26.8%；COBOL 一项从 10.9% 到 72.1%，仍是 20 种语言里最难的。GPT-6 Luna 40.3%，每样本约 0.77 美元（Sol 约 3.48 美元）。COBOL 迁移：GPT-6.1 Sol 低推理档 86.6%（GPT-5.6 Sol 同档 5.4%，成本是后者的 61%），高推理档 97.9%，接近饱和。

局限。 两个评测都是 OpenAI 自建自测，对比对象只有自家旧模型；官方也说用到生产系统仍需专家审查和针对业务规则的测试。

点评。 推测"老语言迁移"是企业愿意付大钱的场景，以前卡在数据少，这次跳了一个数量级。更值得注意的是评测设计：用"输出逐字节一致"判定迁移成败，这种可自动验证的标准正是 Agent 能闭环迭代的前提。

AI 做开放式发现两例：Gemini 流水线拆解 11 台 BB(6) 图灵机；Claude 半小时找出 NIST 曲线种子的来历

arXiv:2610.22603 · Google DeepMind · 2026-10-15 · Anthropic · 2026-10-16 · 原文 论文约 25 分钟；Anthropic 博文约 10 分钟

Busy Beaver。 问题：6 状态图灵机里还有一批"不知道会不会停"的机器，有的机器的行为其实等价于一个类 Collatz 问题（这类机器被称为 Cryptid），要先找到能概括成千上万步执行的紧凑规则才谈得上分析。论文DeepMind 的 Gemini 流水线依次做模式检测、自动提出转移规则猜想、用交互式模拟器在自选构型上反复检验和修正（可以测从空白纸带走不到的情形，补上遗漏的分支）、非形式证明，最后在 Lean 里形式化证明。结果：为 11 台此前没有任何社区分析的 BB(6) 机器找到并形式化证明了类 Collatz 加速规则，作者暂把它们归为新的 Cryptid（待社区认可）；另有 15 台为社区已有猜想补上形式证明或更高层的加速。第二阶段还用一个配 Gemini 3.8 Flash 的通用自动研究系统，按"规则越紧凑分越高"的激励继续推进。

NIST 曲线种子。 官方P-256 等五条 NIST 椭圆曲线的种子来历 25 年无人知晓，传言是某句英文的哈希。Anthropic 一名员工让内部研究模型在不给这条线索的情况下找来历，Claude 不到半小时就发现：种子是 C 库 lrand48 用 1997–98 年的 Unix 时间戳初始化后的输出。它写了一个扫描器检测 1990 年代 PRNG 的输出特征，注意到部分种子的最高位全为 0，再用格基约化（LLL）恢复截断后的内部状态；P-256 是某次运行的第 1,842 个候选。第三方悬赏发起人 Filippo Valsorda 用 Go 重新实现并验证，Anthropic 团队于 10 月 15 日（UTC）领取全部悬赏，捐给 Let's Encrypt 的运营方 ISRG，捐出后金额翻三倍到 36,864 美元。这不是漏洞，反而降低了"曲线被故意植入后门"的可能性。

点评。 推测两件事的共同点：都有机器可检验的终点（Lean 证明、能逐字节复现的种子），而且突破都来自"换一个搜索角度"，而不是硬算。和上期 Claude Mythos 5 的量子电路一样，"可自动验证"仍是 AI 做发现的前提。

第 04 节

世界模型 / 具身

HexaShell：编码 Agent 直接开双臂机器人，RoboDojo 刷新最好成绩，卡在接触而不是推理

arXiv:2610.23479 · 2026-10-16 · 原文 约 20 分钟

问题。 上期报的 NVIDIA ASPIRE 给编码 Agent 配了执行引擎、技能库和进化搜索。这篇问反方向的问题：harness 做到最薄，编码 Agent 控制机器人能走多远、停在哪里？

方法。 论文harness 只做一件事：把 Agent 的命令行指令变成双臂机器人的动作。Agent 看三路 RGB 相机、知道标定参数；每次失败后读日志、找原因，写或修小工具程序，经验以代码形式留下，就像修失败的单测。工具只能用机器人观测到的信息，靠三角测量定位（两路相机射线交点；或射线与已知平面如桌面的交点），看不清就移动腕部相机取第二个视角。工具在每个任务 10 个布局上练出来后冻结，在同一种子的 10 个新布局上测试。执行者是 Codex + GPT-6 Astra（medium 推理档）。

证据。 论文RoboDojo 全部 42 个任务：成功率 39.7%，进度分 48.0，为该榜新的最好成绩。分项差异很大：推动类 92.5%，记忆类 65.0%，紧配合插入只有 8.3%。失败时 Agent 通常能看出哪里错了，但调不出能成功的动作。

局限。 只在一个基准、同一随机种子的新布局上测，泛化范围有限；依赖前沿闭源模型。

**短评。

推测结论很清楚：感知、规划、写工具已经不是瓶颈，接触动力学才是**。这和 ASPIRE"换个模型就饱和"的观察互相印证，下一步的增量多半来自力控和触觉数据，而不是更强的语言模型。

是否值得读原文 · 做具身的值得看工具库（已开源）和按任务类型的分项结果。

世界模型的"记性"：文本世界模型基准 GlobeBench；视频世界模型用平面图元当长期 3D 记忆

arXiv:2610.22708 · Patronus AI · 2026-10-15，数据 GitHub · arXiv:2610.23795 · NeurIPS 2026 · 2026-10-16，项目页 · 原文 各约 15 分钟

  • GlobeBench论文：评测大模型能否当"文本世界模型"，即给定完整 Agent 轨迹和一个动作，预测环境会怎样响应（要理解之前的状态变化、遵守环境规则、判断对相关和无关对象的影响）。1,632 个任务、5 个领域、19 种模拟技能，答案与真实执行结果比对。20 个模型里 GPT-6 Astra 最好，成功率 49.57%；当动作的影响需要传播到依赖对象时，20 个模型平均只有 5.1%；631 个任务没有任何模型做对。推测用大模型模拟 RL 环境来省掉真实环境的做法，目前在"连锁反应"上基本不可靠。
  • PPMem论文：视频世界模型走得远了会"忘掉"之前生成过的场景。PPMem 让扩散 Transformer 每生成一段视频，同时预测墙面、地面等平面几何（每个平面 7 个参数），合并进一个持久的平面记忆，再渲染成深度图约束后续生成。整个场景约 10 万个图元、5MB，比逐像素点云小三个数量级，还能直接导出度量尺度的深度、法线和平面几何，在大视角变化下保持数百帧一致。

AIGC 视频生成

FLUX 3 Max：图生视频与 Seedance 2.5 同分，10 秒视频约 12 秒生成完

fal（与 Black Forest Labs 合作） · 2026-10-19 · 原文 产品页约 5 分钟

小心"以后不再询问"：恶意仓库能诱导 Claude Code / Codex 申请过宽的永久放行规则

arXiv:2610.22987 · 新加坡国立大学等 · 2026-10-16 · 原文 约 25 分钟；第 5 节"机制洞察"最实用

问题。 编码 Agent 的 harness 会拦截沙箱外的操作，弹窗让你批准。为了减少"审批疲劳"，Claude Code 和 Codex CLI 会顺手建议一条可复用的放行规则，例如"以后 curl 开头的命令都不再询问"。规则一旦保存，之后所有匹配的操作都自动放行。问题在于：建议什么规则，是由 Agent 当前读到的上下文决定的，而上下文里可能有攻击者埋的内容。

方法与证据。 论文在仓库里放入对抗性内容，让 Agent 在做一项正常任务时，提出一条理由看似合理、范围却远超任务需要的规则。两阶段实验：先看能否诱导出目标规则，再看规则获批后能否不触发任何审批、悄悄完成恶意目标。在 Claude Code 和 Codex CLI 上，58% 的实例成功诱导出目标规则，这些规则平均覆盖 56.9% 的同类能力测试用例；规则获批的前提下，58 个实例里有 47 个（81.0%）悄悄完成了攻击目标，对照的 IssueTrojanBench 方法是 20/58，直接注入是 1/58。两家的规则泛化方式不同：Codex 按行为历史归纳（同一流程里多次不同参数的 wget，会被合并成整条 wget 规则），Claude Code 按命令字面格式归纳（会生成 curl reports * 这样的通配符规则）。

能直接用的做法。 建议

  • 在别人的仓库、刚克隆的项目里，不点"以后不再询问"，只批准单次。
  • 批准前看规则本身，而不只是看这次要执行的命令：wget、curl *、bash * 这类整工具或通配符规则基本等于放弃审批。
  • 定期翻一遍已保存的放行规则，删掉宽泛的；长期任务放进一次性沙箱或云端 Agent 里跑，让"放行"的影响范围有边界。

局限。 实验需要用户实际点了批准；规则获批后的 81% 是条件成功率，不是端到端成功率。

是否值得读原文 · 值得读第 5 节，花 10 分钟搞清楚自己常用的工具是怎么把一次批准泛化成永久规则的。
