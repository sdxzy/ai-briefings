第 01 节

个人 Agent 与记忆/上下文管理

上下文管理不只是「删短」，还要决定留下什么证据，以及时间过了之后要不要改计划。

CarryOn：把该留下的证据留下，不必再花一次模型调用去整理上下文

Li, Yang, Wang 等（UNSW / 港科大广州） · arXiv · 提交 2026-11-13，星期一（11-16）新公告 · 原文 摘要与引言约 15 分钟；全文约 25 分钟

问题。 论文长程工具 Agent 的历史会越积越长。摘要可能丢掉后面步骤要用的精确细节，整段保留又会带进大量无关信息。作者指出：更短的上下文并不自动等于更好的决策。

方法。 论文CarryOn 是一个轻量上下文管理器，把紧凑的执行状态和带来源链接的细粒度证据分开保存。一个学出来的选择器和自适应保留策略决定留下哪些证据，而且不再额外调用语言模型去做上下文整理。评测指标有两项：S_α 在计资源消耗的同时看任务成功，NCS 看每次成功花费的资源。实验在 AppWorld、OfficeBench 和 Tau2 Telecom 上，配三个 LLM Actor。

证据。 论文CarryOn 的宏平均任务成功率为 75.7%，比最强基线高 6.7 个百分点，并在两项效率指标的平均值上最好。

局限。 这是标准 Agent 基准，不是个人记忆产品研究；仓库目前是匿名审稿地址。摘要没有按基准拆开逐项分数。

短评。 评论和「只做压缩」相反，它把「该留下的证据必须可回溯」写成可学习的策略，而且明确不肯为整理上下文再付一次模型调用。这比再堆一个总结 Agent 更可迁移。

是否值得读原文 · 做上下文管理或长程工具 Agent 的值得读引言和实验设置，约 15 分钟。

CarryOn: Learning What to Keep in Context for Long-Horizon LLM Agents (arxiv.org)

会话中断后再打开：Agent 往往查得到现在几点，却仍按过期日程安排

Su, Wang, Zhang 等 · arXiv · 提交 2026-11-13，星期一新公告 · 原文 摘要与问题设置约 12 分钟

问题。 论文持久个人助手常在一次长中断后被重新打开，而旧的预约和准备说明还留在记录里。例如用户 5 月 6 日预约了体检，助手记下了空腹和带证件；到 6 月 5 日用户再问晚上怎么安排时，体检日早已过去，记录却没写去没去。现有长程评测多看事实是否还在，较少看 Agent 会不会根据「现在几点」改计划。

方法。 论文作者把这种能力叫「时间状态的感知与使用」：先感知当前时间，再用来解释带日期的旧记录。他们设计 session-rekindling 任务：先前对话固定，只改变回访日期，以及时间信息以何种方式提供给 Agent。实验覆盖五条模型路线和五种时间信息条件。

证据。 论文Agent「可以获得当前时间，却常常不会用」：它们可靠地查询时钟，甚至在推理里写明预约日已过，却仍有许多次继续让用户为已经过期的事件做准备。补充明确的时间上下文能降低这类错误；直接给出算好的日期关系，则可以把这类错误完全去掉。作者的结论是：跟上时间，关键不在于查不查得到钟，而在于能不能把感知到的时间写成更新后的计划。

局限。 摘要没有给出单一的准确率数字；这是行为发现，不是新系统。代码在 session-rekindling-benchmark。

短评。 评论这是一直在线助手里很好抓的一类失败：时钟在，计划不更新。补救可以很便宜——把「距预约已过多少天」算好再交给模型，而不必先指望它自己完成这一步。

是否值得读原文 · 做个人助手或会话恢复的看问题设置即可，约 12 分钟。

Can Agents Keep Up with Time? An Empirical Analysis of Temporal Adaptation After a Conversational Hiatus (arxiv.org)

第 02 节

RSI（自我迭代 / 人参与的迭代）

生产环境里的自我训练，难点往往不是再跑一轮 RL，而是需求变了、harness 也变了之后，如何在学会新行为的同时保住旧能力。

G-CAST：在 1688 采购 Agent 上做受治理的持续自训练；harness 演进时，仍要过保留旧能力的关

Yu, Kong, Mao, Zhang（阿里巴巴） · arXiv · 提交 2026-11-13，星期一新公告 · 原文 G-CAST 摘要、部署节与表 2 约 20 分钟；ModHarness-RL 摘要约 8 分钟

问题。 论文上线后的购物 Agent 会遇到两类漂移：用户需求在变（新类目、新采购场景），执行 harness——工具、技能、作业流程——也在变。按旧契约训练出来的模型，未必知道何时调用新能力，旧轨迹也缺少新工具的证据；为旧契约写的奖励，还可能评不准新行为。定期人工重训往往跟不上。

方法。 论文G-CAST 把每日生产证据，在不断变化的需求与能力契约下，做成按奖励路由、按熵优先的训练数据，并受治理地演进奖励函数。检查点只有通过累积评估才会晋级：既看对新任务的适应，也看对先前已接受能力的保留。对比基线是作者所称的强自治后训练系统 AutoTrainess。系统已部署在阿里巴巴 1688 的 B2B 采购 Agent 元采。

证据。 论文HTML 表 2 与第 6 节在契约扩展最充分的 Iteration 4（P1–4，400 条查询）上，G-CAST 的累积结果为 0.8078，AutoTrainess 为 0.7911。同一轮里，G-CAST 把新时段奖励从 0.3983 提到 0.5813，把保留奖励从 0.8712 提到 0.8833；AutoTrainess 的保留奖励则从 0.8907 降到 0.8739。部署侧，作者写 G-CAST 把人工奖励审计从每轮约 2 人日 降到 30 分钟，把需求到验收的周转从约 一周 降到 两天；晋级与奖励关口还拒绝了 3 个候选检查点和 2 个未通过验证的奖励版本。

同日公告的 ModHarness-RL论文把 harness 本身写成可学习、随训练一起演化的程序：压缩程序负责历史到上下文，引导程序在行为偏离时给指导。候选程序由近期轨迹提出，经执行验证后再在旧轨迹上重放。作者在 CodeSearch 上做了深挖，并在 ALFWorld 和 BIRD SQL 上、用 1.5B 到 8B 的模型做了实验，称压缩与引导「在多数设置中」优于固定 harness 基线。摘要没有给出单一的领先幅度。

局限。 G-CAST 的分数是作者生产评测里的内部奖励单位，不是公开榜；摘要本身未写这些数字，以上取自论文 HTML。ModHarness-RL 的模型规模在中小范围，改进也不是全部设置都成立。

短评。 评论这两篇把「人参与的迭代」落到可检查的关口上：G-CAST 用保留旧能力的累积评估决定能不能上线，ModHarness-RL 则把平时手写的压缩和引导当成与模型一起进化的程序。可迁移的是这套治理，而不是 0.8078 这个数本身。

是否值得读原文 · 关心生产 RSI 或 harness 迭代的，优先读 G-CAST 的表 2 与部署节，约 20 分钟。

第 03 节

各领域模型能力进展

模型找漏洞、写利用和修漏洞的速度都在变；威胁情报与披露政策在同一天给出了两端的信号。

多智能体进攻框架已出现在真实入侵里；Anthropic 把高危漏洞披露窗口从 90 天缩短到 30 天

Google Threat Intelligence / Mandiant · 2026-11-16 · Anthropic Frontier Red Team · 2026-11-16 · 原文 GTIG 全文约 15–20 分钟；Anthropic 政策说明约 6 分钟

观测。 官方GTIG 与 Mandiant 的季度 AI 威胁追踪认为，对手已从手工提示转向自主多智能体框架、自动化漏洞利用流水线，以及 LLMJacking 这类变现方式，并称对抗性 AI 达到「关键拐点」。报告列举的开源进攻框架包括 ARTEX、CAIRN、CyberStrikeAI 和 PentAGI，用于以更高速度执行多阶段入侵。GTIG 写明：已在真实环境中观察到 CAIRN 和 PentAGI 被部署，并看到对 CyberStrikeAI 和 HexStrike AI 的试验。报告还描述发现了一台暴露的暂存服务器，其上托管名为 exploit_agent 的多智能体漏洞研究与武器化框架，可对接多种前沿和本地模型，并对热门 Web 应用在补丁公告前后的代码做持续差分分析。变现方面，LLMJacking 是从被入侵企业环境窃取模型凭证和云配额，再经地下代理（如 LLM Mixers）转售；官方「在一些案例中，单日欺诈账单超过 10 万美元；最严重的累计资源滥用在处置前达到 100 万美元」。报告还转述 Greynoise 的观测：在一场针对数百个组织的利用活动中，初始立足点「在数分钟内」扩大到域管理员。

政策。 官方Anthropic 把协调漏洞披露（CVD）窗口从 90 天 缩短为：高危和严重问题 30 天，其他问题 45 天。新时限适用于 2027 年 1 月 1 日及之后 向厂商或维护者报告的漏洞；届时仍在进行中的报告沿用原截止日期。相关调整还包括：维护者若对首次报告无回应，争取在 15 天（原 30 天）后升级到外部协调方；补丁发布后再等 30 天（原 45 天）才公开完整技术细节。正在利用中的漏洞仍是 7 天 窗口，不变。新政策不适用于未经人工审阅的 AI 发现，例如 OSS Scanner 的结果。对已超过现行 90 天期限、尚未公开的高危/严重报告，Anthropic 通知维护者再给 30 天，然后从 2027 年 1 月 1 日起按更新后的政策发布到看板。理由写得很直接：模型现在能帮助写修复，「一个模型能发现的漏洞，越来越可能被另一个模型发现」，重新发现率在上升。难以快速修补的关键基础设施或需要改规范 / RFC 的问题，仍可商定修复时间表。

局限。 GTIG 基于遥测和暴露服务器，不是受控评测；部分速度和金额是事件个例。Anthropic 写的是政策，不是新的能力分数。更短的窗口会增加维护者压力，官方也承认了这一点。本条只报告观测与政策，不复述具体利用步骤。

短评。 评论两端说的是同一件事的不同侧面：进攻侧已经在用多智能体框架压缩从发现到利用的时间，披露侧则不再假设「漏洞能保密几个月」。不要把 GTIG 的框架名单、加州诉讼里的「80 起事件」和 Anthropic 的窗口缩短并成同一个故事，它们是不同来源。

是否值得读原文 · 安全与政策相关读者值得读 Anthropic 全文（约 6 分钟）和 GTIG 的趋势节；不必为了简报去复现框架细节。

只在仿真里做强化学习，27B 推理模型就能在真机上按「下一步末端位姿」使用机器人

arXiv · 提交 2026-11-13，星期一新公告 · 原文 摘要与图 1–2 约 15 分钟

问题。 论文计算机使用 Agent 看屏幕、在思维链里推理，再输出下一次点击或按键。作者把同样的循环用到机器人上：模型观察相机画面和机械臂状态，推理后输出下一步末端执行器位姿，再由逆运动学和控制器去执行。关键问题是：这样的「机器人使用 Agent」能不能只在仿真里用强化学习训练，并且不依赖真机演示，就迁移到真机和新指令上。

方法。 论文训练栈是 Post-training Engine for Agentic Robotics（PEAR）和 robot-use RL（RURL）。作者在 LIBERO 和 RoboDojo 的仿真中训练开权推理模型 Qwen3.8-27B。官方表述是像计算机使用那样「不需要 harness」。回合会写入上下文，仿真和真机用同一套步骤。

证据。 论文摘要在仿真里训练后，模型在真机双臂机器人上的成功率为 60%，基础模型为 0。在 LIBERO 上，成功率从 1.6% 升到 74.4%，作者称接近 GPT-6 Astra 和 GPT-6.1 Sol 在最高推理力度下的表现。在 LIBERO-Pro 上，当熟悉场景被赋予新任务时，基于演示微调的视觉-语言-动作模型 π₀.₅ 成功率只有 0.75%，该模型为 57.4%。作者还称，在九项推理、编程和视觉基准上「没有可测到的能力下降」。

局限。 真机「60%」写的是「our trials」，摘要未给出试验次数 N。与 GPT-6 和 π₀.₅ 的对比是作者自报。「without any harness」是作者用语，真机部署仍有运动学和控制器。

短评。 评论这是本期具身结果里最硬的一条：仿真里学会「下一步怎么动」，就能迁到真机和新指令，而且对任务改写比演示微调的 VLA 更稳。它解决的是控制策略，不是空间一致的视频生成；和白膜预演是不同层的问题。

第 05 节

AIGC 视频生成

过去 24 小时没有新的视频生成模型发布。下面这条是 11 月 11 日提交、上一期未写入的基准，直接评测「剧本或照片 → Blender 4D 灰盒 → 视频模型上色」这条预演路径，故作为遗漏补记。

VibePrevisBench：编码 Agent 能否在 Blender 里做出可执行的 4D 灰盒预演；视频模型会把预演里的错误一起保住

Chen, Diao 等（天津大学、可灵、北邮等） · arXiv · 提交 2026-11-11（非星期一新公告，本期补记） · 原文 摘要与项目页方法说明约 20 分钟；全文更长

问题。 论文可控的真实感视频模型可以条件于一段渲染出来的灰盒（graybox / greybox）代理视频，从而固定布局、运动和相机。编码 Agent 已经能在 Blender 里重建 4D 场景并渲染这类代理，但此前缺少同时检查「多镜头、长时间 4D 场景」和「渲染出来的代理视频」的基准。项目页用一句话问：编码 Agent 能否把剧本、几张照片、首帧或实拍，变成导演用得上的可执行 4D 场景？

方法。 论文VibePrevisBench 有 242 道任务，输入分四类：剧本、照片、续拍和参考视频。Agent 写并运行 Blender 代码，渲染预览，检查自己的帧，交付灰盒场景。评分有两路：规则化 Scene Check 在干净沙箱里重跑代码，把导出的 4D 场景与隐藏的真值事实在 九个维度 上逐项比较；VLM Screen Check 则问评判模型，通过规则检查的事实能否在代理视频里被认出来。项目页还设了三道交付门（代码能跑、完整渲染、场景能打开），任一失败则该题为 0。作者分析了 11 个前沿编码 Agent 的结果和轨迹。项目页示范视频的灰盒由 GPT-6 Astra（max effort）制作，真实感画面由 Seedance 2.5 从这些灰盒生成。

证据。 论文三条主要观察：第一，多模态理解，尤其是空间和相机运动，是拉开 Agent 差距的关键；第二，各 Agent 似乎已经掌握基本的镜头和调度，但会在更难的请求上失败；第三，Agent 会检查自己的渲染，却改不对错误。作者因此建议：加强空间与相机的视觉理解，对高难度请求做显式检查，并按条目把渲染结果对回任务书。图注还写明：Seedance 2.5 生成的真实感视频「keep the errors of their proxy videos」，代理视频里的错误会被外观模型一起保住。项目页用三位 VLM 评判和 242 对人偏好做了一致性核对：Gemini 4 与 GPT-6.1 Sol 在 11 个 Agent 上的 Spearman ρ 为 0.96，与人类偏好的相关为 0.92；评委在绝对分数上有差距，但排序几乎一致。

局限。 这不是 11 月 16–17 日的新模型发布，而是 11 月 11 日提交的基准，按遗漏补记。项目页的排行榜在本次静态抓取中没有以表格形式露出各 Agent 的 Scene / Screen 分数，这里不引用未打开的名次数字。VLM 分数依赖评判模型，作者已用另外两个模型和人类偏好做了对照。

短评。 评论这条基准把「先有几何和镜头，再生成外观」写成了可逐项打分的测试，而且直接看到：预演错了，成片也会错。它评的是编码 Agent 建 4D 场景的能力，不是视频模型本身的生成质量。

是否值得读原文 · 做分镜、空间一致视频或灰盒预演管线的值得读摘要和项目页方法，约 20 分钟；要看各 Agent 分数需打开项目页排行榜。

第 06 节

高效使用 AI / Agent

把任务交给更便宜的子 Agent，是现在许多 harness 的默认设计；一篇工作坊论文指出，系统的安全性往往会掉到最弱那个读者的水平上。

只在多智能体时才出现的破裂：编排模型自己读文件几乎从不出错，交给更便宜的子 Agent 后则会跟着错

Wang, Mannby（CMU / USC，Prosaic Intelligence） · arXiv · 提交 2026-11-12，星期一新公告 · 原文 摘要与引言约 12 分钟

问题。 论文对隔离使用的前沿模型已经失效的攻击，在这些模型编排更便宜的子 Agent 时可能重新奏效。作者用一个具体设定说明：Agent 要从磁盘上的文件库回答问题，库里被放入一份带有两处固定破绽的伪造记录。若攻击成功，模型在独自阅读时能给出正确答案，一旦伪造记录经子 Agent 转达，就改口采用攻击者主张的错误答案——作者称之为 harmful revision。

方法。 论文作者在未修改的 Claude Code、Codex 以及一个参考 harness 上，使用这些产品自己的子 Agent 机制做测试。对照包括：编排模型自己检索文件库、把同一事实交给更便宜的默认子 Agent、以及同档子 Agent。他们还在 18 个模型上做了转达通道的模拟。

证据。 论文强编排模型自己搜索文件库时，在超过 1,000 次试验里几乎不提交有害修订；引言补充，一份伪造记录在 180/180 次中被单独阅读的编排模型指出，只有 1 次被采信。但若把同样的事实交给更便宜的子 Agent，同样的模型在同样的事实上分别失败 20/180、44/180、75/180 和 553/900。引言给出的产品数字是：Claude Code 在 stacked 条件下失败 75/180，Codex 在 gloss 条件下失败 44/180。同档子 Agent 则为 0/180、1/180 和 11/540，明显低于更弱子 Agent 的 20/180、44/180 和 553/900。在 18 个模型的模拟里，五个「自己几乎从不安全」的汇总者，在 751/757 次试验中重复了被污染的子 Agent 错误。干净文件库上的委派不会造成伤害。作者的结论：系统安全取决于最弱的那个 Agent，而不是编排者。

局限。 这是工作坊论文，任务是植入伪造记录后的修订，不是对真实生产系统的全面审计。产品名称和未修改 harness 的结果是作者声明。失败比例对应不同条件和不同强弱搭配，不宜合成一个单一「失败率」。

短评。 评论这给「默认把检索交给便宜子 Agent」的用法敲了一记：编排模型更强，并不能自动审住子 Agent 转来的证据。若关键事实决定对错，更稳妥的是让最终做决定的模型自己接触原始证据，而不是只看转述。

是否值得读原文 · 在用 Claude Code / Codex 子 Agent 或自建编排的，值得读摘要和引言，约 12 分钟。
