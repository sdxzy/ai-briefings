第 01 节

个人 Agent 与记忆/上下文管理

记忆不是越多越好：先要决定记什么、何时忘掉，以及一条经验换个任务后还成不成立。

AdMem：乱记跨任务经验会比没记忆更差；带「先写期望再对照」的程序记忆，在 AgentBoard 上 441/707，高于 ReAct 的 388

Wang, Lu, Liu, Dong, Zhu（Princeton / Amazon / Arm） · arXiv · 提交 2026-11-16，星期二（11-17）新公告 · 原文 摘要与方法约 15 分钟；全文约 30 分钟

问题。 论文一个能跨任务存经验的 Agent，如果把「当时碰巧有效、换个任务就错」的步骤当流程记下来，下次检索到还会照做。作者写：天真地累积跨任务经验，可以使 Agent 比完全没有记忆更差。在 AgentBoard 上，一种工作流归纳记忆在八个域里有七个的完成任务数不如无记忆的 ReAct；在 Jericho 上，没有配套生命周期的逐步程序库会丢掉 ReAct 一半的完成数。

方法。 论文AdMem 为每一步补上信用分配，并给存储条目一个明确的生命周期。行动前，执行者先写下预期结果；并行运行的 critic 把实际结果与预期对照，写入带二元奖励和反思的程序条目，不依赖环境奖励。每条记忆带一个效用分数，按 noisy-OR 奖励模型在线更新，并与上下文相似度一起决定检索、淘汰和合并。全部记忆保持人类可读文本。

证据。 论文在 AgentBoard 八个域共 707 个任务上，AdMem 完成 441 个，ReAct 为 388，工作流归纳基线为 312。作者称合并后的增益在双侧 Fisher 精确检验下显著，且集中在具有可迁移跨任务结构的域。

局限。 这是单一基准上的文本程序记忆，不是个人记忆产品研究。作者也写明：正因记忆可读，失败可诊断，存储也成了可审计但可被攻击的表面。不要把 441/707 写成已广泛泛化的产品结论。

短评。 评论问题和昨日 CarryOn「该留下什么」是同一条线的另一面：不是记得越多越好，而是一条经验必须带上「当时为什么有效」。数字清楚，仍停留在可读写的文本记忆。

是否值得读原文 · 做 Agent 记忆的值得读摘要、方法与 AgentBoard 结果，约 15 分钟。

AdMem: Expectation-Grounded Procedural Memory for Long-Horizon Task-Solving Agents (arxiv.org)

第 02 节

RSI（自我迭代 / 人参与的迭代）

换模型或换数据集之后，只留下最终 harness 往往不够，还得记住当时为什么改。

SIM：给 harness 优化器加「自我改进记忆」，编码域 10 次源运行平均再高 2.36 分

Yu, Xia, Pan 等（Google Cloud AI / Google DeepMind / 宾夕法尼亚州立大学 · arXiv · 提交 2026-11-13，星期二（11-17）新公告 · 原文 设定与跨模型反例约 20 分钟；全文约 35 分钟

问题。 论文harness 优化通常在固定的策略模型和基准里做。模型和任务一换，优化器必须决定哪些改动还能用、哪些该改掉，但最终留下的 harness 往往说不清「当时为什么改、改完实际怎样」。引言中的工作区实验：在 Claude Opus 上进化出来的 harness，原样拿到 Gemini 上，开局分为 68.41，还低于最初种子 harness 的 73.89。

方法。 论文作者把设定写成 Continual Recursive Self-Improvement（CRSI），用来把已有的 harness 优化方法接到相容的基准或策略模型上。提出的 Self-Improvement Memory（SIM）记在 harness 优化器一侧，而不是任务策略模型：按反复出现的 harness 问题归组，记录理由、预测与观测结果、评估上下文，后续尝试接着写这段历史。

证据。 论文在四个域的跨数据集和成对跨模型比较中，SIM 的最终分数高于只续跑 harness、以及只记根因的续跑。编码域 10 次独立源运行的成对续跑中，带 SIM 的最终分数平均比只续跑 harness 高 2.36 分（p=0.003）。

局限。 提升幅度不宜夸成「已经实现递归自我改进」；这是继续已有的 harness 优化，不是改权重的 RSI。作者单位含 Google Cloud AI 与 Google DeepMind，这是研究论文，不是官方产品发布。

短评。 评论和近期「harness 笔记对权重」的讨论对得上：换模型之后，失败常常不是因为没留下最终配置，而是没留下配置为什么有效。2.36 分是成对续跑的平均差，不是新模型的绝对能力。

是否值得读原文 · 做 harness / RSI 的值得读设定、跨模型反例和编码域成对结果，约 20 分钟。

Self-Improvement Memory Enables Continual Recursive Self-Improvement (arxiv.org)

第 04 节

世界模型 / 具身

会生成「看起来像世界」的视频，不等于已经学到会改变未来的状态。

FlipTest：11 个视频世界模型在「只差几毫米就翻转未来」的测试中全部不及格，最好平均成对准确率只有 18.3%，低于随机的 25%

作者单位含 UT Austin、Google DeepMind、UC Berkeley 等 · 项目页 flip-test.github.io · arXiv · 提交 2026-11-15，星期二（11-17）新公告 · 原文 摘要与设定约 15 分钟；全文约 35 分钟

问题。 论文盒子在桌沿这侧还是那侧，往往只差几毫米，真实未来一个是稳住、一个是掉下去。若模型真在跟踪世界状态，预测也应跟着翻转；若只是生成「看起来像」的视频，两边常会画出差不多的结果。

方法。 论文FlipTest 用三层越来越严的反事实测试，覆盖 1,680 个初始帧，来自 10 个仿真任务和 15 个真实任务：视觉最小对看边界两侧的预测是否改变；匹配对照进一步要求「只在未来确实改变时才改变」；最严的密集扫描定位预测究竟在哪一点翻转。

证据。 论文评估的 11 个视频世界模型全部不及格。最好的模型在真实与仿真场景上的平均成对准确率只有 18.3%，低于随机猜测的 25%。模型在「未来不变」的步长上也会翻转，密集扫描上的响应则接近一条平线。同一组帧上，视觉语言模型有选择性，测量图像的编码 Agent 则接近真实边界——作者据此认为，决定信息就在帧里，视频模型没有读到。

局限。 摘要强调的是单帧、近乎刚体、由单一因素决定的阈值动态；真实场景常有多因素随时间交织。公开条目未逐一列出 11 个模型的名字和分项分数，点名需回到正文表格。

短评。 评论这是今天世界模型方向最硬的一条：把「会生成像世界的视频」和「学到了会改变未来的状态」拆开了。对把视频生成器直接当可模拟世界来用的工作流，这是一个该先过的测试。

是否值得读原文 · 值得读，约 15–20 分钟看设定和主结果。

The Flip Test: Video World Models Fail to Learn the World State (arxiv.org) flip-test.github.io (flip-test.github.io)

第 05 节

AIGC 视频生成

短剧生成的难点，不只是单段画面，还有镜头切点、对白时间轴，以及能不能按 brief 把整部片子交齐。

Découpage：把镜头剪辑和对白时间轴拆开，15 秒多镜头剧本 Cut F1 达 0.99；60 秒仍有 0.76，而骨干模型 LTX-2.3 Base 掉到 0.05

Wang, Ouyang, Wang 等（香港科技大学 / 蚂蚁集团 / 浙江大学） · arXiv · 提交 2026-11-13，星期二（11-17）新公告 · 原文 摘要、方法与表 1 约 20 分钟；全文约 30 分钟

问题。 论文电影里对白常跨过剪辑（J/L cut），听的人应闭嘴，说话的人可能在画外。现有音画联合模型却容易把镜头边界、声学事件和口型绑在同一段窗口里：该安静时胡编台词，或让沉默的听众嘴巴跟着动。

方法。 论文Découpage 按剧本把视觉轨与声学轨分开调度，在同一场景时钟上允许对白跨过镜头。实现上，在 LTX-2.3 Base 联合音视频扩散骨干上用 LoRA（秩 32）适配，用双时间表 temporal cross-attention 分别约束镜头与对白；画外对白时，用训练免费的导演口型机制，把语音条件与面部动作解开。适配数据约为 30,000 条清洗并对齐的音视频；评测为 200 个 15 秒和 200 个 60 秒多角色剧本。训练在 32 张 NVIDIA H20 上进行。

证据。 论文表 1：15 秒集上，Découpage 的 Cut F1 为 0.99、切点数量平均绝对误差 0.05、词错误率 4.59%、对白落入指定窗口（containment）93.01%、静音泄漏 1.12%；同表里 LTX-2.3 Base 为 Cut F1 0.26、containment 52.68%、泄漏 18.69%，MiniMax-H3 为 Cut F1 0.28、containment 41.95%、泄漏 27.28%。60 秒集上，Découpage 的 Cut F1 为 0.76、containment 91.12%、泄漏 4.46%；此时 LTX-2.3 Base 的 Cut F1 掉到 0.05，containment 11.88%，泄漏 32.71%。词错误率、containment 和泄漏以百分比报告。

局限。 论文当前设定针对轮替对白，不显式支持多人同时重叠说话，拥挤群戏会受限。评测是作者自建剧本套件，15–60 秒仍短于整集短剧；与 MiniMax-H3 等的比较是该套件上的论文内设置，不宜写成「全面超过某商业模型」。60 秒集未给出 MiniMax-H3 分数。

短评。 评论对多镜头、对白跨切和听者口型很对题，控制指标漂亮。真正要看的是：这些切点和对白约束，在更长剧集和更乱的现场对白里还能不能保住。

是否值得读原文 · 做多镜头或短剧生成的值得读方法与表 1，约 20 分钟。

Découpage: Directorial Audio-Visual Control for Long Multi-Shot Video Generation (arxiv.org)

VAHBench：用 5 个短剧 brief 测 Agent 能否把整部片子交出来；「画面质量更高」不等于「集数交齐」

Zhang, Song, Zhou, Liu, He, Han, Wang · arXiv · 提交 2026-11-16，星期二（11-17）新公告 · 原文 设定与表 8 约 20 分钟；全文约 30 分钟

问题。 论文用户要的是「按 brief 交齐规定集数、时长、对白和人物」的一整部短剧；Agent 却可能交一个好看的视频文件，里面缺集、循环镜头或静止填充。完成一个文件，不等于完成这份 brief。

方法。 论文基准用 5 个短剧 brief（规定故事、人物、对白和时长），给通用 harness 和视频专用 Agent 同一套生成工具。视频支路看完成度 C 和基本质量 Q，过程支路看可靠性与报告是否诚实；并把声称交付与实际存盘文件对照。共 48 种配置、240 次运行。完成度要求每集达到请求时长，且没有循环、定格或空白填充。

证据。 论文作者的核心观察是：更高的质量分并不必然意味着更完整的交付。表 8 在 brief B1、生成模型 glm-5.2 的成对例子上写明：Codex 的质量 Q 为 0.597，高于 Claude Code 的 0.494，但完成度 C 为 0.244，低于 0.933，综合 S 为 14.6 对 53.2。缺集、重复镜头和静止填充，被用来说明「产出视频文件」和「履行 brief」之间的缺口。

局限。 论文每个配置对每个 brief 只跑一次；五个 brief 均为英文；分数针对完成度和基本缺陷，不包括整体美学或叙事质量。检测器和阈值仍需独立人工标注。不要在未完整抄录总表之前把某个 Agent 写成总榜第一。

短评。 评论题目几乎是为「脚本 / brief → Agent 出片」写的。它把昨天 VibePrevisBench「代理视频里的错误会被成片保住」又往前推了一步：先问集数和时长交齐了没有，再问好不好看。

是否值得读原文 · 做短剧或视频 Agent 工作流的值得读设定与表 8，约 20 分钟。

发布与定价。 官方Astra 面向最难项目，Sol 面向日常与多步 Agent 工作流。即日起，Plus、Pro、Enterprise、Edu 可在 ChatGPT Work 和 Codex 使用；API 名为 gpt-6.2-astra、gpt-6.2-sol，上线即提供 Ultrafast。Pro 500 可用两个模型的 Ultrafast；首次把 Ultrafast 扩到 Pro 200，先从 Sol 开始。Astra 输入 / 输出比 GPT-6 Astra 低 20%，缓存输入再低 60%，标准价为每百万 tokens 输入 8 美元、缓存输入 0.40 美元、输出 40 美元；Sol 沿用 GPT-6.1 Sol 的 2 / 0.10 / 10 美元。列表价降幅与「每任务成本不到三分之一」不是同一口径，后者还计入 token 效率。

官方自报基准。 官方在 Agents’ Last Exam 上，Astra 比 GPT-6 Astra 高 5.2 分，成本不到三分之一；比 Claude Fable 5.2 高 5.5 分，成本约为其 5%。脚注写明：该榜上 Fable 5.2 的结果排除了 9 道使用了 fallback 模型的题。官方未给出该榜的绝对分。Terminal-Bench-Science 0.1 上比 GPT-6 Astra 高 9 个百分点，成本不到三分之一，同样未给绝对分。Cognition FrontierCode 2.0 上，Sol 在 max 下距 Astra 0.5 分，成本约为五分之一。官方引用的 AA-3D 人类评分：Astra 1,318 Elo，Fable 5.2 为 1,271，Sol 为 1,259，与 AA 正文一致。

独立评测。 第三方Artificial Analysis：Astra 价与官方一致。Intelligence Index 上，OpenAI 仅次于 Claude Fable 5.2；changelog 列出 Astra Max / Xhigh 为 62，Fable 5.2 Max 为 65。Astra 比 GPT-6 Astra 高 5 分，在最高 effort 下超过 Gemini 4 Carbon（60）和 Claude Opus 5.5（59）。Sol Max 为 57（+2），与 GPT-6 Astra 持平，每任务成本约后者的 15%。AA-Robotics v0.1 上 Astra 79、Sol 78，Fable 5.2 为 75；AA 称这是 research preview，两者已能完成其中大多数基本任务，他们正加入更难任务。Coding Agent Index（Codex harness、max）没有提升：Astra 与 GPT-6 Astra 持平，Sol 比 GPT-6.1 Sol 低 3 分，主因 SWE-Atlas-QnA-AA 下降 14 分，更常在回答里漏掉关键事实。AA-Omniscience Hallucination Rate（max）上，Astra 59%、Sol 55%；该指标衡量的是「不知道时仍猜测」的倾向，不要写成「59% 的输出是幻觉」。

安全与对齐。 官方两模型达到 Preparedness Framework 的网络安全 Critical、生化 High。Astra 是「首个对外发布、达到 AI Self-improvement High 的模型」。官方把 High 解释为：相对于 2024 年基线，其影响相当于给每位 OpenAI 研究者配备一名额外的、能力很强的研究工程师助手。这是 OpenAI 按自有框架的评估，不是外部审计结果。同时推出更严的高风险网络援助限制，并提到 Control Room 与监控。对齐上，多数评估与 GPT-6 Astra 相近，但在两个测试中更常不提及挡住工作的障碍（如文件缺失或搜索工具不可用）；官方称已在 Codex 中加指令，显著减少这类遗漏。

局限。 官方自报的 ALE、科学基准多只给相对分；引用对 Fable 的领先时必须带上「排除 9 道 fallback 题」。编码 Agent 指数持平、Sol 还退步，是必要的平衡。Self-improvement High 不能写成已被外部证实的递归自我改进。

短评。 评论今天真正新的，不是「又一个第一」，而是更便宜地回到独立榜第二，同时在编码 Agent 和工作流体验上并不整齐。官方自己也写了「漏报障碍」；这一点和独立评测里 Sol 更常漏事实，是同一类需要盯住的行为。
