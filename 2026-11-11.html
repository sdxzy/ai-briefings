Cursor Projects 变多人：每人保留私有上下文，团队共用一层上下文，agent 之间可以直接对话

Cursor · 2026-11-10 · 原文 博客约 4 分钟；文档「Multiplayer Projects」一节约 5 分钟

问题。 官方agent 的上下文一直按人隔离：新同事加入要从头喂需求、设计和约定；两个人各自的 agent 改同一处代码，往往到合并时才发现冲突。

做法。 官方上下文分两层。每个成员在 Project 里有自己的一对一聊天，配自己的协调者（coordinator）和执行 agent，局部上下文归个人；另有一层共享上下文（需求文档、图、技术规格、设计稿等），全体成员的 agent 都能读写，「一个聊天里做的决定，Project 里所有 agent 都能拿到」。共享任务看板显示谁在做什么、每个任务对应哪个 PR。成员的协调者之间可以直接发消息，例如一人改数据库 schema、另一人的功能要读这张表，两边 agent 先商定先后顺序。

安全边界。 官方文档写明：别人的 agent 发来的消息标注为「agent 输入」，接收方当作不可信输入来权衡，而不是主人的指令；回复在一个分叉出来的侧聊天里进行，侧聊天只能回答，不分享密钥和凭据，不能改看板，也不能向主人提问或申请权限；分享个人文件或连接器数据前要先问主人。

局限。 第三方AlphaSignal 指出 Cursor 没给出依赖检测的准确率或误报率，也没说明哪些聊天决定会进入共享层、过期决定如何清理。评论「共享层只写一次、随工作增长」意味着它也会积累过时结论，这和个人记忆的老化问题是同一个问题，只是放大到了团队。

是否值得读原文 · 值得读文档的「How coordinators message each other」，跨 agent 消息的信任规则写得很具体，可直接借鉴。

主动型 agent：从「你给 agent 派活」到「agent 给你派活」，难点先在发现任务

arXiv · 2026-11-09 · 原文 论文约 20 分钟；幻灯片约 10 分钟

问题。 论文常驻助手要自己从邮件、聊天、文档和业务系统里看出「主人欠着哪些事」，再去对应系统里办完。现有基准几乎都直接把任务交给 agent，测不到「发现」这一步。

方法。 论文AutoBuddy-Bench 把一个组织的员工、项目、业务系统和事件历史建成时间图，渲染成逼真的工作区材料，从「产生义务的事件」推出标准答案任务，并按 agent 对工作区的实际改动判分。参考 agent 先列出任务并指向来源记录，再为每个任务开独立会话、带写权限去执行。

发现。 论文只换底座模型时，任务丢失的位置系统性移动：弱模型主要丢在发现阶段，中等模型能找出任务但常常做到一半就停，最强模型主要失败在执行，尤其是业务系统操作；发现的精确率与执行质量只弱相关，作者认为这是两种不同能力。论文摘要未给出具体分数。

行业观点。 第三方LangChain 的 Sydney Runkle 在 AI Engineer 大会上讲同一主题，论点是 agent 将从「接任务」转向「给人派任务」，这需要记忆和交互界面都上一个台阶。

局限。 模拟组织再逼真也是合成数据；「判断哪些事该主动做、哪些该先问」的边界问题论文没有展开。

是否值得读原文 · 做常驻助手的读论文 §1 和结果部分的失败分布即可。

SoMem：让 agent 用普通链接文档自己整理记忆，每条摘要都挂着原始证据

香港城市大学 / 腾讯 · arXiv · 2026-11-09 · 原文 约 20 分钟

问题。 论文比如会议地点改了：固定 schema 的记忆系统要么新增一条矛盾记录，要么覆盖旧值丢掉历史。作者问：能不能让 agent 自己决定怎么归档和修订。

方法。 论文记忆就是一组相互链接的文档：agent 决定把什么写成摘要、怎么分主题、何时修订已有主题，每条摘要都链接回原始对话作为证据；运行时校验每次更新，并自动从整理好的内容派生时间线、关系图和「最近」三种视图。查询时 agent 自己搜索、顺着链接读，必要时翻原始证据。

证据。 论文在 LoCoMo、BEAM-100K、LongMemEval-S 上分别比最强基线高 2.66、3.10、2.00 个百分点；建好的记忆能换模型复用，加大推理力度还能继续提升。

局限与短评。 提升幅度不大，方法也不复杂；价值在于证明「普通文档 + 链接 + 证据回溯」这种接近人类笔记的结构就够用，和 Anthropic 记忆四层、知识库式记忆是同一方向，不做深挖。

RSI（自我迭代 / 人参与的迭代）

BadEvolve：只投毒「进化用的任务」，就能让 agent 自己把后门写进技能库

宾夕法尼亚州立大学 / 微软 · arXiv · 2026-11-07 · 原文 约 30 分钟（可只读 §3.2 威胁模型与 §5.2）

问题。 论文自进化 agent 有两个角色：执行者做一批「进化任务」，进化者从执行轨迹里提炼出可复用的技能（skills）。以往的技能后门攻击假设能直接改技能文件；但如果技能由可信的进化者在内部生成，攻击者只能往任务池里混几道题。问题是：只靠混题，能不能让 agent 自己把恶意规则写进技能，之后遇到触发词就执行攻击者指定的行为。

方法。 论文把攻击拆成四个阶段诊断失败：诱导（规则有没有被写进技能）、激活（触发时有没有取到）、遵循（执行者有没有照做）、效果（行为是否达成），每轮只针对失败的阶段改投毒任务；再加回滚（新版本更差就退回）和失败记忆（不重复无效改法）。

证据。 论文在 Trace2Skill、SkillGrad、SkillOpt、A-Evolve 四个技能进化框架和 SpreadsheetBench、WikiTQ、OfficeQA 上，以 Kimi-K2.5 为受害模型，平均攻击成功率 79.6%（59.3%–100%），两个基线只有 37.6% 和 27.8%；干净任务准确率平均只降 1.1 个百分点，所以从效果上很难察觉。答案篡改场景下，Claude Sonnet 4.6 作为受害模型时条件攻击成功率 54.1%。

局限。 只测了技能这一种 harness 组件，记忆和提示词留作后续；论文没有给出防御方法。

坦率短评。 这是「自进化 = 新攻击面」最直接的证据：进化者从任务经验里学规则，任务来源不可信，技能就不可信。凡是让 agent 从外部任务或用户输入自动沉淀技能的系统，都该对进化任务的来源做隔离，并对新技能做差异审计。

TRUST：用在线多重假设检验决定「这次自我改进要不要保留」，误收劣化更新从 45.6% 降到 2.8%

arXiv · 2026-11-07 · arXiv · 2026-11-08 · 原文 TRUST 约 30 分钟（理论较多，可只读 §1 与实验）；InfraRSI 读摘要即可

问题。 论文agent 改 harness 后，常见做法是「验证分更高就收下」。但验证集有噪声，一次看起来的提升可能只是运气，连续收下几次就会慢慢劣化；反过来，太保守的统计门槛又会拒掉真正有用的改动。

方法。 论文把每轮「是否接受新版本」看成一次假设检验，用在线多重检验控制「错误进化率」（被接受的更新里造成不可接受性能损失的比例），并让 LLM 读历史上下文来决定这一轮需要多强的证据。作者证明了该比例的上界和最终性能提升的下界。

证据。 论文在 HotpotQA、DROP、APPS 上（DeepSeek-V4-Flash 与 Qwen-3.8-Flash），贪心门控接受的更新中平均 45.59% 实际更差，TRUST 降到 2.78%，最终分数也高于其他统计门控基线。

相关。 论文InfraRSI 把同一思路用到训练基础设施：先锁定可改范围和任务契约（负载、loss、计时不变量）防止钻空子，再联合调启动参数和代码补丁；在四个单机/多机稠密与 MoE 训练负载上最高提速 2.75 倍，平均 MFU 从 17.4% 提到 30.0%。

局限。 TRUST 只在三个较老的基准上验证；「错误进化」的阈值要人设定。

坦率短评。 和前天 Flex-RSI「只有留出集更好才保留」、上周自进化审计「得新丢旧」放在一起看，「接受门」正在成为 harness 自改进里独立的一环。

AlphaProof Code：Gemini 4 Carbon 驱动的 agent 把 Signal 协议的安全性质证明到编译后的机器码，用时四周

Google DeepMind · 2026-11-10 · 原文 博客约 6 分钟；技术报告很长

问题。 官方Signal 协议保护着 Signal、Google Messages 等应用里的数十亿对话。以往的协议形式化验证大多停在设计层面，而真实漏洞常藏在「设计」和「实现」之间。

方法。 官方人和 agent 分工：研究员与多个模型合作，把 Signal 的安全目标翻译成形式化规格，每一条都由人审核；然后 Carbon 驱动的 agent 自主完成证明，生成超过 600 万行 Lean；agent 再审计证明，标出约 1% 需要人复核的部分，其余由 Lean 自动检查。第三方据技术页与报道，验证覆盖 libsignal 中 PQXDH 和 Triple Ratchet 的前向保密、认证、入侵后恢复等性质，直到 AArch64 编译代码。

证据。 官方全程四周，官方称以往需要专家团队数年；为确认系统能分辨对错，团队把两个已修复的真实漏洞放回隔离版代码，系统都给出了「该版本不安全」的机器检查证明。Signal CTO 公开背书。

局限。 第三方保证是符号层面的，不覆盖 Signal 移动应用整体，也不涉及密码字节的计算安全性；规格由人定，证明「代码满足规格」不等于规格本身完备。

坦率短评。 这是继 Fable 5.2 形式化费马大定理之后，又一个「千行级以上 Lean + 人只看 1%」的长程 agent 案例，而且落在真实软件上，比数学更接近工程价值。

是否值得读原文 · 值得读博客，并看技术页上「what is and isn't covered」的边界说明。

世界模型 / 具身

Gemini Robotics 2.5：200 多项任务成功率高 30%–100%，奔驰产线试点 96%，附开源机器人越狱基准

Google DeepMind · 2026-11-10 · 原文 约 10 分钟（视频多）

能力。 官方新一代视觉-语言-动作（VLA）模型，官方称很大程度上得益于 Gemini 4 Argon 加速机器人研究。在 200 多项任务上评测（用夹子端菜、给礼盒系蝴蝶结、移液等），按任务类型成功率比上一代高 30%–100%，完成速度快 20%–30%。同一模型可控制 Apptronik Apollo 2 人形机器人（22 自由度五指手）和 Franka 双臂夹爪平台。

工厂试点。 官方在奔驰匈牙利凯奇凯梅特和德国辛德尔芬根的产线上，Apollo 2 做汽车零件配料（从散料箱按车辆所需顺序分拣到托盘），成功率 96%。分工是 Gemini Robotics ER 负责跟踪流程，2.5 动作模型控制手臂。

安全。 第三方据 Ars Technica，推理时安全推理让有障碍物时安全完成任务的比例提高 33%，有人挡路时提高 43%；新开源的 ASIMOV-Jailbreak 基准含 1,500 条诱导不安全行为的指令，把 Argon 放进回路后安全率 98.8%，只用 Robotics ER 2 时 73.5%。

局限。 只向合作伙伴开放，没有公开 API 或权重；所有数字为 DeepMind 自测，「30%–100%」是区间，不同任务不可直接比较。

PAN 2：LLM 先写「会发生什么」，29B 扩散模型再画出来，权重和训练代码全部开源

MBZUAI IFM · 2026-11-10 · 原文 技术博客约 30 分钟

问题。 官方给一个起始画面和一句动作描述，模拟接下来会发生什么，让 agent 先「想象」候选动作的后果再选择，避免昂贵或不可逆的真实试错。

方法。 官方两层：概念推理层是一个预训练 LLM，输出带时间戳的结构化描述（谁在何时做什么、镜头怎么动）；感知推理层是从零训练的 29B 双流扩散 Transformer，把描述补成接触、形变、运动等细节的视频。训练视频按物理动态而非画面好看来挑选。第三方Diffusers 实现使用 Qwen3.5 文本编码器和 Wan2.2 VAE，默认开启提示词与视频安全检查。

证据。 官方自建的多步计划测试中单步完成率 75.1%、完整计划完成率 34.0%，后者是所测模型中最高；Physics-IQ Verified 公开榜上总第三、开放模型第一；六维物理智能测试里仅次于 MiniMax-H3。第三方有报道称去掉 LLM 层后单步正确率跌到 8.7%。

局限。 官方长时间的世界一致性仍是未解决问题；人工盲评在四个开放模型中排第二。

坦率短评。 「先用文字写清时间线与镜头运动，再交给视频模型」这种分层，和短剧管线里「分镜/镜头表 → 生成」的思路一致，开源训练代码也方便研究这层文本中间表示怎么设计。

视频生成提速与可控：pi-H3 两步出片快过实时，SwitchX 3.0 用平面图 + 多参考图拍「一镜到底」

斯坦福 · 2026-11-10 · Beeble · 2026-11-10 · 原文 pi-H3 约 10 分钟；SwitchX 页面以视频为主，约 5 分钟

pi-H3。 官方基于开源的 MiniMax H3，只用 2 或 4 步采样，最后一步直接输出像素、跳过视频 VAE 解码器（称为 DWD）。单张 B200 上 5 秒 768p 带立体声视频 3.8 秒生成，10 秒视频 9.2 秒，都比播放时长短；在 5–15 秒视频上比 Sol-H3 快 2.4–2.7 倍（2 步）。Hugging Face 演示已上线，权重和推理代码定于 11 月 16 日那一周发布，训练代码在 11 月晚些时候。

SwitchX 3.0。 官方在 MiniMax H3 基础上重做的视频到视频模型：用 alpha 遮罩把演员表演逐帧锁住，只换背景和光照。新版最多接收 4 张参考图，例如一张平面图加每个空间各一张图，就能把绿幕走廊里的一段行走变成穿过多个房间的连续镜头；背景可以动（车流、人群、雪），手持、环绕、奔跑镜头无需标记点即可跟踪；输出 4K、10-bit，帧数与源素材一致。

物理一致性。 第三方Hedra 发布 Model Factory 后训练平台，演示把 H3 重训以提升物理一致性，Physics-IQ 从 30.3 升到 34.9，蒸馏版在 AMD MI355X 上不到 3 秒出 5 秒视频（Hedra 自报）。第三方Artificial Analysis 评测 Google 11 月 5 日发布的 Gemini Omni Flash 1.2：视频编辑榜第 2，文生视频从第 12 升到第 6。

局限。 pi-H3 的 DWD 作者自称仍在实验阶段；SwitchX 和 Hedra 都没有可比较的第三方质量数据。

坦率短评。 评论SwitchX「平面图 + 每个房间一张参考图」本质上是给模型一份空间布局，和用白模或 Blender 布局约束多镜头空间一致性是同一类思路，只是输入更轻。

第 06 节

高效使用 AI / Agent

多 agent 怎么配模型、judge 怎么保鲜：Antigravity /swarm 的角色分工与 Meta AutoRefine

Google Antigravity · 2026-11-10 · Meta · arXiv · 2026-11-06 · 原文 Antigravity 博客约 3 分钟；AutoRefine 约 20 分钟

按角色配模型。 官方/swarm 把一个提示交给一组 agent：协调者在隔离的 git worktree 里启动并行执行者，另设专门跑测试、挑战改动的「对抗式验证者」；所有 agent 在一块只追加的共享留言板上协作，空闲时不消耗 token。Google 建议把 Carbon 放在协调、架构设计、安全审计和对抗验证这类高杠杆角色上，并行改文件和常规实现交给更轻更快的模型。这与前天 Anthropic「Fable 做顾问/编排、小模型干重复活」的建议一致。

judge 会过期。 论文很多 coding agent 用 LLM judge 判断改动好不好，但 agent 一变，judge 的提示词就过时，人工标注又贵又会过期。AutoRefine 改用工作流自带的结果当标签（测试过没过、改动被合并还是被放弃）：一个能看到结果的「老师」解释每个标签并据此改写 judge 提示，解释不了的就弃权。在有执行判据的留出集上，一致性（Scott's π）从 0.36 升到 0.60；在一个已部署 agent 上，按当前工作流重新校准后，与合并/放弃结果的一致性从 0.16 升到 0.51，但在旧工作流的 16 个改动上旧 judge 反而更好。

局限。 AutoRefine 的部署实验只有 17 + 16 个改动，样本很小；/swarm 是预览版，没有公开效果数据。

可直接用的做法。 评论两条可以马上用：多 agent 编排时把最强模型只放在「规划、审计、验证」节点；自建 judge 时用合并/放弃、测试结果这类免费信号定期重新校准，并把「老师解释不了」的样本当作 judge 输入不够的信号。

是否值得读原文 · AutoRefine 的方法图和「弃权即诊断」一段值得看。

Google · 2026-11-10 · 原文 官方博客约 5 分钟；AA 两篇各约 5 分钟

发布要点。 官方两周前先通过 Fairwind 计划给网络安全防御方，现在向付费开发者、企业和 Google AI Ultra 订阅者开放（API、AI Studio、Gemini 应用、搜索 AI 模式、Antigravity）。定位是比 Argon 更「花 token 去深挖和反复验证」的模型；Google 仍建议多数软件工程和知识工作用 Argon。入门价 $2/$10 每百万 token，11 月 30 日后恢复 $4/$20。第三方The Verge 估算入门价约为 GPT-6 Astra 的五分之一、Fable 5.2 的四分之一。

评测。 官方Google 称在 CursorBench 4.0、Perplexity WANDR、Zapier AutomationBench 上第一，且每任务成本比第二名外部模型低一半以上。第三方Cursor 称高档位 CursorBench 60.4% 居首（前天 Fable 5.2 最高档为 60%）。Artificial Analysis 10 月 28 日首测时智能指数 v5 得 59，当时第一，模型页现为 60，已被 Fable 5.2 的 65 超过；AA-Omniscience 54 分领先，幻觉率 11%，仍属最低一档。

MKA 新基准。 第三方DeepMind 与 AA 合作推出的多模态知识工作基准：200 个私有任务、10 个行业，要读建筑图纸、工程原理图、临床影像等复杂视觉文件，产出幻灯片、表格、报告或标注图，每题约 70 条加权专家评分细则。Fable 5.2（max）57%，Carbon（high）54%，Opus 5.5（max）53%；但 Fable 每任务 $31.97，是 Carbon（$6.29）的 5 倍多。同一个做幻灯片的任务，Carbon 76 轮、约 1 小时、约 $8，Fable 224 轮、约 3 小时、约 $68，Fable 的成品得分更高（87% vs 72%）。

局限。 评论MKA 由 Google 出题，虽由 AA 独立运行，选题偏好仍值得留意；入门价只到月底，按标准价比较成本时差距会缩小一半。
